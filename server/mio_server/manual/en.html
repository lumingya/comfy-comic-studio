01 · Start here

This is the 4.x handbook: FastAPI + React, port 8788. The restored classic appearance is not the legacy 3.2 engine. Old instructions for port 8777, python server.py, the offline practice button and the old file library do not apply.

A release needs Python 3.11+. Run the root start.bat or ./start.sh. Source checkouts also need Node.js 20+: run npm ci --prefix web and npm --prefix web run build. Use start.bat --check or ./start.sh --check to diagnose startup. Open http://127.0.0.1:8788.

  1. Connect a serviceStart ComfyUI separately, then configure an instance (usually 127.0.0.1:8188).
  2. Select the actual render profileImport a working API-format workflow and select it in a render profile. Importing a workflow alone does not switch the active pipeline.
  3. Write one panelUse Storyboards, for example {character}, standing by a window, {style}. Write dialogue separately.
  4. Define variablesUse Presets to define character and style. Wait for saving to finish.
  5. Assemble, then generateIn Assembly & Queue, select storyboard, presets and profile. Assembly only creates a snapshot. Start generation explicitly; cloud calls may cost money.
  6. Adopt and exportThe first candidate is adopted only if there is no adopted image. Reruns add candidates: explicitly adopt a replacement before expecting the reader to change.

There is no one-click offline practice generator in this UI. You can read existing images, edit templates and assemble offline; generation needs a real service.

02 · Services & keys

ComfyUI uses Instances. OpenAI Images, NovelAI and chat-image services use Cloud channels. A cloud channel also needs a render profile with cloud shaping enabled and that channel selected.

For cloud-only output, leave no enabled final / subsequent local stages. A hybrid profile still requires ComfyUI for refinement; queue adoption happens after refinement. Local and cloud-mode overrides cannot be mixed in one batch. Use separate batches.

Masked keys preserve the existing secret when saved unchanged. Never place keys in prompts or shared files. Offline adapter tests do not certify every live provider or proxy: test one neutral panel and one candidate first.

03 · Workflows & profiles

Import ComfyUI API format with class_type and inputs, not the visual editor's nodes/links document. Copy built-in workflows before editing. Set real installed checkpoint filenames in the graph; check required custom nodes.

Use [mio:prompt], [mio:seed], JSON Pointer mappings and compile/diagnostic tools. Select that workflow in the profile's draft stage, save the profile, then select the profile when assembling. Chained stages need [mio:init]. A submitted request is a snapshot, not a live view of later workflow edits.

04 · Variables & snapshots

Prompts and dialogue accept {name}. Panel-local $name overrides win over series variables, which win over built-ins. Later selected presets override earlier ones. Values may reference other variables; {{name}} is a literal brace escape. Unknown names remain unchanged.

Assembly copies the storyboard, presets, variables and canvas settings into a new album. Editing workshop templates afterwards does not update existing albums. Current presets are text variables; legacy executable variables and scripts are not automatically migrated.

05 · Jobs & uncertain results

Assembly cards represent albums; the Jobs page represents execution batches. Generation fills panels with no adopted image. Reruns create candidates without silently overwriting your selection. Hybrid jobs adopt after the last local stage.

Pause affects scheduling, not necessarily a request already accepted upstream. Cancellation is not a refund. For uncertain results, check provider records before resolving or explicitly resubmitting: repeated paid calls can create duplicate charges. Inspect job details for actual failures.

06 · Read & export

The classic reader displays adopted images. Templates change presentation, not generation. Use Studio's strip canvas for lettering and bubble editing rather than legacy reader instructions.

OutputMeaning
HTML albumSelf-contained offline reader, not an editable project backup.
Image ZIPImage files, a simple reader and a manifest.
Album PDFOne panel per page; images are encoded, not a byte-perfect original archive. Separate captions are not automatically typeset into unlettered PDFs.
Platform slices / long imageThe adopted, composited strip, with platform sizing and a real slice preview.

Auto starts with lossless metadata cleaning and may compress large inline HTML. Publish encodes WebP up to 2560px on the long side. Archive preserves original bytes only when not compositing lettering; it may retain private workflow metadata. Hiding prompts is a display option, not complete privacy scrubbing.

07 · Sharing editable work

Reader HTML, image ZIP and PDF are reader-facing outputs. .mio.zip is an editable series bundle, not an image ZIP or full server backup. Bundle routes are GET /api/series/{id}/bundle and POST /api/bundles (raw ZIP body). External clients should use the token-protected /api/v2 equivalents, not legacy v1 examples. Recheck profiles, instance settings and keys after import.

08 · Backup & migration

Root launchers default to server/data/runtime/v3, containing mio.sqlite3, jobs.sqlite3 and assets/. --data / MIO_V3_DATA can change this; manual launches resolve relative paths from their working directory.

Finish active jobs and stop the server, then copy the entire actual runtime directory. Separately preserve root data/ if you still need legacy material. Back up the current state before restoring; do not copy just the database and omit assets.

Legacy imports are not continuous two-way sync. Workshop first-use seeding can bring over storyboards and text presets; first startup can bring over finished albums, and manual legacy import is available. Imported workflows still need model, node, mapping and profile checks. Do not delete data or legacy folders just to reset the UI.

09 · Legacy capability boundaries

New data is organized as series, episodes, panels, takes and assets. The legacy file library, converters, market, user scripts and executable variables have not all returned just because the shell looks familiar. Storyboard JSON, preset JSON, image ZIP and project bundles have different purposes.

10 · LAN access

Only if needed, launch with --host 0.0.0.0 and visit the computer's LAN IP on port 8788 from a trusted device. 127.0.0.1 on your phone means the phone itself; ComfyUI addresses are resolved by the backend computer.

Local /api has no login. Host and origin checks are not account protection. Never expose it directly to the public Internet or an untrusted network. Configure MIO_ALLOWED_HOSTS for custom hostnames; automation uses scoped API v2 tokens.

11 · Troubleshooting

  • No visible change: distinguish saving, assembly, generation, candidates and adoption. Check save errors and job details.
  • ComfyUI online but jobs fail: check the selected profile, actual model filenames, installed nodes, mappings and init inputs.
  • Cloud selected but waiting for GPU: check enabled local refinement stages.
  • Unresolved dialogue variables: check the album snapshot, not just the workshop preset.
  • Code updated but behavior unchanged: finish jobs and restart Python; rebuild the source UI and restart Vite if its proxy config changed.
  • Handbook unavailable in development: backend 8788 must be running. The handbook is shipped with the server and needs neither legacy/docs nor external scripts.

12 · Glossary

Storyboard / panel: reusable workshop Episode / Panel. Preset: named text variables. Album: a Series with episodes, takes and assets. Render profile: the pipeline, not a preset or workflow. Job: an execution record. Take: an image candidate; adopted takes appear in readers. Classic / Studio: two interface modes of the same new engine, not the legacy service.
