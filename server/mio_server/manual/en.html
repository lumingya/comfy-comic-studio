01 · Start here

This is the Mio 4.x handbook: FastAPI + React, port 8788.

A release needs Python 3.11+. Run the root start.bat or ./start.sh. Source checkouts also need Node.js 20+: run npm ci --prefix web and npm --prefix web run build. Use start.bat --check or ./start.sh --check to diagnose startup. Open http://127.0.0.1:8788.

  1. Connect a serviceStart ComfyUI separately, then configure an instance (usually 127.0.0.1:8188).
  2. Select the actual render profileImport a working API-format workflow and select it as the profile's base generation workflow in render profiles. Importing a workflow alone does not switch the active pipeline.
  3. Write one panelUse Storyboards, for example {character}, standing by a window, {style}. Write dialogue separately.
  4. Define variablesUse Presets to define character and style. Wait for saving to finish.
  5. Assemble, then generateIn Assembly & queue, select storyboard, presets and profile. Assembly only creates a snapshot. Start generation explicitly; cloud calls may cost money.
  6. Adopt and exportThe first candidate is adopted only if there is no adopted image. Reruns add candidates: adopt a replacement on the board before expecting the reader to change.

You can read existing images, edit templates and assemble offline; generation needs a working ComfyUI or cloud service.

02 · Services & keys

ComfyUI uses Instances. OpenAI Images, NovelAI and chat-image services use Cloud channels. The text model in Settings → Models & connections is only used for script writing.

A render profile has a render route: Local ComfyUI runs the base generation workflow; Cloud render sends requests to the selected channel and needs no local ComfyUI. If you need both, create two profiles and submit separate batches.

Masked keys preserve the existing secret when saved unchanged. Never place keys in prompts or shared files. Offline adapter tests do not certify every live provider or proxy: test one neutral panel and one candidate first.

03 · Workflows & profiles

Import ComfyUI API format with class_type and inputs, not the visual editor's nodes/links document. Copy built-in workflows before editing. Set real installed checkpoint filenames in the graph; check required custom nodes.

Use [mio:prompt], [mio:seed], JSON Pointer mappings and compile/diagnostic tools. Select that workflow as the profile's base generation workflow, save the profile, then select the profile when assembling. A stage that takes the previous stage's image needs [mio:init] and its stage image input set to "Feed previous output". A submitted request is a snapshot, not a live view of later workflow edits.

04 · Variables & snapshots

Prompts and dialogue accept {name}. Panel-local $name overrides win over series variables, which win over built-ins. Later selected presets override earlier ones. Values may reference other variables; {{name}} is a literal brace escape. Unknown names remain unchanged.

Assembly copies the storyboard, presets, variables and canvas settings into a new album. Editing workshop templates afterwards does not update existing albums. Presets hold text variables.

Storyboards edit titles, prompts, dialogue and parameters. After assembly, open the album's panel editor from Assembly & queue to set shots, cast, reference images, control images and per-panel render overrides, and to see history.

05 · Jobs & uncertain results

Assembly cards represent albums; the Jobs page represents execution batches. Generation fills panels with no adopted image. Reruns create candidates without silently overwriting your selection.

Pause affects scheduling, not necessarily a request already accepted upstream. Cancellation is not a refund. For uncertain results, check provider records before resolving or explicitly resubmitting: repeated paid calls can create duplicate charges. Inspect job details for actual failures.

06 · Read, letter & export

Open an album from the gallery. The reader shows adopted images. In its toolbar, the layout picker changes the presentation template (not the images); the strip canvas arranges panels, gutters, bubbles and sound effects; export opens the export drawer.

OutputMeaning
HTML albumSelf-contained offline reader, not an editable project backup.
Image ZIPImage files, a simple reader and a manifest.
Album PDFOne panel per page; images are encoded, not a byte-perfect original archive. Separate captions are not automatically typeset into unlettered PDFs.
Platform slices / long imageThe adopted, composited strip, with platform sizing and a real slice preview.

Auto starts with lossless metadata cleaning and may compress large inline HTML. Publish encodes WebP up to 2560px on the long side. Archive preserves original bytes only when not compositing lettering; it may retain private workflow metadata. Hiding prompts is a display option, not complete privacy scrubbing.

07 · Sharing editable work

Reader HTML, image ZIP and PDF are reader-facing outputs. .mio.zip is an editable series bundle, not an image ZIP or full server backup.

Export a bundle from an album's "⋯" menu → "Share album source…", or select several albums in the gallery and choose Export. Import it in Settings → Data & backup → Import .mio.zip. Scripts use the token-protected API: GET /api/v2/series/{id}/bundle and POST /api/v2/bundles (raw ZIP body). Recheck profiles, instance settings and keys after import.

08 · Data folder & backup

Root launchers default to server/data/runtime/v3, containing mio.sqlite3, jobs.sqlite3 and assets/. --data / MIO_V3_DATA can change this; manual launches resolve relative paths from their working directory.

Finish active jobs and stop the server, then copy the entire data folder. Back up the current state before restoring; do not copy just the database and omit assets.

The root data/ folder holds bundled samples: the first start loads the sample albums, storyboards and presets into the data folder, and later edits to data/ are not synced. Deleted works go to the trash in Settings → Data & backup and can be restored during the retention period. To start fresh, back up and launch with an empty --data folder instead of deleting the database.

09 · Files & formats

Data is organized as series, episodes, panels, takes and assets, stored in the data folder's database and assets/; there are no JSON files to edit by hand. Storyboard JSON, preset JSON, album templates (imported from the reader's layout picker), image ZIP and project bundles each have their own purpose. Reusable workflows and render profiles live in Workflows & APIs.

10 · LAN access

Only if needed, launch with --host 0.0.0.0 and visit the computer's LAN IP on port 8788 from a trusted device. 127.0.0.1 on your phone means the phone itself; ComfyUI addresses are resolved by the backend computer.

Local /api has no login. Host and origin checks are not account protection. Never expose it directly to the public Internet or an untrusted network. Configure MIO_ALLOWED_HOSTS for custom hostnames; automation uses scoped API v2 tokens.

11 · Troubleshooting

  • No visible change: distinguish saving, assembly, generation, candidates and adoption. Check save errors and job details.
  • ComfyUI online but jobs fail: check the selected profile, actual model filenames, installed nodes, mappings and init inputs.
  • Cloud channel set but still waiting for ComfyUI: check that the profile's render route is Cloud render and the right channel is selected.
  • Unresolved dialogue variables: check the album snapshot, not just the workshop preset.
  • Code updated but behavior unchanged: finish jobs and restart Python; rebuild the source UI and restart Vite if its proxy config changed.
  • Handbook unavailable in development: backend 8788 must be running. The handbook ships with the server and works offline.

12 · Glossary

Storyboard / panel: reusable workshop Episode / Panel. Preset: named text variables. Album: a Series with episodes, takes and assets. Render profile: the pipeline, not a preset or workflow. Job: an execution record. Take: an image candidate; adopted takes appear in readers.
