01 · Start here

This is the Mio 4.x handbook: FastAPI + React, port 8788.

A release needs Python 3.11+. Run the root start.bat or ./start.sh. Source checkouts also need Node.js 20+: run npm ci --prefix web and npm --prefix web run build. Use start.bat --check or ./start.sh --check to diagnose startup. Open http://127.0.0.1:8788.

  1. Connect a serviceFor local rendering, start ComfyUI separately and configure an instance (usually 127.0.0.1:8188). For cloud rendering, add a cloud channel.
  2. Select the actual render profileFor local rendering, import an API-format workflow and select it as the base generation workflow in render profiles. For cloud rendering, create a new cloud profile and select the channel; no workflow import is needed. Importing a workflow or adding a channel does not switch the active profile. Start with one panel and one candidate.
  3. Write one panelUse Storyboards, for example {character}, standing by a window, {style}. Write dialogue separately.
  4. Define variablesUse Presets to define character and style. Wait for saving to finish.
  5. Review, assemble, then generateIn Assembly & queue, select storyboard, presets and profile. Review each panel's substituted prompts and dialogue in the final step, then add a standby task. Assembly only creates a snapshot. Start generation explicitly; cloud calls may cost money.
  6. Adopt and exportThe first candidate is adopted only if there is no adopted image. Reruns add candidates: adopt a replacement on the board before expecting the reader to change.

For another work, reuse a storyboard and character presets, check the substituted prompt preview and assemble a new album. Creating, editing and assembling do not automatically call a script-writing model.

You can read existing images, edit templates and assemble offline; generation needs a working ComfyUI or cloud service.

02 · Services & keys

ComfyUI uses Instances. OpenAI Images, NovelAI and chat-image services use Cloud channels. With neither a selected nor a default channel, cloud rendering uses the connection and image model under Settings → Models & connections. A normal text service may not return images.

A render profile has a render route: Local ComfyUI runs the base generation workflow; Cloud render sends requests to the selected channel without automatically running retained local stages. For separate local and cloud batches, create two profiles. Only the explicit API option for cloud plus local refinement schedules a local follow-up, and that profile is shown as a hybrid route.

Assembly shows the selected profile's route and channel. Per-panel overrides take precedence over the album default. The top bar opens render profiles directly. Home and an open setup checklist check the workshop default; the panel editor checks the current panel. A cloud status of configured does not certify connectivity or credit, and opening a page does not make a paid image request. A blank channel selects the default channel first, then falls back to the model connection when both are blank.

Cloud parameter support

Panel dimensions, negative prompts and references are saved with the job. Channel negatives add constraints; channel dimensions are defaults only when no panel dimensions are supplied. Later template or channel generation-setting changes do not rewrite the job. Deleting its channel or changing its type fails explicitly.

OpenAI Images receives the panel size and negative prompt as a text constraint, but no seed. Chat-image services receive dimensions and negatives as prompt constraints, so exact output pixels are not guaranteed; no image seed is sent. NovelAI uses native negatives and a fixed seed, aligns dimensions to 64, and records any conversion to a 32-bit seed. Its vibe references do not guarantee character identity.

Enlarge a candidate and expand Cloud generation parameters to compare requested values, submitted values, actual output dimensions and reference sources. Unsupported seeds are not shown as effective seeds. Automatic selection prioritizes the cast, then fills remaining slots with scene and selected-style references, up to four by default. All manual references retain their order; reference mode off sends no images. Custom chat-image models receive all selected images, with explicit errors when the service rejects their count.

Masked keys preserve the existing secret when saved unchanged. Never place keys in prompts or shared files. Offline adapter tests do not certify every live provider or proxy: test one neutral panel and one candidate first.

03 · Workflows & profiles

Import first shows recognized bindings, ambiguous inputs and required nodes or models. Save explicitly after review. Output mappings select nodes; parameter mappings select stored values. Diagnose the selected branch against its actual graph; custom plugin validation still belongs to ComfyUI.

Import ComfyUI API format with class_type and inputs, not the visual editor's nodes/links document. Copy built-in workflows before editing. Set real installed checkpoint filenames in the graph; check required custom nodes.

Use [mio:prompt], [mio:seed], JSON Pointer mappings and compile/diagnostic tools. Select that workflow as the profile's base generation workflow, save the profile, then select the profile when assembling. A stage that takes the previous stage's image needs [mio:init] and its stage image input set to "Feed previous output". A submitted request is a snapshot, not a live view of later workflow edits.

Explicit hybrid jobs validate and freeze their local refinement graphs, parameters and instance selection before submission. Editing or deleting the profile while the cloud request runs does not replace that frozen follow-up. Pure cloud candidates can be adopted directly; further refinement can be requested explicitly through the professional API.

Custom-node compatibility

Mio submits a ComfyUI API graph. Custom nodes that execute through the backend API can remain in that graph without a dedicated Mio button. Install their packages, models and dependencies on the executing instance. If automatic detection is incomplete, target a field with [mio:prompt=field_name] or a JSON Pointer mapping; one value can feed multiple inputs. Bindings and overrides cannot replace a node link or its node ID / output index. Target the upstream input that stores the actual text or number instead.

Browser-only scripts, virtual frontend nodes and custom submission protocols may need explicit adaptation. Check that the API export contains the required values. ParameterControlPanel supports production jobs after explicitly capturing and saving config.state through the workflow API. Mio records original values before writing, reserves that endpoint, saves results before restoring state, and keeps recovery records after interruptions. Use one canonical address per ComfyUI service and avoid external clients changing its parameters while it runs. Other browser-state plugins still need their own adapters. A custom image output can be tagged [mio:output], but image retrieval still needs standard images in /history; video, audio and custom result formats are not automatically supported.

Import validates the document, compilation applies bindings, and diagnostics check node availability and some model requirements. Only a real run on that instance verifies execution and image results; offline samples do not execute every plugin.

04 · Variables & snapshots

Prompts and dialogue accept {name}. Precedence is panel-local $name, values supplied for this assembly, selected presets (later wins), workshop variables, then built-ins. You can reorder selected presets. Values may reference other variables; {{name}} is a literal brace escape. Unknown prompt variables remain unchanged for workflow wildcards; unresolved ordinary names in reader dialogue are blanked.

Assembly copies the storyboard, presets, variables and canvas settings into a new album. Editing workshop templates afterwards does not update existing albums. Presets hold text variables.

The final assembly step previews each panel's positive and negative prompts and reader dialogue using the server's compiler. Missing values link to their panel and field; temporary values affect only this new album. Empty strings are valid deliberate overrides. Cycles and deep references are flagged for review. Previewing does not contact image services; extensions may still modify prompts during generation. Retrying the same unchanged request in the dialog reuses its assembly result instead of creating a duplicate.

Drag the thin divider between the storyboard list and its editor to reveal long titles. Instances, workflows, profiles and cloud channels have the same control. Focus the divider and use Left / Right to resize, Home / End to reach the limits, or double-click to reset. Each page remembers its width in this browser; narrow windows preserve usable space on both sides. Presets retain their single-column editor.

Storyboards edit titles, prompts, dialogue and parameters. After assembly, open the album's panel editor from Assembly & queue to set shots, cast, reference images, control images and per-panel render overrides, and to see history.

05 · Jobs & uncertain results

Assembly cards represent albums; the Jobs page represents execution batches. Generation fills panels with no adopted image. Reruns create candidates without silently overwriting your selection.

If ComfyUI accepts a job but history or image download is interrupted, its result stays uncertain. With a known prompt ID, reconciliation retrieves it without resubmitting. A lost submission response without an ID still needs manual verification. Cancellation discards results that have not entered the save stage; if saving has already begun, that save finishes before cancellation returns.

Pause affects scheduling, not necessarily a request already accepted upstream. Cancellation is not a refund. For uncertain results, check provider records before resolving or explicitly resubmitting: repeated paid calls can create duplicate charges. Inspect job details for actual failures.

06 · Read, letter & export

Open an album from the gallery. The reader shows adopted images. In its toolbar, the layout picker changes the presentation template (not the images); the strip canvas arranges panels, gutters, bubbles and sound effects; export opens the export drawer.

Strip, gallery and spread views use the same album; there is no need to create separate works. Reader templates and export formats are separate choices. An HTML template does not become a freely arranged print page; see the current PDF behavior below.

Without a saved layout, the reader shows complete original images with captions underneath, without adding crops or bubbles. Saved layouts retain framing and lettering; continuous reading preserves the full canvas, whitespace and text across panels. By default, only matching text already fully embedded in the same panel is omitted from external captions. Remaining captions appear below each image, or after a saved continuous canvas. Panel views and HTML templates cut text at panel boundaries and use their own spacing. Changing framing, adopted takes or series variables refreshes the preview.

Long album menus scroll to their final action. Moving one or more albums to the trash takes effect directly and can be undone or restored from the trash. Permanent deletion still asks for confirmation.

Deleting a panel also removes its canvas box, crop and lettering, and clears bridges pointing to it. Other panels, independent text and existing whitespace stay in place; adjust spacing manually when needed. Candidate artwork and historical snapshots are retained.

Select an image on the strip canvas to adjust zoom and horizontal/vertical framing, or reset to automatic centre crop. Undo/redo retains the last 100 edits (Ctrl / Cmd + Z, Ctrl / Cmd + Shift + Z, or Ctrl + Y); text fields keep their native editing shortcuts. Undo remains available after saving, but history ends when you leave the canvas. Long images and platform slices preserve saved framing and whitespace. Changes to script aspect ratios only move existing boxes after an explicit layout action.

OutputMeaning

HTML albums and portable ZIP/PDF default to composited panel crops. Disabling in-image lettering (lettered:false in the API) uses original adopted images and also skips saved framing. Strip PDF exports through the API instead paginate the full strip.

Auto starts with lossless metadata cleaning and may compress large inline HTML. Publish encodes WebP up to 2560px on the long side. Archive preserves original bytes only when not compositing lettering; it may retain private workflow metadata. Hiding prompts is a display option, not complete privacy scrubbing.

07 · Sharing editable work

Reader HTML, image ZIP and PDF are reader-facing outputs. .mio.zip is an editable series bundle, not an image ZIP or full server backup.

Export a bundle from an album's "⋯" menu → "Share album source…", or select several albums in the gallery and choose Export. Import it in Settings → Data & backup → Import .mio.zip. Scripts use the token-protected API: GET /api/v2/series/{id}/bundle and POST /api/v2/bundles (raw ZIP body). Recheck profiles, instance settings and keys after import.

Automation and optional extensions

External programs use token-protected /api/v2: see the API reference and OpenAPI schema. Read the workshop with GET /api/v2/workshop, inspect substitutions with POST /api/v2/workshop/assemble/preview, then assemble with POST /api/v2/workshop/assemble. Supply idempotency_key to avoid duplicate albums when retrying a request. Assembly only creates a snapshot; submit generation separately. Grant read, write, render and admin scopes according to the operations needed.

Editing, QA, finalization, variants, the script assistant and motion export have backend APIs, without default buttons in the main interface. The repository's examples/extensions/qa-review demonstrates optional QA: installation and activation do not submit work, an explicit command does, and images are never adopted automatically. Disabled or changed extensions reject new calls immediately; reactivation requires a restart to mount new routes. Create the first token locally; subsequent token and extension management is available through the admin-scoped open API. Extension routes also have v2 versions with declared scopes, and enabled extensions can wrap or replace core operations.

08 · Data folder & backup

Named checkpoints preserve work data before editing. Preview changes before restoring; restoration protects the current state automatically and refuses stale previews, missing references and unfinished jobs. Checkpoints do not copy image files or global service configuration, and require the original work to still exist.

Root launchers default to server/data/runtime/v3, containing mio.sqlite3, jobs.sqlite3 and assets/. --data / MIO_V3_DATA can change this; manual launches resolve relative paths from their working directory.

Settings → Data & backup can create workspace archives containing both databases, checkpoints and assets. Finish active or uncertain jobs first. Configured keys and API tokens are excluded by default; an advanced option explicitly includes credentials.

Choose an archive and inspect its counts, then stage and explicitly schedule restoration. Mio first saves a protection backup of the current workspace. Stop and restart the server to install it; closing a browser tab does not stop the server. Further edits after scheduling invalidate the preview, so stage again. You can cancel before restarting.

Restored extensions, ComfyUI instances and webhooks remain disabled, and the queue is paused. Review configuration before enabling them. The sibling .<workspace-name>.mio-recovery/ directory retains the original workspace and protection backups, which include credentials. Archives are limited to 2 GiB, or 4 GiB unpacked; for larger workspaces, stop the service and copy both the entire data folder and recovery directory, including assets.

The root data/ folder holds bundled samples: the first start loads the sample albums, storyboards and presets into the data folder, and later edits to data/ are not synced. Deleted works go to the trash in Settings → Data & backup and can be restored during the retention period. To start fresh, back up and launch with an empty --data folder instead of deleting the database.

09 · Files & formats

Data is organized as series, episodes, panels, takes and assets, stored in the data folder's database and assets/; there are no JSON files to edit by hand. Storyboard JSON, preset JSON, album templates (imported from the reader's layout picker), image ZIP and project bundles each have their own purpose. Reusable workflows and render profiles live in Workflows & APIs.

Creation kits package selected storyboards, presets, character and style details, workflows and referenced assets. Choose Creation kit ZIP in the workshop export picker or the album menu. Import first shows a preview; explicitly bind each profile to services or choose Import now, configure later. Select the kit as the storyboard source in the assembly wizard to reuse it without replacing the workshop.

When creating a task, choose local or cloud image generation and a matching render profile. If none exists, open render profiles from the dialog to add one. Both workshop and kit sources allow a profile for this work without changing the source; explicit panel profiles still take priority.

Choose a kit in the storyboard or preset workshop's source selector to edit it, or open its editor from the assembly wizard. Switching sources saves current edits first and stays put if saving fails. Kit presets can also create a one-panel standby preview album; generation starts only when explicitly requested. Kit edits affect future assembly, while existing albums keep their snapshots.

Select panels to copy or move them between episodes in the same work. Organize actions duplicate or reorder episodes and find, preview and rename variables. Transfers preserve takes, framing and the source canvas's whitespace. Locked content and bubbles crossing the selection boundary require explicit choices. Variable operations preserve escaped double braces and candidate history.

10 · LAN access

Only if needed, launch with --host 0.0.0.0 and visit the computer's LAN IP on port 8788 from a trusted device. 127.0.0.1 on your phone means the phone itself; ComfyUI addresses are resolved by the backend computer.

Local /api has no login. Host and origin checks are not account protection. Never expose it directly to the public Internet or an untrusted network. Configure MIO_ALLOWED_HOSTS for custom hostnames; automation uses scoped API v2 tokens.

11 · Troubleshooting

  • No visible change: distinguish saving, assembly, generation, candidates and adoption. Check save errors and job details.
  • ComfyUI online but jobs fail: check the selected profile, actual model filenames, installed nodes, mappings and init inputs.
  • Cloud channel set but still waiting for ComfyUI: check the assembly profile, panel overrides and any explicit API hybrid setting. Adding a channel does not change an existing local profile; a pure cloud profile does not automatically call local stages.
  • Unresolved dialogue variables: check the album snapshot, not just the workshop preset.
  • Code updated but behavior unchanged: finish jobs and restart Python; rebuild the source UI and restart Vite if its proxy config changed.
  • Handbook unavailable in development: backend 8788 must be running. The handbook ships with the server and works offline.

12 · Glossary

Storyboard / panel: reusable workshop Episode / Panel. Preset: named text variables. Album: a Series with episodes, takes and assets. Render profile: the pipeline, not a preset or workflow. Job: an execution record. Take: an image candidate; adopted takes appear in readers.
