CHAPTER 08 / THE MIO HANDBOOK

Data folder & backup

Named checkpoints preserve work data before editing. Preview changes before restoring; restoration protects the current state automatically and refuses stale previews, missing references and unfinished jobs. Checkpoints do not copy image files or global service configuration, and require the original work to still exist.

Root launchers default to server/data/runtime/v3, containing mio.sqlite3, jobs.sqlite3 and assets/. --data / MIO_V3_DATA can change this; manual launches resolve relative paths from their working directory.

Settings → Data & backup can create workspace archives containing both databases, checkpoints and assets. Finish active or uncertain jobs first. Configured keys and API tokens are excluded by default; an advanced option explicitly includes credentials.

Choose an archive and inspect its counts, then stage and explicitly schedule restoration. Mio first saves a protection backup of the current workspace. Stop and restart the server to install it; closing a browser tab does not stop the server. Further edits after scheduling invalidate the preview, so stage again. You can cancel before restarting.

Restored extensions, ComfyUI instances and webhooks remain disabled, and the queue is paused. Review configuration before enabling them. The sibling .<workspace-name>.mio-recovery/ directory retains the original workspace and protection backups, which include credentials. Archives are limited to 12 GiB, or 16 GiB unpacked; for larger workspaces, stop the service and copy both the entire data folder and recovery directory, including assets.

The root data/ folder holds bundled samples: the first start loads the sample albums, storyboards and presets into the data folder, and later edits to data/ are not synced. Deleted works go to the trash in Settings → Data & backup and can be restored during the retention period. To start fresh, back up and launch with an empty --data folder instead of deleting the database.
