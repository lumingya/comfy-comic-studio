CHAPTER 08 / THE MIO HANDBOOK

数据目录与备份

分镜工坊的「创作存档」可保存命名快照，作品检查点也可通过开放 API 管理。恢复先显示差异，明确恢复时会自动保护当前内容；过时预览、缺失素材、活动或待核对任务会阻止恢复。检查点保存作品数据，不复制图片文件或全局服务配置；已经永久删除的作品不能靠检查点重建。

用根启动器启动时，数据默认在 server/data/runtime/v3，包含 mio.sqlite3、jobs.sqlite3 与 assets/。自定义 --data 或 MIO_V3_DATA 时，以实际路径为准；手动从其他工作目录启动时，相对路径也会改变。

「设置 → 数据与备份」可创建完整工作区备份，包含作品、任务、存档与素材。等待活动及待核对任务处理完毕后导出；默认不包含已配置的密钥和访问令牌，高级选项可明确包含凭据。

  1. 选择备份包，先检查作品、素材和任务数量；检查不会修改当前内容。
  2. 暂存后明确安排恢复，程序会先保存当前工作区的保护备份。
  3. 停止 Mio 服务并重新启动。关闭浏览器不等于停止服务；安排后继续编辑会使版本检查拒绝恢复，需要重新暂存。

重启前可以取消安排。恢复后扩展、ComfyUI 实例和 Webhook 保持停用，队列暂停，请重新核对配置。恢复目录在工作区旁的 .<工作区目录名>.mio-recovery/，保留保护备份和替换前的目录；保护备份包含凭据。包上限 12 GiB、展开后 16 GiB；超限时可停服后完整复制数据目录及恢复目录，不要漏掉素材。

根目录的 data/ 是随包示例：首次启动时把示例画册、分镜与预设载入数据目录，之后对 data/ 的修改不会再同步过来。删除的作品先进入「设置 → 数据与备份」里的回收站，可在保留期内恢复。

不要为了重置界面而删除数据库。需要从头开始时，先备份数据目录，再换一个空的 --data 目录启动。
