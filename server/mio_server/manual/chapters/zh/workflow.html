CHAPTER 03 / THE MIO HANDBOOK

工作流与出图配置

导入后先查看预检，再明确保存。预检列出已识别绑定、歧义和需要的节点 / 模型；详情默认折叠。输出映射选择输出节点，普通参数映射选择真正保存值的输入。诊断时可选择分支，检查实际选中的图；插件自身的校验仍以 ComfyUI 为准。

工作流是 ComfyUI 节点图，可在新建任务时直接选择。多个工作流串联时使用高级出图方案。每幕生成张数与尺寸在任务里设置，最近使用值按工作流记忆；尺寸留空保留工作流原值。

  1. 在 ComfyUI 导出 API 格式 JSON（节点含 class_type 和 inputs），再导入 Mio。带 nodes/links 的可视化编辑器 JSON 不能直接作为 API 工作流。
  2. 内置工作流只作起点：先复制，再修改。把 CheckpointLoaderSimple 等节点里的模型名换成你安装的真实文件名；可在 JSON 编辑器中调整节点图与配置。
  3. 映射选择器可搜索节点编号、标题与输入名。常用参数以外可以添加自定义参数，并绑定多个目标；「编辑 JSON」可切换参数配置与节点图。检查依赖后用「试生成一张」验证实际执行。
  4. 多工作流串联时，在高级方案中「添加后处理工作流」。后一阶段接收上一步图片需要 [mio:init] 输入，并把「阶段图像输入」设为「接上一步输出」。未启用的阶段不会执行。

原始提示词模式保留你写的文本；自动编译模式才会组合设定集、景别、风格等结构化字段。更改工作流不会自动刷新已经提交到任务引擎的请求快照；需要明确重新提交任务。

显式混合任务会在提交前检查并固定本地精修工作流、参数与实例选择；云端运行期间修改或删除配置，不会替换该任务已固定的后续工作流。纯云端生成的候选可直接采用；进一步精修仍可主动通过专业 API 调用。

LoRA 槽位与分级覆盖

工作流详情和预检会列出可控 LoRA 的名称、来源、默认开关、权重范围与当前适配器。工作流自带的 pinned LoRA 默认保留；任务可以按稳定 key 独立关闭、恢复或调整权重，追加的 LoRA 使用同一份清单。关闭只影响本次冻结快照，不会改写导入的原始 JSON。

覆盖顺序是「工作流默认值 → 任务参数 → 分幕 panel.overrides」。分幕覆盖只作用于当前幕，任务重试和工作流试绘会沿用相同的冻结规则。多个工作流阶段分别解析自己的槽位；同名槽位不会跨阶段误写。

自定义节点使用 workflow_slot_adapter 扩展点声明 inspect 与 write 方法，适配器只写入已声明的输入并返回稳定身份。停用适配器后，核心标准槽位仍可用，依赖该适配器的槽位会明确报告不可控原因。

自定义节点与插件的兼容范围

Mio 提交的是 ComfyUI API 节点图。自定义节点只要能在 ComfyUI 后端通过 API 执行，就可保留在图中；不需要等待 Mio 为每个插件增加专用按钮。节点包、模型和依赖仍需在实际执行的 ComfyUI 实例上安装。

  • 自动识别不完整时，可用节点标题 [mio:prompt=字段名] 指定字段，或用 JSON Pointer 映射到节点输入。一个值可写到多个输入；高级 JSON 编辑保留。绑定与参数覆盖不能覆盖节点连线或其中的节点编号 / 输出序号；需要修改值时，映射到上游节点实际保存文本或数值的输入。
  • 依赖 ComfyUI 网页脚本的控件、前端虚拟节点或特殊提交协议，不能仅凭导入成功证明可用。先确认 API 导出中已包含实际执行所需的值，再检查编译预览。ParameterControlPanel 已支持正式任务，须先通过工作流 API 捕获并保存 config.state；Mio 在写入前保存原值，独占该服务，结果落盘后恢复参数，中断后保留恢复记录。同一个 ComfyUI 使用唯一地址登记，执行期间避免其他客户端修改参数；其他前端状态插件仍需单独适配。
  • 自定义图片输出节点可标记 [mio:output]；最终取图仍要求服务在 /history 中返回标准 images。只返回视频、音频或自定义结果结构的节点不等于可直接作为漫画图片输出。
  • 导入成功证明格式可读；编译成功证明绑定能应用；诊断检查节点与部分模型条件。最终是否能生成预期图片，仍需在对应实例试跑。离线样本测试不等于执行了所有插件。
