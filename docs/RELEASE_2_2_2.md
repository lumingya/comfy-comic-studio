# Mio 2.2.2 — 预设编辑隔离与「另存为」

[教程中心](README.md) · [内容文件与安全升级](guide/CONTENT_AND_SHARING.md)

## 修复了什么

在实际交付的 2.2.1 ZIP 上复现了两个问题：

1. 新建空白预设 → 另存一份 → 添加变量 → 切换到七海，上方仍显示空白编辑区。检查原生文件后，七海的角色内容仍是 `nanami`，并没有因为切换而清空；错的是下拉名称与编辑区不对应。
2. 在这个状态继续点击「更新当前预设」，实际写入的却是最初新建的预设，而不是下拉框显示的预设。「另存」没有同步更新保存目标，存在真实的误写风险。

本版不再用本册的 `editingPresetId` 决定保存目标，也不把预设编辑区当作生成计划。

## 现在如何操作

| 操作 | 结果 |
| --- | --- |
| 下拉框选「本册设定（当前生效）」 | 显示并编辑实际用于这本画册的全局设定，不回写预设 |
| 下拉框选某个预设 | 显示该预设自己的独立草稿，切换不会把其他草稿清空 |
| 新建空白预设 | 新建独立文件和空白草稿，不清空本册或原预设 |
| 更新当前预设 | 只保存下拉框与编辑区对应的这一份预设 |
| 另存为 | 将当前显示内容保存成新 ID 的独立副本，并切换到新副本；之后更新只针对新副本 |
| 应用 | 确认后把当前显示的草稿复制到本册；不修改原预设或已经入队的任务 |
| 导出当前设定 | 导出当前显示的本册设定或预设草稿，包含所用参考图；不是悄悄导出另一个编辑对象 |
| 删除预设 | 保持 2.2.1 的一次确认、保留已使用值与图片的行为，同时清理这份预设的草稿 |

原按钮「将当前设定存为预设」已改为 **「另存为」**。

### 草稿与文件保存

每份预设的文本、属性增删及参考图编辑都有独立的草稿。草稿随正常保存暂存在私人工作区的 `settings/workspace.json` 及所属图片目录中，切换、正常保存后刷新或重启仍可继续编辑。页脚保存状态表示工作区保存状态，不等于已点击「更新当前预设」。编辑区会明确显示正在编辑本册还是哪份预设草稿。

更新、新建、另存发生 409/500 或断网时，会明确显示尚未确认，不假装文件已经保存；待保存副本和草稿保留。已经提交但响应丢失时，普通保存/更新重试保持同一份身份，不会悄悄再创建一份预设。真正存在版本冲突时，不强制覆盖磁盘。

如果另一页面或文件编辑器在草稿暂存之后改动了原预设，重新打开后仍保留你的草稿，但阻止它直接覆盖新版本；可用「另存为」保留独立副本。

### 不改变正在使用的内容

应用使用独立副本，之后更新预设不会同步改动已经应用的画册。本版在更新仍被旧计划或单幕引用的预设前，也保留它们当前生效的值与覆盖顺序。原画册、单幕文字、图片和已入队快照不跟随预设编辑变化。

图片上传绑定的是发起上传的预设及属性身份，而不是上传结束时下拉框恰好选中的预设。切换到另一份预设，图片仍属于原草稿；如果原属性被删除后重建，或整份预设被删除，迟到的上传不会绑定到新对象或复活预设。

## 升级与完整交付

这是含 59 个独立内容文件及完整源码的运行包，不是补丁，不需要重新导入现有工作区。日常运行只需 Python 3.10+。

**停止旧服务，将新程序解压到新目录，用 `MIO_DATA_DIR` 指向自己的原 `data/`。不要把随包初始 `data/` 覆盖解压到唯一的个人工作区。** 本版不自动恢复或猜测之前已被误写的内容；没有原始文件时无法可靠重建丢失值。

实际旧包复现、2.2.1 → 2.2.2 原生文件逐字节升级对照、完整回归、异常路径和最终包测试见 [验收记录](acceptance-2.2.2/README.md)。验证使用隔离工作区和 Linux/Chromium；不声称经过付费模型、实体手机或 Windows/macOS 实机验证。
