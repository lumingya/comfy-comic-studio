## 结论及角色边界

本角色的十二份新公开真实静态工作流盲测首版仍为 **VERIFIED PASS（限定于已测静态契约）**。这不是整个产品的无缺陷承诺。纳入本次授权交叉证据后，我支持汇总签名 **REQUEST CHANGES**：编译角色的同一项数字字符串权重缺陷为 **Medium 1 项**；通用性角色的阶段归属缺陷另为 **Medium 1 项**。两项不同根因，不因两个字符串案例或三个采样控制而重复计数；Blocker 0、High 0、Medium 2、Low 0。本补充没有把其他角色的案例伪装成本角色新 cohort 的独立实测。

我的真实 cohort 只有一个原生数值权重的有效 LoRA 条目；其负权重及禁用两次精确整图 delta 均通过。这个 2/2 只覆盖该原生数值条目的两种操作，不能外推到数字字符串、平铺堆栈、Power 形态、多个 LoRA 或其他节点实现。四份 UI 格式文件仍只计导出指引和可执行边界通过，不计执行成功。二十五份历史 UI 原件不可得造成的不完全去重限制保持不变。

我独立只读核对了当前源码，因果链与上述记录一致：

1. `workflow_slot_common.py:108-109` 只将原生整数和浮点数视为数字。`workflow_slot_values.py:51-58,66-72` 的两种堆栈读取因此把有限数字字符串的模型权重回退为 `1`，并遗漏 CLIP 字符串。与之对照，链式读取 `:19-36` 和对象列表读取 `:91-103` 已使用数值解析。
2. `workflow_slot_apply.py:123-127` 对合并选择与 pinned 的字典等值判断会把明确请求的数值 `1` 和错误默认值 `1` 判成无变化，提前跳过 writer。这里没有把实际原字段是否等于该默认值再作核对。
3. `workflow_slot_writers.py:157-182` 的写入前快照重复了同样的原生数字判定；`:67-74,130-143,242-256` 又依赖该快照确定字段变化。只修发现显示或只去掉外层跳过都不足以保证精确写入，两侧应共享一致的有限数值语义，同时保留未改字段的原生表示。
4. `render_models.py:39-66` 的图边界并未强制把这些字符串转成数字；`workflow_slot_shapes.py:74-124` 也不会仅因该表示而将两种结构排除。不能把这个已被正常识别、接受明确编辑的输入事后当作已被拒绝的只读边界。

因此我支持编译角色的 **R4-COMPILE-01，Medium**，两个案例只计一项。它违反稳定键覆写及静默忽略边界，影响可编辑条目的实际编译产出。当前证据没有外部节点执行或源文档损坏，不支持拔高为 High，也没有证明由本次变更新引入。无需用我的原生数值两例通过去抵消这个不同表示边界的失败。

## 互核二：Stage2 的 manual oracle 与当前归因充分，但不是本角色重跑

本节不是第三次独立核全图或新的产品复测。我依主审要求接受已经两位审查者直接核图的事实记录，仅确认其 manual 预期、当前实际来源及源码归因之间没有缺口或自相矛盾。我的新 cohort 中两次种子预期差异属于另一个控制种类：源码 `binding_inference.py:379-380` 明确给所有执行采样点开放 seed，现有专项契约覆盖该 fan-out；这不能作为 steps、cfg、sampler 自动选择后阶段的依据，也不能抵消本项证据。
