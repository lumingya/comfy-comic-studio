## Medium 发现

### VIS-M01 · 修图主按钮 hover 后文字几乎消失

- **定位**：`extensions/panel-retouch/panel.css:22,25`。通用 `button:not(:disabled):hover` 的选择器优先级高于 `button.primary`，将 primary 背景换成 accent 的 9% 透明色，前景仍保留 on-accent 颜色。
- **复现**：显式启用修图包，打开面板，不发起模型请求，将指针移入已启用的“读取候选与配置”主按钮。两尺寸均复现，浅/深/动态均可见；无需进入生成阶段。
- **症状与数值**：14px 正文按钮。浅色实际前景 `rgb(244,247,241)`、合成背景 `[226,231,224]`，**1.16:1**；深色前景 `rgb(21,41,28)`、背景 `[34,40,38]`，**1.03:1**。均明显低于普通文本 4.5:1 检查线。动态截图同样近乎失读，其跨层透明背景不引用不可靠的静态合成比值。
- **证据**：六上下文稳定颜色补测；原始截图名 `extra-panel-panel-retouch-{1440|390}-{light|dark|dynamic}-hover`，人工放大核对。文字不是 disabled 状态。
- **影响/建议**：常用主操作在鼠标 hover 时丢失标签；只需在本包为 enabled primary hover 保留匹配的 accent/on-accent 前后景。无需改基座主题、添加滤镜或脚本。架构官已确认该局部修复不冲突。当前工作树出现专用 hover 规则，但未纳入本固定构建复核，故本轮仍未关闭。

### VIS-M02 · Folio 默认元数据对比度不足

- **定位**：`server/mio_server/album/builtin/export-folio.json:10,19`；默认 accent `#8b6f4c` 被用于 9–11px 的 topline、章节/阅读标签、作者署名和 imprint。
- **复现**：用默认 Folio 导出随包样张，不自定义颜色，在桌面/手机打开；三宿主/偏好上下文均保留同一模板纸面主题。
- **症状与数值**：实际截图像素背景和已知 CSS 前景计算，`FOLIO / 精装对页` 在 `[229,223,213]` 上为 **3.54:1**；章节标签在 `[232,227,217]` 上 **3.67:1**；署名在 `[234,229,220]` 上 **3.74:1**；尾注约 **3.68:1**。均为小号正文，达不到 4.5:1。主要书名/正文与图像本身正常，问题不扩大为整个模板失读。
- **证据**：`album-export-folio-sample-390-{light|dark|dynamic}` 原图及桌面/手机五模板联系表；DOM 字号/色值和 PNG 背景像素交叉核对，三上下文结果一致。对照检查 Monograph 署名约 4.91:1，Nocturne 日期约 7.62:1，未将所有模板一概判错。
- **影响/建议**：作者/章节等阅读定位信息在默认发行样式中偏淡。局部加深默认 accent 或仅将这些小字映射到可读正文色即可，保留纸面层次与现有排版；不能依赖用户手动调色补救默认值。

### VIS-M03 · 动态壁纸让浮层与底层图文重叠

- **定位**：`web/src/app/theme.ts:56–62,79–84` 将 panel 等全局令牌设为半透明（panel 68%）；`web/src/styles/overlays.css:23–36` 的 dialog 使用该表面，`web/src/styles/legacy-fit.css:347–349,663–671` 的原生 dialog/模板也依赖 panel；`web/src/app/themeBackdrop.css:17–43` 只稳定 settings、reader-tools、chip 等，没有覆盖这些 dialog/drawer。
- **复现**：390×844 选择动态壁纸；在有书封的画册页依次打开导出抽屉、模板自定义/预览、HTML 导入结果弹窗，或从长文拆幕打开预览。浅/深无壁纸对照不出现同程度穿透。
- **可见症状**：导出模板卡片直接叠在底层 Monograph 亮纸面与巨标题上；HTML 回导成功弹窗中，底层书封竖线穿过“已恢复文件附带的完整台词和展开后的正向提示词”，底层排序栏与书名透到前景说明区。模板与拆幕浮层也能看到底层卡片/行文字。不是只有装饰边缘半透明，前景正文阅读区出现竞争图文。
- **证据**：人工放大查看 `import-390-dynamic-02/03/04/08`、`main-template-390-dynamic-live-preview`、`main-story-import-390-dynamic-storyimport-preview`，并对照同一路径浅/深截图；`import-390-dynamic-03` 重新单图检查确认。
- **对比度边界**：背景由多层动态图像与宿主内容决定，普通 DOM “从白底向上合成”的数字不能代表真实画面，故不虚报精确最低比值。此项依据实际图文重叠截图和清晰的透明令牌路径成立。
- **影响/建议**：长文、导入结果、导出选项等需要稳定阅读的关键浮层受底层图文干扰。只给动态模式浮层稳定不透明语义表面即可；性能官同意此方案，并要求不新增 `backdrop-filter`/重复模糊，修复后另绑定新构建复核 idle 零帧。

## Low 发现

### VIS-L01 · Contact Sheet 翻页动画短暂扩大横向滚动范围

- **定位**：`server/mio_server/album/runtime.css:201–213` 的 `mio-enter`，以及 `runtime.js:216–223` 给翻页宽卡片添加该动画。`rotateY(-7deg) translateX(5px)` 的投影边界在动画起段超出视口。
- **复现**：1440×900、无减少动态偏好，Contact Sheet 单页模式按 End/Home。原矩阵的 single、12、60、120、合集长标题、仅图片、无配文、XSS 文本、极端比例九场景都在动画起段触发宽度断言；初始布局、图像和目录已通过。
- **证据**：固定快照已导出 HTML 的原生 rAF 补测，九场景两个方向均测 0–750ms。瞬时最大 `scrollWidth=1482`，相对 1440 多 **42px**；所有 450–750ms 样本及最终 End/Home 均回到 1440，没有持续溢出。80ms 动画状态暂停截图与完成态截图已人工对看。没有将暂停帧伪称成正常稳态。
- **影响/建议**：短暂的水平滚动范围/边缘摆动，而非持续裁字或图片比例损坏，定为 Low。可局部约束动画溢出或调整变换边界，不能简单以删除有效动画测试掩盖。原始结果保留 291/300，补测 9/9 只解释失败及补全 End/Home 行为，不重写历史。

## 探针修正、互核与结论边界

- 主应用动态引导两次失败是探针快速重开帮助时，异步工作流 assembly dialog 仍后挂载并拦截点击。补测明确等待该 dialog 可见、Esc 关闭、确认卸载后再开启引导，六上下文均能进入阅读。该现象未作为新的产品 Medium；也不把原两次 timeout 删成通过。交互官独立四步路径正常，与此解释一致。
- 初始自动对比度扫描对 CSS `color(srgb …)` 与透明祖先合成有误差，也可能读取遮挡层文字。后续用 canvas 解码浏览器色值、可见命中检查及真实 PNG 背景复核。报告只采纳上列已核实的 opaque/paper 数据，不以早期自动 low 列表签发全局可访问性结论，不声称已证明每个像素/每种壁纸帧均达标。
- 架构官确认本包 hover 的局部修复边界；其英文入口固定中文/混合元数据 Low 与本官中文矩阵不冲突。本官没有声称执行完整英文视觉矩阵。
- 交互官发现 motion 全屏缺权限、拆幕 Esc 后焦点落 BODY、script 节奏 checkbox 无可访问名称等，本官 42 格正向专业矩阵没有覆盖这些路径，不能反证；这些问题由对应主报告统计，不在此重复立号。架构官的活跃任务 cancel 403、顶层资源隔离缺口也不因正常 iframe/正向完成流通过而消失。
- 交互官已回读 VIS-M02/VIS-M03 的证据说明，确认信息性小字与浮层正文重叠定为 Medium 合理、与其控件/实时预览/焦点结论不冲突；其没有独立量色或放大核验这些像素，独立视觉证据仍归本席。引导正确等待后的 6/6 补测也没有剩余互核冲突。
- 性能官与本官同意动态浮层应提高表面稳定性而不引入新 blur；其模板稳态无横溢出与 VIS-L01 的 0–400ms 瞬时动画溢出没有冲突。五模板独立主题不继承宿主壁纸的边界一致。已只读互核其模板按需解码、全实例内存并非各模板独占排名的证据边界；本官候选比较的同步/采纳功能通过，也不能反证其 C4-M01 长篇高频拖动约 180–205ms 长帧，后者以性能席真实采样为准。
- 本官不评价真实模型图像品质、未授权私人作品、真实声卡输出、所有屏幕阅读器、所有未改动页面或后续修复提交。没有以 Fake 模型结果当作真实模型质量证明。
