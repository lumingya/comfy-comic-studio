## 方法与判定边界

1. 先阅读 AGENTS、README、ROADMAP、完整原始任务及现有 `check_roadmap_power.py`、`roadmap_power_fixture.py`、模板和专业面板夹具。复用数据和入口，不直接采用原探针的通过标签。
2. 原探针对冻结采用 `decoded_frame_delta <= 1`，且未以 0 ms 绘制为硬断言。本审计分别测暂停后立即 1 秒与稳定 5 秒窗口；记录 `getVideoPlaybackQuality().totalVideoFrames` 差值、播放时间、暂停状态、真实可见性与焦点，并列 trace 的 decode / paint / raster / composite / swap 事件。
3. CDP 类别：`devtools.timeline,disabled-by-default-devtools.timeline,cc,viz,gpu,media,disabled-by-default-media`。保留逐事件名称、线程、类别、次数和耗时；不把嵌套或多线程时长之和换算成 GPU 百分比。
4. 壁纸使用本机既有 ffmpeg 生成的中性 H.264，1280×720、30 fps、8 秒循环。真实等待 30 秒阈值；分别以鼠标移动、按键、滚轮恢复，统计事件到首个 `requestVideoFrameCallback` 的真实延迟。关闭档真钟超过 30 秒；60/180 秒检查原生定时器计划、切换撤销与持久化，不冒充实际等候 60/180 秒。
5. `Performance.getMetrics` 给出宿主 renderer JS 堆、DOM、TaskDuration 等。显式 GC 后的 retained JS 堆不是总 RAM。通过本实例的 `SystemInfo.getProcessInfo` 和 psutil 采样进程 CPU、Working Set 与 Private Bytes；RSS 求和可能重复计算共享页，Private Bytes 也不是 VRAM。没有电表、ETW 能源计数或电池实验，因此不报告瓦数和真实能耗百分比。
6. 六扩展比较：未安装/全部关闭 → 逐项按官方 ZIP 安装与摘要信任启用 → 全启但面板未打开 → 各面板打开/关闭 3 轮 → 再次全部关闭。比较同一设置首屏的请求资源、iframe 数、retained JS、DOM、进程内存和 3 秒空载 CPU；记录空转任务和副作用边界。
7. 长篇看板：120 幕 / 1,440 候选记录，12 张 480×640 独立位图复用。该测试验证 DOM 和交互规模，不代表 1,440 张不同纹理。同步比较两层 transform；滚动真实滚动容器，并记录 rAF 帧间隔、p95 和 >50 ms 样本。
8. 拆幕：60、120 幕中性 Markdown，每档每宽 3 次真实填入，观察本地实时预览 24 行；显式导入仅写临时数据，核对新增幕数和候选不丢。
9. 五模板：60/120 张独立中性 480×640 PNG（非三张重复 SVG），两种视口，每格 3 次打开，分别测真实滚动或分页导航，并观察反复离开后的 GC 堆与 DOM。大图、截图和 raw trace 不写仓库，原始 trace 仅留内存并在聚合后释放。
10. 性能结论只来自总控明确放行后无其它审计 Chrome、构建或重测试的窗口。准备期的探针数字不参与最终比较。有限次数不证明长期无泄漏，单机 headless 不等同所有设备的交互和能耗。

## 结构化发现

### C4-M01 · Medium · 长篇候选比较每次拖动出现约180–205ms长帧
