## Spec

本轮发现并修复三项 P2 功能缺陷：

1. **稳定键追加 LoRA 被拒绝或按名称折叠。** `models.py:106` 新增 `LoraRef.key` 后，`pipeline/render.py` 将其传入槽位编译；`comfy/workflow_slots.py` 的 `normalize_loras`、`merge_overrides` 和 `_merged` 仍混用名称与槽位身份。角色追加项与工作流固定项同名时抛出标识不匹配，渲染的容错路径会跳过全部角色 LoRA；两个同名但不同 key 的追加项只留下后者。直接隔离探针已复现。主 agent 对角色来源使用独立稳定身份，并按显式 key 合并追加项；仅切换 enabled 时保留模型和 CLIP 原强度，保持固定槽位的错误身份拒绝规则。
2. **任务级开关遗漏分幕采用的其他配置。** `workshop.py:254` 的 `_freeze_task_slots` 原先只更新 `generation.profile`。真实 `/workshop/tasks` 请求使用默认配置 A、分幕配置 B，二者指向同一工作流；任务明确关闭 ink，B 的编译结果仍为模型强度 0.7。主 agent 现对全部冻结配置的本地阶段分发覆写；分幕更具体的覆写仍优先。
3. **多个套装配置绑定同一渠道时串用参数。** `generation.py:80` 原先仅按 channel id 保存 portable recipe。两个来源配置携带不同模型/quality，套装导入时都绑定到一个目标渠道，后者覆盖前者。主 agent 保留每个冻结配置自身的 recipe，并让请求规划、装配预览与套装导出优先使用该配置的 recipe；当前服务绑定与凭据仍来自目标渠道。
