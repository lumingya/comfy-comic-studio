## 本轮改动的其他实质修复

- 取消、重试失败、明确 discard 与发布日志保持一致，不再永久阻塞备份或单项重试；完整中间素材可按原 stage/prompt 只读补取，不再次提交生成。
- 无归属的受管 staging 可回收；保留已登记、共享和仍有日志所有权的文件。
- CLI 阶段键有界且稳定，旧 receipt 能安全续跑；绑定核对完整业务语义，新增默认字段也有真实模型契约回归。
- 云端截止作用于已建立连接的真实阻塞读取、TLS 和取消；请求退出前停止 watchdog，避免误关其他请求。
- 媒体响应的清理由外层 `finally` 承担，ASGI 2.4 发送失败也能及时释放；没有冒称默认 Uvicorn 2.3 曾复现相同漏洞。

新的独立复验补出了取消后再重试、多阶段早期文件缺失、小数坐标接缝、1px 尾段与默认字段漂移等组合，均补修后再验。首份[存储复审](round-2-verification/storage.md)保留其发现时状态，最终正常业务关闭矩阵见[接续功能复核](round-2-verification/storage-completion.md)，没有用未完成的审查充作通过结论。

旧的 `autostart=False` 上下文若进入 API lifespan，实际上具备启动默认 GitHub 更新检查的能力；缺少签名键也不阻止只读目录检查，不能把旧测试一概称为保证零网络。新回归在构建上下文前即注入受控 transport。关闭等待受既有 HTTPX I/O 超时约束，该超时不是硬总耗时 deadline；本轮不声称提供新的硬总关闭时限。

## 验证边界和执行记录

- 没有真实付费生成、真实用户安装、真实 pip 升级或物理断电。进程中断使用 TEMP 子进程退出；Windows 无目录 fsync 的保证不变。DNS/尚无 socket 的 OS 建连不保证立即抢占取消，已发 Webhook 请求不能撤回。
- 一名审查者误用默认 App 入口，初始化在既有 workspace lease 处终止，未进入数据库或启动服务；另有定向命令未先覆盖 legacy 根，不能将该次称为纯 TEMP。偏差与后续隔离重验见[访问报告](round-3-adjacent/access.md)。默认测试根现已修复，没有回显相关数据内容，也没有主动改动或提交 `data/`。
- 少量遗留 TEMP 探针/夹具的清理命令被自动审批以 `blocked by policy` 拒绝，未改用其他途径绕过。它们不在仓库内；截图清理完成的结论不扩大到这些目录。具体记录见[存储复审](round-2-verification/storage.md)及[导出修复](fixes/export-integrity.md)。
- 本轮是有明确边界的对抗审查与故障注入，不是全仓逐行审查或“项目零缺陷”证明。各主审、修复与复审报告保留覆盖清单、未验证窗口及失败到修补的过程。
- 收尾期间工作区出现并行任务的前端未提交改动及后续独立提交，本轮没有纳入审查范围、覆盖或回滚它们。为避免并行推送相互取消 CI，最后的测试夹具补修在 `0bf22c2` 的隔离 worktree 完成，通过 `codex/adversarial-review-20261121` 固定版本验证，并单独回放至 `main`。最终 CI 验证的是该审查快照，不把结果扩大到并行后续内容。
