# R5-WIN-PATH-01：Windows 路径独立复审

日期：2026-11-21。环境：Windows、Python 3.13.6。本报告只由新的复审者维护；未修改生产代码、测试或共享台账，未提交推送。

最终结论：**补修后建议关闭 R5-WIN-PATH-01**。下列首轮反例保留为失败到补修的证据；
原反例与新增身份组合已在实际 TEMP 文件系统独立复验通过。远端跨平台整合由主控另核对。

## 首轮结论：不能关闭，扩展路径前缀仍可损坏工作区

复审开始时，补修在 `_workspace()` 检查原始路径没有链接后返回 `data.resolve()`；
更新安装根已经 `resolve()`。该修复能消除普通 `..`、真实 8.3 短名和大小写别名的差异，
但不能统一 Windows 的扩展长度路径前缀。

独立用真实签名更新夹具创建以下工作区：

```python
data = Path("\\\\?\\" + str(case.root)) / "web/private-workspace"
```

`data.resolve()` 保留 `\\?\C:\...`，安装根仍是 `C:\...`。
因此 `data.is_relative_to(root / "web")` 返回假，重叠保护没有触发。
实际执行 `Updater.apply_pending()` 后，程序从 4.0.0 升到 4.1.0，工作区内的
`private-marker.txt` 与 `updates/pending.json` 均不存在，证明不是单纯错误文案差异。
所有目标均在新建 TEMP 内，无真实安装和用户数据参与。

最短复现命令（独立探针保存在 TEMP，不随仓库分发）：

```text
python -X utf8 %TEMP%/mio-r5-windows-review.py <仓库绝对路径> PathReview.test_extended_prefix_overlap
Ran 1 test in 0.304s
FAILED (failures=1)
private_marker_exists=false, pending_exists=false, program_version=4.1.0
```

已即时通知主控和修复者。建议为安装根与工作区采用相同的 Windows 路径身份规则，
不能只去掉工作区前缀；需要同时考虑普通盘符的扩展路径、扩展 UNC 和不支持的设备命名空间。
修复前仍须保留原始路径的链接/reparse 检查，不能先解析后隐藏链接。

## 已通过的独立反证

在同一真实签名夹具上，以下目标均在替换前拒绝，且私有标记、pending 原始字节与旧版文件完整：

- `root/data/../web/private-workspace`。
- 通过 `GetShortPathNameW` 取得的真实 8.3 短名，并以 `WEB` 大写目录进入工作区。
- 真实 8.3 短名与 `data/../WEB` 的组合。

另创建真实 Windows junction，分别测试链接本身、链接下不存在路径、链接后含 `..` 的路径。
三者均在规范化前拒绝，junction 目标未产生 `updates`；随后只移除 junction 本身。

首轮探针将原测试类直接导入模块，unittest 因而额外发现了 12 项既有恢复测试。
它们均通过，包括两个曾在 CI 未进入的暂停钩子、跨进程安装租约、逐次 rename/commit 中断恢复、
恢复器自身中断、缺失应用模块恢复、journal 归属拒绝、链接拒绝、损坏包和重叠保护及启动参数转交。
该次总数 15 项、11.963 秒，仅独立扩展前缀探针失败。随后已改为导入测试模块而非测试类，
避免后续再次自动发现；未修改仓库测试。

## 补修后的独立复验

修复者新增 `_path_identity()`：文件 I/O 保留原路径，仅在归属/重叠/租约键比较时，
将已解析的 Windows 扩展盘符与扩展 UNC 折叠为统一 `PureWindowsPath` 身份。
身份比较同时用于安装根和工作区、journal 根归属与重叠检查、安装租约键及 `_plain()` 最终归属。
原始工作区链接检查仍在 `resolve()` 之前；设备命名空间另行拒绝。

独立复审读取上述全部生产差异后，以原 TEMP 探针执行 8 项，11.450 秒，全部通过：

| 独立探针 | 实际结果 |
| --- | --- |
| 普通根 + 扩展前缀工作区 | 原先 0.304 秒红环变绿，私有标记/pending/旧版完整 |
| 扩展前缀根 + 普通工作区 | 首轮另确认同样会损坏；补修后拒绝且数据完整 |
| 扩展前缀根 + 扩展前缀工作区 | 拒绝且数据完整 |
| `..`、真实 8.3、大小写与组合 | 三个子用例均拒绝，私有标记和 pending 字节不变 |
| 真实 junction、其不存在子目录及 `junction/../safe` | 三种形态均拒绝，没有把链接规范化后放行 |
| 两种前缀共用安装租约 | 同线程嵌套不增加 owner 项；另一线程以别名前缀进入时立即 BusyError，未绕锁或死锁 |
| 以另一种前缀恢复 journal | 普通写入/扩展恢复、扩展写入/普通恢复两种真实中断组合均恢复完整 4.0.0，pending 保留 |
| API 读取隔离夹具 | 子进程 TEMP/TMP 强制使用真实 8.3 短路径，两项实际 API 用例通过；故意撤回默认隔离时读取器护栏仍准确报错 |

最后一项的故意回退只在受控测试执行期间修改 `ApiCase.setUp` 的运行时方法，
测试本身仍预先重定向生产 fallback 到 TEMP 哨兵并 mock 读取器，未访问仓库 `data/`。
预期失败被外层独立探针明确断言，未将该负向实验报成生产失败；磁盘源码未修改。
因此根代理对路径等值断言增加双侧 `resolve()` 没有削弱“默认读取器不调用”的保护。
