# 图片变量：按提示词顺序传入图片

[教程中心](../README.md) · [渠道配置](CHANNELS_AND_KEYS.md) · [备份恢复](BACKUP.md)

图片和文字使用同一套变量：**不需要独立的“图像输入”区域、用途选择或图生图开关。** 不会根据变量名称猜测人物、背景或初始图用途；用途由你在提示词里描述。

## 三步使用

1. 在「创作画册 → 角色与画面设定」点击「新增属性」，选择 **图片** 类型。变量名支持中文，例如 `图片`，也支持 `charcter_image1`。
2. 在该属性内上传 PNG、JPEG 或 WebP。显示缩略图后，原文件已写入本地磁盘。预设和单幕变量编辑器也支持同样的图片类型。
3. 在分镜提示词中写 `{变量名}`。展开后的预览会显示 `@image_1` 等编号以及对应图片，顺序就是提交顺序。

例如，`charcter_image1` 和 `图片` 是图片变量，文字变量 `charcter` 为 `王明`：

```text
参考{charcter_image1}的人物，{charcter}坐在椅子上，仰望星空。背景参考{图片}
```

实际展开为：

```text
参考@image_1的人物，王明坐在椅子上，仰望星空。背景参考@image_2
```

同时传入人物图片、背景图片，依次对应两个编号。

## 编号、作用域与错误

- 按第一次出现的顺序编号；同一个图片变量重复出现，复用编号且不重复附图。
- 两个不同的图片变量即使选择同一文件，也分别占据自己的编号。
- 没有引用的图片不提交；没有引用图片变量时，正常走文字生成。不再隐式选用角色正面参考图。
- 正向和负向提示词共用图片编号：先扫描正向，再扫描负向；字幕不是图像输入来源。
- 变量按预设、本册、本幕预设、本幕覆盖合并。图片和文字遵循同样的覆盖规则。
- 已定义、但当前作用域中缺失的变量会报错。文字变量**明确留空**仍会略过；图片变量被引用但未上传、被移除或原文件丢失时会报错，不悄悄省略图片。
- 为兼容提示词权重，未定义的 `{masterpiece}` 等内容仍按原文保留；双层花括号及反斜杠转义不会被当作变量。变量内容不递归展开。

## 落盘与任务快照

上传使用现有的本地素材服务，文件保存在：

```text
data/assets/images/albums/variable-assets/<SHA-256>.png
```

JPEG/WebP 使用对应扩展名。文件按内容寻址，不覆盖旧文件；相同内容可以复用同一份磁盘资产。变量配置只保存带 `kind: "mio-image"` 的本地引用及名称，不保存 Base64 图像正文。

入队同时冻结：

- 展开后的正向、负向提示词；
- 图片引用、变量名和顺序；
- 变量作用域以及原有渠道/工作流快照。

因此，后来替换图片、改变量文字或修改源提示词，都不会改变已入队的任务。旧图片不会被自动删除，因为它可能仍被任务或画册来源快照使用。刷新、重启可继续读取这些引用；不要手动清理仍被引用的素材文件。

## 各渠道如何编码

| 渠道 | 提交形式 |
| --- | --- |
| OpenAI 兼容 Chat | 文本在前，随后为按顺序排列的 `image_url` 内容项 |
| OpenAI 兼容 Images | 有图时使用 `/images/edits` multipart；单张字段 `image`，多张重复字段 `image[]`，文件名 `image_1.*`、`image_2.*` 等 |
| NovelAI | 图片变量写入有序的 `reference_image_multiple`，不把第一张擅自变成 img2img 初始图 |
| ComfyUI | 按顺序上传图片；在原有节点映射中使用「变量」来源，把各图片变量绑定到对应图片加载节点的 `image` 字段 |

**`@image_N` 是 Mio 的提示词约定，不保证模型原生识别这个记号，也不保证跨图身份一致性。** 服务商和具体模型是否接受该输入，由其协议决定；不增加能力选择开关，也不自动换接口或无图重试。

ComfyUI 没有统一多图消息体，必须由工作流决定图片进入哪个节点。每个被引用的图片变量都需要对应的变量映射；缺少映射会明确失败，而不是上传后悄悄不用。多个节点可读取同一变量，文件只上传一次。

### NovelAI 的边界

当前使用公开 SDK 所示的多参考图数组形式，同长度发送 `reference_information_extracted_multiple`（固定 `1.0`）和 `reference_strength_multiple`（固定 `0.6`）。这些是此适配器的参考图协议默认值，**不是新增重绘强度界面**，也不根据图片变量名改变用途。[1](https://aedial.github.io/novelai-api/novelai_api/novelai_api.ImagePreset.html) [2](https://pypi.org/project/novelai/)

V4+ 的 Vibe 流程可能需要预编码的参考数据；本实现**不会自动调用编码接口或追加付费请求**。默认 V4.5 模型并不因此获得“任意原图直接参考”的保证；如服务端拒绝原始图片数组，会返回它的错误。未实现 Precise Reference 专有控制、多角色坐标或蒙版编排。既有精修/外部 API 的显式 `source` 参数仍属单独操作，并非本功能的自动模式。

## 接口报错与安全限额

图像服务的 HTTP 错误保留状态码和响应正文。任务失败后，在「生成队列 → 错误详情（原始响应）」展开查看；不是仅显示通用排查提示。响应中若回显本次请求密钥，会替换成 `[REDACTED]`；默认不重试付费请求，也不会降级成无图生成；可在队列页确认启用有限重试。

常规上传支持单张最多 50 MiB；一次云端提交最多 32 个图像输入、原始图像合计最多 50 MiB。具体模型可能有更小限制。上游错误正文设有 2 MiB 安全读取上限，超过时明确报告超限而非完整保留；工程配置还有既有的整体大小限制。停止等待不能保证服务端取消或退款。

## 备份与外部调用

- **完整 `data/` 备份**包含图片变量文件；其中密钥库仍属于敏感数据。
- **便携目录 ZIP**包含当前变量、任务快照及画册来源快照引用的图片。恢复时将图片重新写入本地不可变素材目录，再绑定引用；需要正在运行的 Mio Python 服务。
- 普通工程 JSON 和单独的预设 JSON 只带本地引用，不是独立图片备份；跨机器迁移请使用上述完整方式。
- `/api/v1/images/generations` 新增 `images` 有序字符串数组，可传本地 `/images/` 引用或 PNG/JPEG/WebP data URL。外部调用者自行解析文字变量和编号，API 不读取当前浏览器变量。

## 验证范围

专项测试覆盖真实浏览器上传和磁盘字节、中文变量、顺序与重复引用、正负提示词、单幕覆盖、替换/刷新后的快照、移除与缺文件错误、无图提交、错误详情，以及移走原素材目录后的便携恢复。

OpenAI、NovelAI 和 ComfyUI 的生成接口均采用协议拦截测试；**未使用真实付费账户出图，也未运行真实 GPU 工作流**。完整回归结果见 [测试日志](../TEST_RESULTS.txt)。
