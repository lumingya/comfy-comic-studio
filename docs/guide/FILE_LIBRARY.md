# 独立文件工作区：保存、复制、分享与恢复

[教程中心](../README.md) · [English](../en/FILE_LIBRARY.md) · [2.2 内容与分享](CONTENT_AND_SHARING.md)

Mio 2.x 的主界面、保存接口、图片路由和任务执行链使用独立文件工作区。不是只换目录名称，也不是在另一个 JSON 中继续存放全部画册。**新版不直接读取旧格式，不自动迁移或覆盖旧数据。**

## 一、怎样开始

### 全新工作区

1. 把完整程序包解压到新文件夹，保留随包 `data/`、`js/`、`vendor/`、`providers/`、Python 模块和 `docs/`。
2. 使用 Python 3.10+；Windows 运行 `start.bat`，macOS/Linux 运行 `bash start.sh`，也可执行 `python server.py`。
3. 打开服务显示的本机地址。发行包已经携带独立内容文件。全新外置工作区初始化随包内容，已有工作区不被示例覆盖。
4. 生成仍需你配置渠道并手动启动。启动服务、扫描文件、导入资源、打开画册都不会发出付费生成请求。

默认工作区为程序旁的 `data/`。可指定不同目录，程序升级不需要搬动工作区：

```powershell
# Windows PowerShell：路径可以包含中文和空格
$env:MIO_DATA_DIR = 'D:\漫画工作区\我的文件库'
python server.py
```

```bash
# macOS / Linux
MIO_DATA_DIR="$HOME/漫画工作区/我的文件库" python server.py
```

在同一工作区上启动第二个执行服务会受到 worker 锁约束；多浏览器页面连接同一个服务即可，不要启动多个写入实例。

### 已有 1.x 数据

先停止旧服务、保存完整备份，按[一次性转换教程](FILE_LIBRARY_CONVERSION.md)输出到**原来不存在的新目录**。再使用新版 `MIO_DATA_DIR` 指向转换结果。

不要把旧 `data/` 直接盖到新版目录，不要为了消除错误删除旧文件，也不要只改 `workspace.json` 的 schema。新服务发现旧格式会停止，而不是把它当作空白工程。

## 二、目录中的每项是什么

```text
data/
├── workspace.json                     工作区标记，不存全部内容
├── distribution.json                  随包内容白名单和哈希
├── catalog/                           独立市场条目、演练与基础内容
├── settings/
│   ├── comfy.json                     ComfyUI 设置
│   ├── llm.json                       剧情模型设置
│   ├── xml.json                       独立分镜文本模型设置
│   ├── workspace.json                 界面、排序、渠道等元数据
│   └── secrets.json                   本机私密凭据库
├── storyboards/中文标题--ID.json        每份分镜一个文件
├── presets/
│   ├── characters/角色名--ID.json      外观、参考图、对白等角色属性
│   └── scenes/场景名--ID.json          独立场景属性
├── collections/企划名--ID.json          企划与分组信息
├── plans/计划名--ID.json                模板、变量和单幕覆盖
├── albums/画册名--ID后缀/
│   ├── album.json                     元数据、分镜、对白、来源与编辑快照
│   └── images/内容哈希.png             本册图片，格式也可为 JPEG/WebP/SVG
├── workflows/                         独立工作流
├── layouts/                           独立展示模板
├── records/                           独立角色行、对话
├── runtime/
│   ├── queue/                         独立队列快照
│   ├── staging/images/                不可变上传及执行素材暂存池
│   ├── execution/jobs.sqlite3         幂等、请求、逐幕结果及删除记录
│   └── materialization/               中断后待完成的画册整理记录
├── .cache/catalog.sqlite3             可丢弃、可重建的目录摘要
├── .transactions/                     原子提交及恢复日志
└── .trash/                            独立文件删除后的恢复材料
```

含图片的非画册资源使用同名侧目录，例如 `七海--ID.json` 搭配 `七海--ID.assets/images/`。文件名方便查找，**JSON 中的 `id` 才是身份**；修改标题不必移动图片。实际文件名经过跨平台安全处理，可能带 ID 后缀。

画册中的已解析提示词、对白、参考输入、原图、编辑结果与可编辑图层会随本册保存。执行结果与图片编辑也会整理到独立画册，不依赖某个浏览器页面一直打开。中断的整理在重启或读取/导出该画册时恢复；SQL 请求记录仍是防止重复提交的依据。

企划是分组文件，计划会引用模板和设定。**只有复制一个企划 JSON，不等于把它引用的所有资源一起打包。** 整个工作区请备份 `data/` 或导出完整图片目录 ZIP；分享单册则优先使用下面的资源包。

## 三、复制与分享

### 在界面分享

- 画册集首页导入画册；单册菜单导出 `.mio.zip`；阅读器导出离线 HTML。
- 分镜模板选择器旁导入、导出；变量在「角色与画面设定」页导入、导出。
- 工作流与展示模板在各自库中管理。设置只保留全局维护与服务。
- HTML/画册 ZIP 的源分镜和变量分别选择是否附带；接收方在同一确认窗口分别同意，默认不选。
- 导入始终创建新 ID、独立图片与新资源，不替换已有内容。变量不自动应用到现有计划；导入不运行模型。
- 有图片请使用完整 ZIP；单个 JSON 不携带旁边的文件。详见 [完整操作与隐私说明](CONTENT_AND_SHARING.md)。

### 直接操作文件

- 复制不含图片的分镜 JSON 到另一个 v2 工作区的 `storyboards/`。
- 含图片资源同时复制同名 `.assets/`。
- 复制画册时复制整个 `albums/<ID>/`，不要只取 `album.json`。
- 回到界面「扫描并重新读取」，或刷新页面；未保存修改请先保存。
- 同一工作区发现重复 ID，会报告冲突，不选择其中一个偷偷覆盖。想保留两份，使用界面导入分享包自动分配新 ID。
- 手工编辑文件前先关闭相关页面或停止服务。JSON 语法、路径、ID 不合法会明确报告，程序不会补默认内容覆盖坏文件。

离线命令示例：

```bash
python tools/file_library.py --data "/我的文件库" scan
python tools/file_library.py --data "/我的文件库" list storyboards
python tools/file_library.py --data "/我的文件库" export albums 画册ID --output "/备份/画册.mio.zip"
python tools/file_library.py --data "/另一文件库" import albums "/备份/画册.mio.zip"
```

## 四、如何防止误覆盖

- 界面只提交已修改资源及明确删除的 ID，不把没打开的画册摘要当正文写回。
- 保存携带文件版本。不同字段可以三方合并；同一字段发生冲突时保留本页草稿，拒绝强制覆盖。确认响应同时返回合并后的内容，避免下一次保存又把旧字段写回。
- 所有参与一次资源保存的 JSON、密钥变更和文件移除具有共同的磁盘提交日志。断电后重放已确认提交；尚未确认提交不替换原文件。
- 文件事务与 SQLite 执行记录承担不同职责；画册删除以持久删除标记为准。迟到结果和旧页面不能恢复已删除画册。
- 删除仍只需要一次确认，不以查供应商记录、放弃追踪或重复生成授权作为删除前置条件。
- 图片按内容保存，保留旧原图和快照；替换当前参考图不修改已经排队的参考输入。

网络断开后，“尚未确认”不代表服务端一定没收到。先保留草稿；普通配置可手动重新保存或重新读取。**模型请求不会因此自动重发**。

## 五、密钥与备份

`settings/secrets.json` 是权限受限的**明文凭据库，不是加密保险箱**。普通 API 配置读取只返回空密钥字段及绑定引用。

- 文本/视觉密钥保存后不回填到浏览器密码框。留空保留原绑定；界面的「忘记密钥」明确移除绑定。
- 地址改变不能带走旧密钥；请为新地址重新填写、选择或忘记原密钥。
- 文本和视觉请求由同源后端按保存的连接解析密钥，不把库里的原始密钥发给浏览器。图像渠道仍使用按渠道与地址绑定的密钥 ID。
- **私密全量备份**：停止服务后复制整个 `data/`，包括 SQLite/WAL、素材和密钥。不要公开分享。
- **可移植工程备份**：界面「导出完整图片目录 ZIP」先读取所有画册正文，再打包图片、来源与图层。便携目录与服务端 v2 `data/` 不是同一格式，请通过界面载入，不直接覆盖目录。
- **本机配置 JSON**：不包含图片文件，不能单独作为跨电脑完整备份。
- **画册 HTML**：用于离线阅读，不是可恢复全部服务端执行状态的工程备份。

导出时仍请自行检查自由文本中的私人信息。程序无法可靠识别随手写在提示词或对白里的全部秘密。

## 六、启动效率与验收边界

目录只保留标题、封面、日期、数量等摘要，打开画册时才读取其正文。启动不解码整个图片库；缓存丢失后会扫描 JSON 重建，首次重建比温启动慢。

Linux 沙箱、Python 3.13、Chromium 的实际 **5000 本 × 12 幕**测试：画册 JSON 共 183,302,780 字节，无图片解码负载。服务就绪约冷启动 **3.34 秒**、温启动 **0.28 秒**；服务启动后页面加载约 **1.24 / 1.26 秒**，启动阶段画册正文请求 **0 次**，首次按需读取正文约 **12 / 10 毫秒**。摘要响应约 2.72 MB。这不是 5000 本真实图片库或低端手机的性能保证。

除新架构回归，还使用实际交付的 1.2.1 ZIP 建立旧工作区、上传图片、转换，再在新版真实界面打开、保存、重载、导出并核对旧源目录哈希。普通/异常生成链使用受控本机接口，包含慢响应、断线、4xx/5xx、迟到结果、重启与删除；不冒充真实付费供应商验证。

桌面/手机视口、明暗主题使用 Chromium 检查；没有原生 Windows/macOS、实体手机、Safari/Firefox 或真实收费供应商的完整验收。详见[发布与验收](../RELEASE_2_0_0.md)。
