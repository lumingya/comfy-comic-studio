# 内容文件、画册分享与安全升级（2.2）

[教程中心](../README.md) · [独立文件库](FILE_LIBRARY.md) · [2.2 发布说明](../RELEASE_2_2_0.md)

## 这次的 `data/` 是什么

完整发行包直接携带可读、可编辑的内容文件，不是启动后才创建一个空目录。内置画册、原图、十二幕分镜、变量、计划、工作流、七种展示模板、市场资源和演练素材均已从程序里的内容工厂拆出。

- `data/albums/…/album.json`：一册一个文件；同目录的 `images/` 保存真实图片。
- `data/storyboards/`：一份分镜一个 JSON。
- `data/presets/characters/`、`data/presets/scenes/`：变量设定。这是工作区内部结构，不另发顶层 `presets/` 包。
- `data/collections/`、`data/plans/`、`data/records/`：画册集、计划、角色与对话。
- `data/layouts/`：每种展示模板一个文件，包含 HTML 和外观选项。已有的 AFTERGLOW 设计保留；「无缝」仍为纯图、零间距，不删除画册原始台词。
- `data/workflows/`、`data/settings/`：工作流及无密钥的初始配置。
- `data/catalog/index.json`：程序使用的内容目录，指向独立的市场条目、演练内容、SVG、模板基础材料和预览尺寸规则。
- `data/distribution.json`：发行内容的明确清单与 SHA-256。打包器只接受这份经审核的清单，不把运行后的全部 `data/` 装进发布包。

程序和样式仍分别在 `js/`、`styles.css` 与 Python 模块中。图片在文件里，不再由启动代码中的 base64 封面或示例工厂补回。

## 新安装

1. 解压**整个** ZIP 到新目录，不要只复制 `server.py` 或 `index.html`。
2. 确认目录内有 `data/`、`js/`、`vendor/`、`providers/`、`docs/` 和启动脚本。
3. Python 3.10+：Windows 运行 `start.bat`；macOS/Linux 执行 `bash start.sh`，或直接 `python server.py`。正常运行不需要 Node.js。
4. 首次启动已有随包画册和内容；生成图像仍需自行配置服务并明确提交。

对全新的外置 `MIO_DATA_DIR`，程序初始化随包内容；已存在的工作区不替换已有画册、分镜、设定和版式；已经初始化但被清空的工作区也不会重新灌入示例。初始化标记和任务数据库属于本机运行文件，不随发行包分发。

## 从 2.x 升级，不覆盖自己编辑过的文件

1. 保存草稿并停止旧服务。为旧工作区做一次私密完整备份。
2. 将新版解压到**另一个程序目录**。不要直接把新版带有 `data/` 的 ZIP 覆盖解压到旧工作区上。
3. 启动新版时让 `MIO_DATA_DIR` 指向原来的 `data/`：

```powershell
$env:MIO_DATA_DIR = 'D:\我的画册\data'
python server.py
```

```bash
MIO_DATA_DIR="$HOME/我的画册/data" python server.py
```

4. 新程序补充所需且尚不存在的内容目录，不覆盖旧实体。已有模板修改、画册标题、默认导出版式和单册展示选择保留。
5. 不再按“内置 ID”自动重写模板、恢复删除的封面、迁移角色名字或补回已删内容。缺少资源时，请手动导入所需文件。

1.x 聚合文件不是 2.x 工作区，仍需使用[显式转换工具](FILE_LIBRARY_CONVERSION.md)输出到新目录；不要改 schema 冒充新版，也不要删除唯一原件。

## 编辑或移除文件

先保存并关闭相关编辑页面，必要时停止服务。修改 JSON 后，刷新页面或使用「扫描并重新读取」。修改标题不会改变实体身份；`id` 必须保持有效且不重复。

- 删除展示模板后，刷新不会把它从源码恢复。
- 删除正在使用的资源会使相关功能缺少依赖；请改选其他资源或显式导入，不会自动用示范内容冒充。
- 已有工作区的日常编辑无需更新发行哈希。`check_distribution.py` 是**重新制作发行包**时的核验工具，不是每次运行的内容重置机制。
- 分享给别人请用导入/导出功能创建新身份；直接复制同 ID 文件到同一工作区会被报告为冲突。

## 在哪里导入、导出

| 资源 | 入口 |
| --- | --- |
| 画册导入 | 画册集首页「导入画册」；支持 Mio HTML、独立 JSON、`.mio.zip` |
| 画册源文件分享 | 单册菜单「导出画册分享包」，保留原图和可编辑画册内容 |
| 离线阅读画册 | 阅读器的展示与导出面板，或画册导出入口；生成独立 HTML |
| 分镜 | 创作页分镜模板选择器旁的导入、导出 |
| 变量 | 本册设定区导出；独立「预设库」导入/导出公共设定；参考图随 ZIP 携带 |
| 工作流 / 展示模板 | 对应的工作流库、模板库 |
| 全局维护 | 设置页保留服务、保存、文件扫描和真正的整库维护，不再集中放单资源选择器 |

含图片的独立资源使用 `.mio.zip`；单个 JSON 不能凭空带走旁边的 `images/` 文件。手动复制原生文件时应连同所属图片目录一起复制。

## 分镜与变量：导出和导入分别同意

HTML 与画册源文件 ZIP 均提供两个独立选项，首次默认不勾选：

- **附带分镜模板**：源提示词、台词与分镜参数。
- **附带变量设定**：变量值、逐幕覆盖与参考图片，可能包含私人素材。

可以都不带、只带分镜、只带变量，或都带。画册本身的图像、台词及你选择显示的提示词也可能敏感，公开前仍需检查。服务配置、密钥和执行授权不作为源素材导出。

接收方选中文件后，程序先只读检查，再在**同一个确认窗口**分别询问是否导入附带分镜和变量。两项默认均关闭：

- 不勾选任何项：只导入画册。
- 勾选分镜：创建新分镜；关联新计划保持禁用，不启动模型。
- 勾选变量：创建新设定预设，不替换或自动应用到现有计划。仅导入变量时也保留参考图及逐幕变量，之后可再次分享。
- 两项均勾选：新计划只引用本次创建的分镜和设定；分镜 ID、变量 ID 和逐幕引用重新分配。

导入画册有自己的新 ID 和图片所有权。取消、错误类型、损坏校验和、不支持的元数据、缺图或非法素材在写入前拒绝。

## 预览为什么可以使用较轻的图片

普通「留白」阅读器仍按需加载；导出预览使用与离线导出相同的模板编译路径。预览可以使用缩略位图，但版式尺寸取自原图，不把缩略图或请求生成尺寸当成最终尺寸。

在**相同可用视口、同一模板及选项**下，横图、竖图的宽度规则及完整比例与导出一致，小图不会被强行放大。真正下载时读取实际原图，保留编辑后的原生分辨率。预览只显示部分样张时，不能把样张数量或面板宽度差异误认为整册页面几何一致性的比较。

## 安全与限制

- HTML 导入按数据解析，不执行 HTML 中的脚本、不访问网页或本地路径。新版识别 `mio.album-html.v1` 元数据；旧 Mio HTML 只读取明确标记的画册帧，并要求图片完整内联。任意网页不属于支持的画册格式。
- SVG 必须通过被动内容校验；ZIP 验证路径、类型、文件数量、大小和哈希。HTML 最大 192 MiB，元数据最大 16 MiB，一次最多 64 本画册，每册最多 512 幕；大文件请分册。
- HTML 是可阅读、可带源素材的分享文件，不是完整任务恢复备份。需要保留原始图层及原图的画册分享优先用原生 ZIP；全工作区备份另行进行。
- 本机密钥库是权限受限的明文，不是加密保险箱。整目录私密备份含凭据，不能当作公开发行包。
- 导入、刷新和升级不会提交付费生成，也不会把未知请求自动重发。删除仍只需一次删除确认。


## 2.2.1：删除预设与复制粘贴

独立「预设库」中的「删除预设」只删除选中的库资源，确认一次。引用它的全册/单幕设定会保留为本地变量；原图、台词及入队快照不变。保存失败会明确提示尚未确认，刷新不会凭空补回已删除的预设。

直接复制**不同文件名且不同内部 ID** 的资源确实是追加。**同路径文件在文件管理器里选择替换，仍会覆盖**；改文件名但保留同 ID 会报告身份冲突。单文件存储并不等于操作系统自动合并同名文件。需要创建独立副本，优先使用界面导入；含图资源要携带所属图片目录。详见 [2.2.1 说明](../RELEASE_2_2_1.md)。


## 2.3：本册编辑与公共预设库分离

主区始终属于右上角「当前画册」，明确区分草稿与具体画册版本。进入独立「预设库」才编辑公共预设的私有草稿；返回主区仍是本册。原来的私有草稿和公共预设文件均保留。

在库中「更新此预设」只保存该公共文件；「应用到当前画册」复制到明确显示的目标，保存后供其未发送分镜读取。之后更新公共库不再联动画册。「另存为」创建独立 ID，不覆盖原预设；从本册另存不切走本册编辑归属。导出跟随各自编辑区，延迟上传始终绑定原对象及属性。

保存失败会显示尚未确认；草稿和待保存身份保留。发现原预设已有外部改动时，不允许陈旧草稿强制覆盖，可另存新副本。详见 [操作与异常说明](../RELEASE_2_2_2.md)。


## 2.2.3：重命名与连续失败上限

画册菜单「重命名」直接预填现有完整名称，多选后可逐本修改。不再只追加前缀；重命名不会删除原标签，标签仍用于画册搜索。

创作画册 → 生成队列 → 失败策略新增「连续失败暂停上限」，默认 5、允许 0–100，0 关闭保护。每次失败尝试计数，包含逐幕首次尝试和重试；成功清零。达到上限后暂停当前任务的重试与后续分镜，其他画册继续。正在执行的请求仍可保存结果，但迟到成功/刷新/重启不会自动解除已触发暂停。修好服务后，确认继续未完成分镜才重置；结果不明仍需计费风险确认，删除仍一次确认。详见 [2.2.3 说明](../RELEASE_2_2_3.md)。
