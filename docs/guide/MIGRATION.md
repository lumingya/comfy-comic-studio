# 从 ComfyComic Studio 升级到 Mio

[教程中心](../README.md)

## 改了什么，没改什么

品牌、README、Logo、发布包和新环境变量改为 Mio。旧 IndexedDB/localStorage 键、`ComfyComic` JavaScript 兼容命名空间、数据字段、旧配置迁移路径保留。新代码另提供 `globalThis.Mio` 别名；这不是稳定的外部插件 API，外部程序应调用 `/api/v1`。

产品版本为 1.0.0；内部工作室数据 schema 版本仍独立维护，不要手工改 schema 版本来匹配产品版本。

## 安全升级流程

1. 停止旧服务，关闭旧页面，避免两个实例同时写同一数据目录。
2. 复制备份整个旧项目，重点是 `data/`、旧 `images/`、根目录遗留数据文件以及自己保存的工程目录。
3. 解压新 Mio 项目到新文件夹，不直接覆盖唯一备份。
4. 将旧 `data/` 和存在的旧 `images/` 复制到新项目根目录。遗留 `comfy_comic_data.json` 按旧名称保留，以便迁移程序发现。
5. 启动新服务，检查画册数量、标题、原图、角色预设、工作流和队列；确认后端保存成功。
6. 新版密钥保存在 `data/secrets/provider-keys.json`；完整物理 data 备份会包含它，仅迁移到可信机器。仅导入普通工程时需重新保存凭证。环境变量需要在新启动环境中重新设置。

## 备份方式

- **完整目录备份**：最可靠，包含配置和原图。服务停止后再复制，避免跨文件不一致。
- **界面目录 ZIP**：适合携带工程，但检查是否包含全部素材与敏感字段。
- **工程 JSON**：可能只引用 `/images/...`，不能自动当成自包含图片包。
- **画册 HTML**：用于阅读/分享，不是可完整恢复编辑状态的工程。

不要将密钥、私有素材或旧配置上传到公开仓库。新 API 没有提供远程配置覆盖，故不能用它当作全量恢复工具。

## 环境变量兼容

`MIO_PORT`、`MIO_HOST`、`MIO_ORIGINS` 优先于 `COMFY_COMIC_PORT`、`COMFY_COMIC_HOST`、`COMFY_COMIC_ORIGINS`。旧变量仍可用。`MIO_API_TOKEN` 是新的公共 API 鉴权，不替代供应商密钥。
