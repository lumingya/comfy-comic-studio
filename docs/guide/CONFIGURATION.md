# 配置如何生效：渠道、分镜与一次请求

[教程中心](../README.md) · [队列操作](../QUEUE_AND_COLLECTION_UPDATE.md) · [任务 API](FOUNDATION.md)

## 改模型后，哪些请求会改变？

在「图像引擎」或队列旁的「配置渠道」修改并等待 **Python 已确认保存**。

- 所有关联该渠道的任务，从**下一次尚未发出的请求**开始使用新的模型、地址、协议、可选参数、高级参数和密钥绑定。
- 在途请求仍使用发送时的配置；已完成图片不重画。
- 切换“当前使用的渠道”只影响新建任务，不把旧任务偷偷改绑到另一渠道。
- 卡片上的 **下次请求** 来自服务端已保存配置，不是浏览器尚未保存的草稿；已发出请求用过什么，查看 **更多操作 → 请求记录**。
- 失败或未知幕不会仅因改模型就自动重发，仍需按原策略或明确确认继续。

例如并发 4 时，前四幕已用模型 A 发出。保存模型 B 后，下一个补位请求使用 B；其他关联同一渠道的任务也使用 B。不是等整本画册结束才切换。

## 配置缺失怎么办？

渠道被移除、模型/地址为空或渠道类型改变时，明确显示配置错误，阻止该任务继续派发，**不会回退到初始模型、旧地址、旧密钥或当前选中的其他渠道**。修复配置后再继续原任务。其余已在途结果仍保存。

新配置整体替换旧渠道配置，不把旧参数偷偷合并回来。关闭 size/quality 或移除高级参数后，下一次请求按新配置构造。选择“无密钥”不会继续使用旧 keyId；选择已保存密钥仍要通过渠道与地址的绑定校验，换地址可能需要重新选择密钥。

## 四层职责

1. **本册分镜**：在原编辑区维护该画册版本的文字与渲染字段；共享模板不自动改写已入队画册。
2. **渠道注册表**：稳定 ID 关联一份当前配置。模型和地址不再作为后续执行的固定快照。
3. **一次请求输入**：发送前，服务从同一个已保存工作区版本读取本册内容和渠道，校验后记录本次输入，再交给适配器。
4. **执行与结果**：每幕独立状态、超时和取消批次；成功结果按真实索引归入原画册。

旧的入队记录仅用于身份、幂等、来源追踪和迁移，不能覆盖新读取的渠道配置。已有浏览器任务保存了 config.id 的，可以直接按原渠道 ID 读取最新设置，不用新建画册。

**ComfyUI 边界**：当前服务地址跟随已保存渠道设置；任务的工作流图、输出节点及变量映射属于该画册版本，不会替换成公共工作流库里另一张图。图内 checkpoint/model 节点不是云渠道的 model 字段。核对已提交 ComfyUI 结果必须使用原请求记录，不能用新地址/新图猜测旧 prompt_id。

## 外部 API

先从渠道列表取得实际 ID，再提交：

```json
{
  "idempotencyKey": "my-book-001",
  "input": {
    "frames": [{
      "channelId": "填写本机已保存渠道ID",
      "config": {"provider": "openai"},
      "prompt": "A pelican riding a bicycle beside the sea",
      "images": []
    }]
  }
}
```

`channelId` 表示动态读取该渠道。没有渠道引用的显式外部任务仍按客户端提供的 config 执行，不猜测关联。原幂等提交返回原任务，不再次出图。

任务响应的 `currentChannels` 是下一次请求的安全配置预览；`requestHistory` 是最近 100 次准备发送的实际输入记录。预览不包含地址、密钥或任意敏感扩展。记录代表准备过输入，不证明供应商已接受或计费。

## 页面操作

- 顶部紧凑工具栏：在途数量、每任务并发、超时、保存与恢复暂存。
- 失败策略默认折叠；调度数字与解释在“调度详情”。
- 任务卡片保留名称、进度、状态、下次模型和主要操作。
- 原始错误、逐幕状态、初始输入在“任务详情”；输入历史及次要控制在“更多操作”。
- 状态刷新保留已展开详情，不打断查看。未完成任务仍可按顺序执行，手动启动另一任务则新增独立池。

本地 HTTP 回归已验证：运行中通过模型输入框及地址字段保存更改，后续两个关联任务请求使用新模型和新路径，旧请求不变。测试使用受控服务，不是付费云端验证。
