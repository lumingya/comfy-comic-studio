# 渠道、模型列表与本地密钥

[教程中心](../README.md) · [English](../en/GUIDE.md#channel-and-key-management)

## 管理渠道

「图像引擎」提供新增、复制、删除。新增时选 OpenAI 兼容或 NovelAI，可以创建多个同类型渠道。ComfyUI 是保留的内置工作流入口，不需要删除。

复制渠道只复制非敏感参数，**不复制密钥选择**，避免把原渠道凭证用于另一个服务。

删除需要确认，并检查是否还有 pending/running/paused 任务引用该渠道；有引用时先处理队列。删除会移除该渠道所有本地密钥（包括它以前的地址所保存的条目），不会删除画册或图片。历史画册快照引用的密钥如果被删除，之后精修会明确报错，需要重新配置。

## 可选尺寸与质量

OpenAI Images 的「输出尺寸」「质量」分别有开关。

- **关闭**：请求中完全没有 `size` / `quality` 字段，包括图生图的 multipart 请求。
- **打开且非空**：使用填写的值。
- **打开但留空**：仍不发送，不会补回默认值。
- **Chat 协议**：这两项禁用且不发送，以免强加不兼容的 Images 参数。

新渠道默认关闭这两项；旧渠道会根据已有非空值保留原来的发送行为，可以手动关闭。关闭只停发，不抹掉输入草稿，下次打开可继续使用。

## 获取模型列表

在 OpenAI 兼容渠道中填写基础 URL，选好鉴权方式，然后点击「获取模型列表」。Mio 通过后端请求 `基础URL/models`，如 `https://example.com/v1/models`，使用与生成相同的鉴权选择。

支持标准 `data: [{id: "..."}]`，以及 `models` 数组中的字符串/id 对象。结果去重后进入下拉选择；**不会自动覆盖手填模型，也不保证列表中的模型都能生图**。

渠道没有接口、返回 401/404、超时或格式不支持时，会明确显示错误，原模型 ID 保留，可继续手动填写。列表只在当前页面缓存，换渠道、基础 URL 或凭证选择不会误用另一渠道的结果。

NovelAI 没有在这里假设提供 OpenAI `/models`，保持手填真实模型 ID。

## 三种鉴权方式

### 1. 无密钥

适用于不要求 API Key 的本地服务或兼容渠道。选择后完全不发送 Authorization，**即使服务端存在环境变量，也不会偷偷使用它**。

### 2. 已保存密钥

1. 点击「管理密钥」。
2. 可填写名称，例如“主账号”“备用账号”，粘贴 API Key。
3. 点击「保存并使用」。密钥写入本机，输入框清空；列表只显示名称、保存时间与当前使用状态。
4. 可重复添加多条，并点击“使用”切换。不轮询、不随机切换，不自动重试扣费。
5. 点击条目“删除”并确认，可移除单条密钥。删除当前使用项会将当前渠道设为“无密钥”，不会自动选中另一条。

刷新页面、重启服务后仍然保留，不需要重复填写。没有明文查看或重新下载密钥的接口。输入框不再使用 `autocomplete="new-password"`，不主动触发浏览器生成注册密码；浏览器或扩展仍可能有自己的填充策略。

留空不创建一条“空密钥记录”；需要为空时直接选择“无密钥”。未保存即关闭管理框，输入内容会被清空。

### 3. 服务端环境变量

显式选择后才使用 `OPENAI_API_KEY` 或 `NOVELAI_API_KEY`。新渠道默认是无密钥，避免将通用环境密钥误发给新添加的第三方地址。旧版已经冻结、没有 keyMode 的任务保留原环境变量语义，以便兼容。

## 地址绑定和任务快照

本地密钥绑定 **渠道 ID + 服务类型 + 规范化基础 URL**。改变 URL 不会把原密钥发往新地址：请求会提示密钥缺失或地址不匹配。请针对新地址保存新条目，或明确选择其他鉴权方式。等价的尾部斜杠、域名大小写、默认端口会归一化。

队列冻结 `keyMode` 和 `keyId`，而不是密钥原文；后来换用另一条密钥不会影响旧任务。删除旧任务引用的密钥后，任务失败而非静默改用其他凭证。

## 保存位置和安全边界

保存文件：`data/secrets/provider-keys.json`。同目录临时文件原子替换，POSIX 系统文件权限 0600、目录新建权限 0700。Windows 仍应保护当前用户目录与 ACL。

**这是本地权限隔离文件，不是加密保险库**。有本机账号或磁盘读取权限的人仍可能读取它。未提供操作系统钥匙串集成；不要直接将工作台暴露到公网。

普通工程 JSON、界面生成的工程 ZIP、原生配置同步、画册导出不包含密钥文件；只包含用于本机查找的引用。复制整个物理 `data/` 时会包含它，因此完整备份应作为敏感资料保存。移机只复制普通工程而不复制密钥文件时，需要重新保存密钥；不能把复制引用误认为已迁移凭证。

若选择迁移密钥文件，应在服务停止时，将它和对应的渠道配置一起迁移到可信机器，保持渠道 ID 和基础 URL。分享作品或提交仓库时不要带上 `data/secrets/`。
