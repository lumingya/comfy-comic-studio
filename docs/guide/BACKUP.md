# 备份与恢复

Mio 的配置、画册和原始图片保存在本地。备份前先确认保存完成。

## 完整目录备份

1. 停止 Mio 服务，关闭浏览器页面。
2. 复制项目根目录的整个 `data/` 到安全位置，不要只复制画册索引。保留 data/execution/ 中的 SQLite 任务数据库；必须停服务后复制，运行中的 WAL 不能遗漏。
3. 在目标电脑安装 Mio，保持服务停止，将备份的 `data/` 放入项目根目录。
4. 启动后核对画册数量、原始图片、分镜、预设、工作流与保存状态。
5. 检查完成前不要删除备份。

`data/secrets/provider-keys.json` 包含未加密的图像渠道密钥。完整目录备份属于敏感资料，只存放在可信设备，不要上传公开仓库。

## 便携工程 ZIP

在设置的服务与保存区域导出完整图片目录 ZIP。解压后使用界面的目录载入功能恢复，不要把便携目录直接覆盖服务端 `data/`：两者结构不同。

便携目录 ZIP 会包含图片变量，以及任务和画册来源快照引用的旧图片；恢复时需运行 Python 服务，将它们重新写入本地不可变素材目录。只替换当前变量不会删除仍被快照使用的旧图。

普通工程导出不包含图像渠道密钥；在目标机器重新保存密钥。只含 `/images/` 引用的 JSON 不包含图片文件，不能单独用作完整备份。

## 单独导出资源

- 工作流库支持导出全部与批量导入。
- 分镜、角色预设和画册 HTML 可按需导出。
- 对外分享前检查提示词、参考图和其他服务配置是否含私密信息。

更多说明：[数据目录](../DATA_LAYOUT.md) · [渠道与本地密钥](CHANNELS_AND_KEYS.md)

## 服务端任务备份

完整 data/ 备份包含持久执行记录和素材来源索引。便携目录不是事务数据库迁移工具：恢复后的未结束服务端任务标记为需人工核对，不自动重新提交。便携目录会包含画册中的多结果 artifacts 图片。参阅 [恢复边界](FOUNDATION.md)。
