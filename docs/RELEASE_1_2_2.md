# Mio 1.2.2 — 分镜导入首幕保护

> 本专项最终合并入 [2.0.0 完整交付](RELEASE_2_0_0.md)，没有单独发行 1.2.2 安装包。以下保留导入修复的历史说明；当前升级请用独立文件转换教程。

2026-09-13 · 本地改进版，基于实际交付的 1.2.1。

## 本次发现并修复的问题

制作独立中文分镜时，实际使用“导入分镜”按钮检查了 JSON 和图片变量。发现 1.2.1 的导入流程虽然创建了新的模板与幕 ID，却存在一个编辑器归属错误：

1. 导入后先把当前模板切换为新模板。
2. 页面导航随后保存尚未重建的旧编辑器。
3. 旧第一幕的名称、提示词等被写到了新模板第一幕，可能让第一幕丢掉图片变量。

问题已在实际 1.2.1 完整 ZIP 解压后的运行环境复现，不是仅通过阅读代码推测。

本版在切换模板前保存旧编辑器，切换后立即绘制新模板编辑器，使随后导航保存的内容与当前模板一致。未失焦草稿仍归属于原来的模板，不会丢弃，也不会污染新导入内容。

## 导入与覆盖的准确边界

- 导入分镜 JSON 会分配新模板 ID 和新幕 ID；同名重复导入也创建副本，不按文件中的 ID 覆盖旧模板。
- **导入后会为当前正在编辑的画册计划选中新模板。** 想保留旧计划的选择，应先新建空白画册计划再导入。
- 已生成的画册、其他旧模板和其他计划不因导入而重写；本操作不启动生成。
- 不要把分镜文件当作整份工程备份导入，也不要覆盖 `default_comic_template.json`。

## 可选分镜

`examples/storyboards/晴天借阅室_分镜导入.json` 是独立的十二幕中文分镜，含唯一图片变量 `{主角参考图}`。它不会自动导入或加入生成队列，不是默认用户数据。

使用时，在新画册计划的“角色与画面设定”中新增图片类型属性，变量名设为“主角参考图”，上传一张单一成年人物的清楚参考图。分镜 JSON 不自动创建该图片属性，也不携带用户图片。

完整创作稿、模型调研和使用说明由本轮单独的分镜包提供。本版不声称已经用用户的付费模型生成或验收十二张图片。

## 启动与升级

这是完整源码运行包，保留独立 JS/CSS。需要 Python 3.10+，运行不需要 npm，不含 Windows exe。

1. 关闭旧网页与服务，完整备份旧项目。
2. 解压到新目录，把旧 `data/` 整体复制进去，尤其保留 `data/execution/jobs.sqlite3`；旧 `images/` 和旧式 JSON 如使用，也原位保留。
3. Windows 双击 `start.bat`；macOS/Linux 运行 `sh start.sh`；或运行 `python server.py`。
4. 打开终端给出的地址，默认 `http://127.0.0.1:8777`，强制刷新并核对数据。

不要直接双击应用 `index.html`；不要让新旧服务同时编辑同一数据目录。
