# 新建任务与桌面选择重构

## 设计方向

延续 Mio 原有主题，用更安静的工作台取代堆叠式表单：左侧创作步骤，中间配置区，底部固定操作。浅色与深色均使用既有主题变量，不写死配色。

- 三步：分镜与渠道 → 视觉预设 → 命名与入队。
- 模型与 LoRA 归入可展开的高级配置，保留现有覆写、渠道校验和提交逻辑。
- 视觉预设为双列卡片，统一选中描边、底色和勾选状态。
- 保留画布连线模式；入队仍然不自动调用生成渠道。
- 窄屏将侧栏压缩成横向步骤，预设改为单列。

## 桌面选择约定

接入范围：画册、任务向导视觉预设、桌面分幕列表、工作流库、工作流映射列表。

| 操作 | 行为 |
| --- | --- |
| 单击项目 | 替换为单选 |
| 双击 / Enter | 打开画册或编辑项目；预设不需要打开 |
| 空白处单击 | 清空当前区域 |
| 拖动 | 超过 5px 后显示矩形，实时按相交范围选择；回拖会取消不再相交的项目 |
| Ctrl / Cmd + 单击 | 切换单项选中 |
| Shift + 单击 | 按当前可见排列连续选择 |
| Ctrl / Cmd + 拖动 | 基于拖动开始前的集合，反转框内项目 |
| Shift + 拖动 | 加选框内项目 |
| Ctrl / Cmd + A | 只选择当前列表可见项目，不劫持输入框 |
| Esc | 清空当前区域选择；拖动取消时恢复原集合。没有可清空的选择时关闭当前弹窗；装配向导里的预设勾选属于表单内容，Esc 不清空，直接关闭向导 |

拖动时接近滚动容器边缘会自动滚动。选择过程只更新状态、选中样式和复选框，不重绘整个列表；松开后再刷新批量工具条。原有的桌面「进入批量模式」按钮不再显示。删除仍走原有确认流程。

## 实现

`js/desktop-selection.js` 为共享选择控制器，使用适配器连接既有状态和批量操作。内部兼容保留 `selMode / bulk` 标志，但它们由选择数量自动驱动，不再是桌面用户必须开启的模式。

选择事件在 app 的全局快捷键之前安装，避免弹窗抢走 Esc。双击采用连续点击识别，避免首次选择重绘 DOM 后浏览器丢失原生 dblclick。画册直接调用原打开动作，绕开旧的批量选择点击拦截。

桌面卡片拖动优先框选，不再兼任画册拖动排序；原排序按钮仍可用。触屏暂保留原有轻点打开及批量管理入口，避免拖选抢占手指滚动。本次没有为原本不支持批量操作的生产队列、文件浏览器新增批量后端 API。

## 验证

已执行：
- `node js/build.js dev`：模块与组装脚本语法检查通过，重建资源版本。
- `npm run lint`：JS 与 HTML 检查通过。
- `npm run test:contracts`：86 / 86 通过。
- `npm run test:desktop-refresh`：真实 Chromium 检查五个接入区域、点击/Ctrl/Shift/Esc/框选/局部全选、画册与分幕打开、390px 页面无横向溢出、无运行时异常。

运行交互测试前，先启动 `MIO_HOST=0.0.0.0 MIO_PORT=8000 MIO_NO_BROWSER=1 python server.py`，并安装 Playwright Chromium 和系统依赖。可用 `MIO_TEST_URL` 指向其他本地服务；截图默认输出到系统临时目录，可用 `MIO_ARTIFACT_DIR` 指定路径。

未执行全量 `test:current`，未连接真实图像渠道、未实际生成付费图像。触屏实机、跨浏览器和超大列表性能仍需要进一步验收。测试用额外视觉预设仅用于浏览器内的展示数据。
