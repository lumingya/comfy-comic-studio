# 应用内更新与 AI 辅助

本轮交付范围：完整的版本目录与签名更新流程，以及可关闭的聊天式 AI 辅助扩展。遵循现有统一 UI 控件、透明次要按钮与简洁主界面。

## 实施与验收顺序

1. 更新：官方 Release 分页目录、更新日志、启动后台检查、手动检查、选择版本、下载进度、取消暂存；下次启动安装并处理依赖，失败恢复旧版本。
2. AI 后端：内置扩展生命周期、渠道适配、会话和图片持久化、开放 API、工具目录、权限与确认、停止和请求去重。
3. AI 界面：聊天、历史记录、图片、渠道和模型目录、权限管理、悬浮窗/一级菜单；提取原文本模型配置。
4. 备份：纳入 AI 对话和图片，沿用备份的凭据开关。
5. 独立功能评审，补齐必要缺口；随后独立 bug 审查，修复并验证。
6. 集中运行仓库门禁、生成 API 类型和客户端，按仓库规范提交。

## 独立扩展与市场

- 业务集中在 `extensions/<id>/`；AI 辅助包含 `core`、独立 `page` 构建产物、测试、清单和说明。主题同样为独立数据包。宿主只保留加载器、SDK、通用服务注册与界面承载。
- 参考 AstrBot 的清单、入口与相对模块组织，以及 SillyTavern 的独立脚本、样式和资源清单；安装不要求改宿主源码或重新构建。
- 左侧「扩展」提供市场与已安装。市场展示实际随包项目，支持其他 JSON 目录源、搜索分类、详情和按摘要校验的安装更新。
- 文件夹和 ZIP 共用加载器，导入版可覆盖随包同 ID 版本；后端路由随启停动态挂载，无需重启。受信完整页面使用独立同源工作区；原有受限面板继续保留沙箱和声明式请求约束。
- 备份通过通用参与者契约纳入扩展数据；只调用本机审阅并保存摘要的规则，不执行备份中携带的代码。

## 当前发布环境的事实

实现时官方仓库 `lumingya/comfy-comic-studio` 的 Release API 返回空目录，项目尚未内置发布公钥。可以验证版本管理与签名安装逻辑，不能将真实官方下载和安装记作通过。开发目录不覆盖 Git 源码；正式发行目录支持应用内暂存升级和降级。

不为测试重启用户的 Mio、ComfyUI 或代理进程，不发布 Release，不修改用户凭据。

## 评审与本机验收

先独立完成功能评审，再进行只读 bug 审查。修复了主题分类不一致、扩展启用失败仍提示成功，以及发送未到达后端时会话无法恢复三项问题。AI 权限由整类禁用细化到具体敏感操作；普通系统只读操作可单独授权。

本机隔离实例在 8797 验证默认市场目录、AI 热启停、独立 HTML/JavaScript 资源与 MIME、未提交请求回执、重新启用后的对话持久化。没有提交真实云端模型请求。浏览器调试连接超时，本轮不宣称完成视觉验收。

随包数据的本机副本已有运行时变动；使用 Git 中的 64 份发布文件通过清单校验，保留本机数据。独立包附带构建产物，CI 会检查单独安装依赖后的重建一致性。
