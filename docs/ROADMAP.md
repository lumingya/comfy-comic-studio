# Mio 路线图

> 本文件记录产品方向、架构约定和待办。用户说明见 [README](../README.md)，开发约定见 [AGENTS.md](../AGENTS.md)。
> 项目处于早期阶段：**不承诺向后兼容**，允许根本性重构，一切以作品效果为准。

---

## 1. 定位与决策

Mio · 绘页是本地优先的条漫工作室：从一个故事出发，经剧本、设定集、ComfyUI 出图、条漫画布，到阅读与导出。

| 决策 | 选择 | 影响 |
|---|---|---|
| 主形态 | **条漫**（竖向滚动） | 数据模型以「话 → 格」为核心；有竖向节奏、留白与转场；嵌字层可以跨格；按平台预设切片导出。画册模板是次要输出 |
| 主力出图 | **本地 ComfyUI** | ComfyUI 是一等公民：任意工作流透传、多实例池、WebSocket 实时预览、缺节点和缺模型诊断。NovelAI / OpenAI 兼容接口作为云端渠道，不是优化重点 |
| 技术栈 | FastAPI + React | 后端 Python 3.11+、Pydantic、SQLite；前端 Vite + React + TypeScript（strict） |
| 参考硬件 | RTX 4060 Laptop 8 GB 显存 | 默认按 8 GB 档设计：出图分「草稿 / 成品」两档（§6.4） |
| 模型 | 只用已装模型 | SDXL 动漫底模（Illustrious / NoobAI）、已有 LoRA、NoobAI tile ControlNet；需要参考图一致性时走云端定形（§6.4） |
| LLM | 本地反代，OpenAI 兼容 | 剧本和视觉检查走同一个 OpenAI 兼容地址，密钥只留在本机 |

## 2. 原则与能力

### 2.1 三条原则

1. **ComfyUI 不做减法**
   - 导入任意 API 格式工作流；任意字段或变量写入任意节点输入（JSON Pointer）；每格覆盖节点参数；原始工作流 JSON 可直接编辑。
   - 内置模板只是默认值。Mio 只负责编排：新模型、新节点、新技术一律以工作流接入，不需要改 Mio 代码。
2. **所有自动化都要能手动接管**
   - 剧本规划、提示词编译、参考图挂载、自动挑图、自动排版、自动气泡，每一层都能手动接管或锁定。
   - 每格都有「原始提示词模式」，完全跳过编译器。编译结果可见、可改；`{变量}` 系统作为高级层保留。
3. **基座保持精简**
   - 界面只放日常创作需要的入口；专业工具先做在后端和开放 API 里，需要时再接界面或交给扩展。
   - 界面上删掉的功能，后端能力和接口照常保留并有测试。

### 2.3 界面结构

- **首页**：开始一部作品、教程入口。
- **画册集**：书架、阅读室（阅读、版式、排版画布、导出）。
- **创作工坊**：分镜工坊、预设工坊、装配与生成（出图板、逐格编辑）。
- **工作流与 API 配置**：ComfyUI 实例、工作流库、出图配置、云端出图。
- **设置**：工作室、外观与阅读、模型与连接、数据与备份、扩展、关于与更新。
- 任务页（顶栏「队列」）、命令面板（Ctrl / ⌘ + K）、帮助抽屉（`?`）随处可用。

### 2.4 扩展系统

扩展的能力上限等于核心的上限；变的是接入方式。

- **内置功能也注册成扩展**。面板、管线步骤、导出器、出图渠道、版式、提示词编译器都通过同一套注册表（`server/mio_server/registry.py`）挂进核心，做法类似 VS Code 的内置扩展。
- **扩展点**按条漫管线设计：出图与 LLM 渠道、工作流模板与绑定预设、管线步骤、导出器与切片预设、版式与气泡样式、剧本模板、界面面板（沙箱 iframe）、后端路由与后台任务、事件订阅。
- **逃生口**：`ctx.internal` 直接访问内部 store、服务和组件。它明确标注为不稳定、跨版本可能失效，但什么都能改。
- **图像能力靠 ComfyUI 工作流扩展**，Mio 一行代码都不用改。
- **安全**：扩展以 zip 安装，启用时信任内容摘要，文件变动即停用；`MIO_SAFE_MODE=1` 跳过全部扩展。
- 注册表先只供内置功能使用（P1），接口稳定后对第三方开放（P5）。SDK 说明见 [extensions/README.md](../server/mio_server/extensions/README.md)。

## 3. 开发方式

- 多个 AI 代理并行开发，靠验收测试和本文件对抗上下文丢失。入口文档只有三份：README（用户）、AGENTS.md（代理）、ROADMAP.md（方向与待办）。
- **代码格式**：前端 Prettier，Python ruff format，行宽 100；TS strict；单文件尽量不超过 400 行。
- **测试金字塔**：主体是领域单测（提示词编译、绑定、版式、气泡布局、任务状态机），加 API 契约测试；E2E 只保留几条主链路，在本地机器上跑；效果基准单独跑（§5）。
- **不入库**：生成物、大文件、截图。

## 5. 效果度量

| 层面 | 指标 | 目标 |
|---|---|---|
| 画面 | 角色一致性通过率：按设定集外观清单做 VLM 检查 | ≥ 85% |
| 画面 | 镜头符合率：景别、出场人物、动作与剧本一致 | ≥ 80% |
| 叙事 | 一话 40–60 格能顺畅阅读：节奏留白合理、台词可读、气泡不挡脸 | 人工评审通过 |
| 效率 | 从一句话创意到可读的一话初稿 | ≤ 30 分钟（出图时间另计） |
| 效率 | 修一格的时间；每张被采用图的平均出图次数 | ≤ 1 分钟；可统计 |

**效果基准**：一篇黄金故事（2 个角色、3 个场景、12–16 格，覆盖近景、远景、背影、双人互动、情绪变化、夜景，见 `next/fixtures/golden_story.json`）。每次改管线都跑一遍，输出联系表和 `metrics.json`；图片不入库，只提交指标摘要。沙盒连不到本机 ComfyUI 时只跑模拟和单测。

## 6. 架构

### 6.1 领域模型（代码与界面同名）

```text
Series 作品（连载）
├─ Bible 设定集
│  ├─ Character 角色：外观清单（发色/瞳色/发型/服装件/饰品）、自然语言描述、标签描述、
│  │                 参考图集（正/侧/背/表情）、服装变体、LoRA（按模型族）
│  ├─ Location 场景 / Prop 道具：描述 + 参考图
│  └─ Style 画风：风格描述（按方言）、风格参考图、LoRA
├─ Episode 话
│  ├─ Panel 格（按阅读顺序）
│  │   ├─ 内容：镜头（景别/角度）、出场角色 [角色, 服装, 表情, 动作, 画面位置]、场景、时间/光线、画面描述
│  │   ├─ 台词：[说话人, 文本, 类型: 对白/心声/旁白/拟声]
│  │   ├─ 条漫属性：宽度模式（全宽/内嵌/出血/无框）、画幅比例、与上一格的间距、转场背景
│  │   └─ 覆盖项：原始提示词模式、追加提示词、负向、种子、节点参数覆盖
│  ├─ Take 候选：出图结果 + 完整参数快照 + 评分 + 是否采用
│  └─ Strip 条漫画布：每格的位置与裁切 + 嵌字层（气泡/旁白框/拟声/特效字，可跨格）
└─ Output 输出：网页与手机条漫阅读、平台切片、长图、PDF；画册模板（次要）

RenderProfile 出图配置：ComfyUI 实例或实例池 + 工作流组合 + 绑定 + 提示词方言 + 能力
Job / Attempt：统一任务引擎
```

平台切片预设可配置。常见规格：LINE Webtoon 宽 800 px、按 1280 px 切片；Tapas 推荐宽 940 px。以各平台当前规则为准。

### 6.2 后端

- **框架**：Python 3.11+、FastAPI、Pydantic、uvicorn。OpenAPI 自动生成，前端 TS 类型和 Python 客户端都从它生成；WebSocket 转发 ComfyUI 进度。
- **存储**：一个 SQLite 库存元数据，素材按 sha256 去重存放；`.mio.zip` 只作交换格式。
- **统一任务引擎**（`jobs/`）：幂等键、不可变快照、租约、epoch 防过期结果、`uncertain` 不自动重试、并发窗口、立即停止、失败上限暂停、重启恢复。多个 ComfyUI 实例按模型分组调度。
- **模块**：`pipeline/`（剧本、提示词、参考图、质检、排版、嵌字）、`comfy/`（绑定、运行器、WebSocket、诊断、实例池）、`providers/`（云端渠道）。
- **接口**：`/api` 供本机界面使用，`/api/v2` 是带作用域令牌的开放接口（read / write / render / admin）。

### 6.3 前端

- Vite、React、TypeScript（strict）；TanStack Query 管服务端状态，Zustand 管界面状态；`openapi-typescript` 生成类型；i18next 中英双语；Radix；react-konva（条漫画布与嵌字）；dnd-kit（拖拽）。
- 冒烟测试用 API 数据挂载全部路由；i18n 测试保证两套文案与代码用到的键一致。

### 6.4 ComfyUI 集成

- **绑定优先级**：
  1. 节点标题标签：`[mio:prompt]`、`[mio:negative]`、`[mio:seed]`、`[mio:width]`、`[mio:height]`、`[mio:ref:1]`、`[mio:mask]`、`[mio:init]`、`[mio:output]` 等。API 格式导出自带 `_meta.title`，不需要装插件。
  2. 用户手动映射（JSON Pointer）。
  3. 启发式识别兜底。
- **绑定规则**：
  - **字段选择**：`[mio:prompt=positive]` 指定写入节点的哪个字段，自定义节点字段也能写；不指定时写入第一个非连线的字符串字段。
  - **一对多写入**：同一个标签可以出现在多个节点上，同一个值写进所有目标（例如两个 `KSamplerAdvanced` 的 `noise_seed`）。
  - **绕过只在前端生效的节点**：`easy globalSeed` 这类节点靠 ComfyUI 前端 JS 生效，经 API 提交时不起作用，种子由 Mio 直接写进各个采样器。
  - **按输出选变体**：输出节点标 `[mio:output:draft]`、`[mio:output:final]`，运行时只保留所选输出及其上游；一份导出同时服务草稿档和成品档。
  - **核对**：`[mio:inspect]` 在运行后读回文本节点（如 ShowText），核对最终提示词。只存在于 ComfyUI 前端的节点值导入时快照，运行前推回服务器，跑完即恢复。
- **实时与诊断**：`/ws?clientId=…` 获取进度、执行节点和预览帧；`/object_info` 找出缺失的自定义节点；对照模型列表找出缺失的模型文件。
- **8 GB 显存下的一致性**：
  - SDXL + 角色 LoRA：画风最好、速度快。原创角色需要先训练 LoRA（ComfyUI 原生有 `TrainLoraNode`）。
  - 混合路线「云端定形，本地定画风」：云端模型按参考图定构图和角色，再用本地 Illustrious 低重绘幅度图生图加 tile ControlNet 统一画风。
- **草稿档 / 成品档**：先用草稿档给每格出 K 张候选；选定后只对采用的图跑成品档（迭代放大、部位细化）。成品档把选中的草稿图作为 `[mio:init]` 输入，不依赖 ComfyUI 缓存复用：有的节点每次提交都判定为「已变化」，下游会全部重算。
- **参考速度**（4060 Laptop，SDXL，832×1216，20 步）：热启动约 17 s / 张；一话 50 格 × 每格 3 张草稿约 43 分钟。

### 6.5 核心管线

```text
一句话创意 / 小说片段
  → LLM 结构化剧本（JSON Schema；不支持时用 json_object，再校验和修复）
  → 话 / 格（镜头、出场角色、表情、台词、条漫节奏）            ← 可编辑，可锁定
  → 设定集（外观清单 + 参考图集）                              ← 挑选锁定
  → 提示词编译（标签方言 / 自然语言方言）+ 按出场角色挂载参考图 ← 可切到原始模式
  → ComfyUI 出图：每格 K 个候选，实时预览，采用
  → 条漫画布：按格属性自动排版（间距、宽度模式、转场）          ← 可拖拽微调
  → 自动嵌字：气泡避开人脸、阅读顺序、尾巴指向说话人、竖排、拟声
  → 导出：平台切片、长图、PDF、网页阅读、.mio.zip
```

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 本地显存门槛高（8 GB） | 草稿档 / 成品档分离；默认用已装的 SDXL / Illustrious / NoobAI + LoRA；需要强一致性时走云端定形、本地统一画风 |
| ComfyUI 经公网隧道暴露 | 没有鉴权时任何人都能提交任务、查看出图历史、上传文件，还可能经 ComfyUI-Manager 安装节点（相当于远程执行代码）。**只在联调时开隧道，用完即关**；长期使用请加带鉴权的反向代理 |
| 本地界面的 `/api` 不需要登录 | 网页可能向 127.0.0.1 发简单请求或做 DNS 重绑定。`api/guard.py` 兜底：Host 只认 localhost、IP 和 `MIO_ALLOWED_HOSTS`，写请求与 WebSocket 握手必须同源；`/api/v2` 走令牌。**不要把 8788 端口直接暴露到公网** |
| 扩展执行任意代码 | 安装时信任内容摘要、变动即停用、安全模式；对第三方分发要有明确的信任确认 |
| VLM 评审不稳定 | 结构化清单、多次投票，最终由人拍板 |
| 沙盒无法真实出图 | 沙盒里只跑模拟和单测；真实基准在本机跑，回传 `metrics.json` |
