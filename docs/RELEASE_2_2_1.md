# Mio 2.2.1 — 预设删除与复制说明

[教程中心](README.md) · [完整内容与安全升级](guide/CONTENT_AND_SHARING.md)

## 预设管理补齐

「角色与画面设定」页的预设选择器旁增加「删除预设」。没有选择时禁用；新建空白预设或将当前设定另存为预设后选中新预设，可直接管理。

- 一次删除确认，展示引用它的画册计划数量。
- 删除预设库里的文件，不删除已生成画册、原图、台词或已入队的冻结快照。
- 正在引用的全册/单幕变量保留为对应计划的本地变量；现有覆盖顺序和值保持不变，其他预设引用保留。
- 参考图片先随保存转为幸存计划/画册自己的图片，再提交删除，不留下指向已删除预设的图片路径。
- 仅变量导入的画册也保留自己的变量快照，仍可再次分享变量和参考图片。
- 取消不删除；保存冲突或失败明确显示「删除尚未确认」，保留待保存草稿，不假装磁盘已经删除。
- 删除后刷新不会恢复该预设。使用原生版本条件写入，不强制覆盖其他页面。

## 为什么单文件仍可能覆盖

单文件解决的是「改一份资源不必重写整个库」，不是为文件管理器增加自动追加/合并功能。

| 复制方式 | 结果 |
| --- | --- |
| 新文件名 + 新内部 ID | 扫描或刷新后追加独立资源，原文件保留 |
| 文件路径和名称相同，文件管理器选择替换 | 原文件被操作系统覆盖，程序无法拦截 |
| 改了文件名，但内部 ID 相同 | 被识别为重复身份并报告冲突，不会当作两份独立资源 |
| 界面导入 JSON / `.mio.zip` | 分配新 ID、重映射引用和图片所有权，适合安全追加 |

含图的资源必须连同 `.assets/` 或画册目录中的 `images/` 一起复制。不要把「合并目录」理解为合并同名 JSON 的内容；不同文件管理器对整个文件夹替换的行为也不完全相同。

2.2.0 升级到本版无需数据转换。仍建议将程序解压到新目录，通过 `MIO_DATA_DIR` 指向原工作区，避免发行包中的同名初始文件覆盖个人修改。

## 验收

新增实际浏览器测试覆盖新建后删除、取消、全册与单幕覆盖、第二份计划、原图和任务快照、仅变量画册的再次导出、实际文件消失及重载、受控 409/500、响应丢失及保存重试、不同文件/ID 追加、同 ID 冲突和 320/390px 明暗主题布局。没有付费模型请求。

本版仍是包含 59 个内容文件的完整源码运行包，不是补丁。运行仅需 Python 3.10+；测试和打包记录见 `docs/acceptance-2.2.1/`。
