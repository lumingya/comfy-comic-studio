## 体验发现与边界

**渠道类型必须清晰。** 本代理的生图模型需要聊天接口；只看到“OpenAI 兼容”时，新用户容易选到 Images API。现有“聊天接口出图（反代）”选项能完成配置，但教程应把模型名、渠道类型和请求方式放在同一示例中，避免用户先遭遇一次失败才理解差别。

**自动化填写和真实保存要区分。** 本轮浏览器自动化填入正向提示词后，一度出现 textarea 已显示文本、API 保存值仍为空的情况；标题、负向与旁白已经保存。对同一输入框执行真实键盘 Space 后 Tab，API 即得到完整文本。生成前已修正并核对，也同步了此前装配的画册快照。该证据只能确认自动化填充事件与受控输入不匹配，不能据此判定普通用户手工输入会丢失。对未来 UI 自动化，应以保存后的 API 值为依据。

**旁白呈现需要适合轻盈画册。** 初次观察旧阅读器时，旁白既以黑边白框合成在画面内，又在画面下重复一次；对这部水彩作品显得偏重。问题已交给主线程处理，本文保留的是修复前观察，不代表最新阅读器仍存在该问题。新导出的无字图加外部旁白版本视觉清爽。

后续修正已在同一画册上视觉复核：未保存版面时显示完整原图与图下旁白，画面内没有自动黑边文字框；已保存的版面继续保留。深夜放映室预览占满顶栏下方空间，原图保持 4:3，标题在深色背景上清晰可见。默认留白单页模式也已核对，只有图下的一份旁白。单元测试另外覆盖混合嵌字、SFX、跨格截断及 PNG/WebP 透明通道，不将这些边界测试误称为本册实图验收。

**手工优先路径可用。** 四幕故事不必经过 AI 剧本生成，分镜工坊和装配向导即可建立作品。API 能补充参考图与精确批次控制，适合外部程序扩展。此次只验证当前代理的一种聊天生图模型及四幕流程，没有据此扩展为所有云端渠道或 ComfyUI 插件都已兼容。
