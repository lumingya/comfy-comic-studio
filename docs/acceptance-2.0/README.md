## 不只计数的回归重点

- 摘要不是空正文：保留真实已生成计数；已完成队列轮询不能清空摘要计数；用户打开后才读取完整正文。
- 新加的跨请求重现：任务的合并保存 ACK 先确认进度、但画册图片尚未轮询时，仍根据实际可见结果拉取缺少的图片，而不是只看任务计数。
- 慢正文响应与较新的图片轮询相交时，保留新版本图片编辑及完整对白。
- 多标签页异字段合并，同字段拒绝覆盖；合并 ACK 后第三次保存不倒退；丢失响应后显式重试不重复创建资源。
- 控制台和文件库诊断保留整理失败信息；SQL 已提交的图片修改、删除墓碑可恢复整理，不调用供应商。
- 第二个 worker 先被租约拒绝，不得改写正在运行实例的暂停状态；重启手动恢复已有队列。
- 真正点击导出/导入/忘记密钥控件；不是只调用孤立库函数。
- 旧全库 revision 与摘要正文假设不再作为新架构目标。外部创建分镜后，本页可以保存另一个计划且不删除新分镜；真正同字段冲突仍有独立回归。

## 测试过程中的失败与修正

最终成功日志之外，过程中发现并修正了：启动 ready 提示早于监听；摘要缓存版本未失效；队列轮询对摘要重新计数为零；任务 ACK 先于画册结果的进度竞态；测试仍直接把未加载摘要传给同步备份函数；基准工具重复等待已被 SIGTERM 终止的进程导致临时目录未清理。后者留下的合成数据占用了沙箱临时内存，曾发生 Chromium target crash；修复清理流程、删除本工具遗留目录后，完整测试和基准分别成功复跑。

没有把超时/崩溃当作通过，也没有通过重发付费请求来“修复”结果。
