# UI 样式与主题

公共控件的外观由一组语义变量和一份控件样式决定。修改按钮、输入框或面板时，先找公共规则；页面样式只负责布局和该页面独有的内容。

## 修改入口

| 要修改的内容 | 入口 |
| --- | --- |
| 基础颜色、字体、全局重置 | `web/src/styles/base.css` |
| 按钮、输入框、卡片、分段选择、开关等公共外观 | `web/src/styles/ui.css` |
| 弹窗、抽屉等浮层布局 | `web/src/styles/overlays.css` |
| 搜索选择器的布局与交互外观 | `web/src/components/searchable-select.css`，复用公共变量 |
| 主题选择、系统明暗订阅、应用 CSS 变量 | `web/src/app/useTheme.tsx` 中的 `ThemeProvider` |
| 导入主题的令牌白名单与取值校验 | `server/mio_server/themes.py` |

普通按钮默认透明；主操作、危险操作、选中状态通过语义样式区分。不要为页头、内容区分别定义普通按钮底色，也不要在页面样式中重新定义 `.btn`、`.segmented` 等公共选择器。

## 自定义主题

主题 JSON 可在「设置 → 外观与阅读 → 主题」导入，也可由扩展提供。完整格式与取值规则见[扩展 SDK](../server/mio_server/extensions/README.md#主题)。

基础色未填写时使用对应明暗模式的默认色。控件语义变量未填写时由 CSS 从基础色派生：只改 `accent`，主按钮仍会随之变化；只有需要特殊外观时才填写 `button-primary` 等覆盖项。切换主题会移除上一主题的覆盖，避免圆角、尺寸或颜色残留。

主题负责通用界面外观。书封、画册模板、画布作品内容和阅读室的专有配色有各自的呈现规则；不会把所有局部装饰或每一个 CSS 属性都公开成配置。

## 本轮代码审计与处理

| 发现 | 处理 |
| --- | --- |
| 公共按钮、分段选择规则分散，依赖 CSS 加载顺序 | 公共定义集中到 `ui.css`；页面保留局部布局 |
| 声明语义变量后控件仍使用旧颜色，定制无法生效 | 公共控件、卡片、浮层和搜索选择器接入相同变量；未使用的变量不公开 |
| 顶栏、命令面板分别订阅系统主题并重复写 `<html>` | Shell 只挂载一个 `ThemeProvider`；切换入口仅读取模式和修改主题选择 |
| 控件设置 `aria-invalid` 却没有统一的错误外观 | 由公共控件样式提供错误边框和焦点状态 |
| 运行状态、书封等旧样式仍使用专有颜色 | 作为后续独立范围；本轮不宣称所有页面装饰都已统一 |

这次聚合沿用现有组件和 CSS 类，不增加只转发参数的组件包装。继续整理时优先删除重复的公共定义、修正实际使用链；不以文件更少或抽象层更多作为目标。

验证（2026-11-16）：后端 783 项（跳过 1 项）、Spike 80 项通过；前端全套 490 项中一项帮助面板断言没有等待异步数据，改为等待加载后，相关页面与主题 57 项通过。类型、构建、格式、Python lint、生成客户端及 64 个干净随包文件校验通过。Chrome 控件夹具按应用相同顺序加载样式，确认浅色、深色、自定义和还原后的颜色、圆角、尺寸、间距与阴影生效；普通按钮透明，输入框与搜索选择器默认均为 36px，自定义后均为 44px。此检查验证公共样式，不代表所有页面的布局均已复验。
