# Mio 1.2.1 — 余光，先让画面好好说话

2026-09-13 · 本地改进版，基于已交付的 1.2.0；不是上游官方发布。

## 为什么重做

1.2.0 的「余光」过于偏向插画展示。实际漫画中，相邻画面忽大忽小，旁白被推到远离图片的侧栏，装饰英文与大号数字又增加了干扰。

在旧包实际携带的离线画册中，1440px 桌面视口的竖图宽度为 439px、下一张方图为 768px，差了约 1.75 倍。这个问题不能靠换几张漂亮的演示图解决。

这次按确认的 **「画面优先，干净连贯」** 方向，修改同一个「余光」模板，没有再增加多个版本供选择。

## 正文具体改了什么

- **同一中轴连续阅读**：取消奇偶幕左右交替。图片居中，标题和旁白直接放在自己的图片下面。
- **协调画面尺度**：常规横图、竖图、方图共用最高 840px 的阅读宽度，不再把竖图额外限制到窄小的画框。低分辨率图片仍不强行放大。
- **图片不裁切**：保持原始比例，长竖图自然下滑阅读，不为塞进一屏而缩小文字或裁掉画面。
- **紧凑的说明区**：缩小标题，旁白靠近图片；“看原图”与说明区一起对齐。标题、旁白和图片属于同一组，不再散落在宽大的横向版面里。
- **减掉多余装饰**：正文移除厚纸框、淡色大编号、PLATE / SCENE 英文标签、装饰横线；删除正文前的通用抒情卷首文案。
- **手机充分利用宽度**：390px 视口下，常规图片宽约 363px，左右约 13px 边距；不再嵌套厚边框挤小画面。

拱形封面、暖纸色、铜色细节、创作者签名和末尾项目小诗保留。目录、大图、实际尺寸、日夜模式、减少动态效果、无脚本阅读和离线导出仍可使用。

## 怎样获得新版布局

打开画册 → **版式 → 余光 · AFTERGLOW**。

- 已选择「余光」的画册无需重新导入模板：旧内置模板在加载时更新到设计修订 2。
- 画册选择不会被重置；原有五个模板和默认连续阅读保持不变。
- 自定义、导入、另存的模板副本不会被强行覆盖。
- 已经导出的旧 HTML 是独立文件，不会自动改版；需要从应用重新导出。

## 完整包启动与升级

运行只需要 **Python 3.10+**，不需要 npm；这是独立 JS/CSS 的完整源码运行包，不是补丁或 Windows exe。

1. 关闭旧网页与旧服务，备份旧项目完整目录。
2. 解压新包到新目录，将旧 `data/` **整体复制**进去。旧 `images/` 和旧式 JSON 如果仍在使用，也原位保留。
3. **尤其保留 `data/execution/jobs.sqlite3`**，不要只复制画册 JSON。这里包含任务、删除标记和编辑记录。
4. Windows 双击 `start.bat`；macOS/Linux 运行 `sh start.sh`；也可以运行 `python server.py`。
5. 打开终端给出的地址，默认 `http://127.0.0.1:8777`，强制刷新网页后核对画册。

不要双击应用 `index.html` 启动；不要让新旧服务同时写同一数据目录。本轮未修改后端任务、删除、供应商重试或图片编辑机制。

## 示例与验收

包内 `examples/afterglow/余光_AFTERGLOW_演示画册.html` 可直接双击离线打开，是新版真实 UI 导出的四幕画册。

专项另外使用了 **24 幕竖图/方图交替、图内对白与选项较密集的排版测试**，检查相同宽度、图文归属、段落距离、手机边界和无脚本布局。它由两张明确标记为“阅读排版测试”的素材交替组成，不是一部真实 24 幕漫画。素材基于本项目原有 AI 插画添加测试文字；没有把用户上传的截图或用户画册放进分发包。

实际查看了密集正文的桌面、手机、夜间截图，以及封面和普通插画阅读效果。测试日志与旧包复现见 `docs/acceptance-1.2.1/`，汇总见 `docs/TEST_RESULTS.txt`；最终 ZIP 的解压启动验收日志随交付目录另附。

**验证边界**：Linux Chromium，手机为模拟视口；未在用户的原始 24 幕工程、实体手机、原生 Windows/macOS、Safari/Firefox 或真实付费供应商上验收。没有真实付费生成请求。
