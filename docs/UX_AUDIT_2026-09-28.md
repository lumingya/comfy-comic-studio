# 全站操作体验主动审计 · 2026-09-28

## 检查范围与方法

本轮不是等待用户逐项指出问题。以当前路由表、所有页面组件及对应旧版交互代码为清单，检查导航、选择、键盘、弹窗、编辑保存、失败恢复和窄屏布局。

- 对照旧版 `desktop-selection.js`、`context-menu.js`、工坊与阅读器代码，保留新后端和现有能力，不回滚架构。
- **入口级覆盖：33 个路由/子页/旧链接，普通与专业模式 × 桌面与窄屏，共 132 次浏览器巡检。** 检查运行错误、缺失接口夹具、全局横向溢出和页面内容。入口检查不等同于每个功能都已经实机验收。
- **操作级覆盖：** 使用有状态的模拟接口，在 Windows Edge 中走通快速输入、切换、失败、重试、取消离开、实际 JSON 下载、阅读器返回、画布并发保存、复制失败及队列暂停等高风险流程；上一轮画册集交互也重新验证。
- 测试使用独立只读静态站和虚构数据，接口全部拦截；模拟生成请求只写入夹具记录。没有连接个人 8788 服务，没有实际出图、付费模型调用或个人数据写入。

## 已修正的关键问题

### 1. 保存和数据一致性

- 原分镜字段在请求成功前就标记“已保存”，失败后的相同文本不会再提交；多个字段分别提交整份 `overrides` 时还会互相覆盖。现在共用同步草稿引用、串行请求、准确的待保存/失败状态及显式重试。
- 切换分幕和离开自动保存页面前先完成保存。失败时保留原编辑器，除非用户明确选择放弃后离开。
- 预设库不再让多个全量保存并发覆盖；卸载时不再使用初次渲染捕获的空工坊 ID。
- 同步抛出的校验异常也会进入失败/脏稿状态，而不是卡在“保存中”。
- 复制、导出及生成前提交活动编辑器；无效节点 JSON 不再被当作已保存，重复 Ctrl+Enter 不重复提交。
- 字幕编辑修改它实际显示的那一条对白/旁白，不再新增一条与原对白冲突的文本；其他说话人、桥接与对白类型保留。
- 变体编辑不再被作品标题刷新抹掉；清空标签只删除标签覆盖，不删除该角色的其他自定义字段。
- 画布不在脏稿状态下悄悄重排服务端布局；旧保存响应不清除提交后产生的新修改。
- 作品/章节编辑子树按资源 ID 定界；排版编辑的离开保护包含章节查询参数变化。

### 2. 选择、快捷键与弹窗

- 把上轮验证的桌面选择控制器用于分幕列表、任务剧本、候选图、装配卡片和任务列表：活动项、真正选中、右键临时目标各自独立。
- 支持空白取消、Ctrl/⌘ 加减选、Shift 连选、框选、Esc 分层退出；排序手柄、输入控件和触摸滚动不被截走。
- 输入法组合、文本输入、菜单及其他弹窗拥有自己的按键，不再把底层画册/候选图的操作一并触发。Backspace 不再充当列表删除键。
- 菜单和提示层在打开的原生阅读器里选择正确宿主；首次打开就使用当前顶层容器，不先渲染到不可交互的背景。
- 关闭/编辑图片的导航交给路由完成，只有真正离开才清理原生阅读器；取消离开不会留下一个已被提前关闭的编辑器。

### 3. 操作状态与可恢复性

- 顺序提交现在可停止；全局暂停/取消会同时停止派发后续任务，暂停的前序任务不会被当成已完成跳过。每次显式序列启动只尝试提交一次，失败不隐式重发。
- 未完整加载任务信息时，不允许基于空的任务记录误删；取消请求失败会显示错误而不是留下未处理的 Promise。
- 点击某个分幕的编辑入口会定位到对应分幕，不再总落到第一项。
- 任务详情、主题、扩展、更新和开放接口的读取失败都有可见重试，不与“没有数据”混淆。
- 令牌撤销和 Webhook 删除先确认；超大/无效的有效期不能使按钮抛异常。无法写入剪贴板时明确报告，并在当前弹窗内尝试兼容复制。
- 新建章节、未确认结果处理与回收站操作在处理中防止重复提交。
- 窄屏剧本编辑不再挤成“侧栏 240px + 编辑器 90px”；操作栏换行，对白文字框占独立行。

## 验收边界

这一轮确认的是应用内操作、参数送达、状态与错误恢复，不把“接口已模拟通过”当作真实模型成功。真实 GPU/服务商响应、生成品质、物理设备手势/音色和第三方扩展内部交互仍需相应环境验证。没有声称新旧版本的所有外观和全部扩展功能已经完全相同。

前端构建完成后刷新即可使用，本轮没有修改后端实现，也不自动重启正在使用的服务。
