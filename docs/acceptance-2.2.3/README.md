# Mio 2.2.3 验收记录

## 实际交付基线

`baseline-2.2.2.txt` 来自原始 2.2.2 ZIP 的实际解压项目：旧弹窗只有空的前缀/标签输入，没有现有名称输入；旧服务的失败策略没有连续失败字段。用旧调度器和受控 503 复现六幕各一次重试，总计十二次失败尝试，仍把全部分镜试完。仅在测试中推进重试截止时间，不访问真实供应商。

基线 SHA-256：`691734cadce44683099cf881fedbcd009a2d24ae59a0931e49070f644a8fb14a`。

## 专项范围

- `rename-retry.txt`：实际浏览器的单本/多本名称预填、直接替换、取消、整批输入校验、懒加载画册正文保留、未选画册/图片/标签不变、标签搜索、并发名称变更拒绝、409/500/响应丢失及同一名称重试。
- 同一浏览器套件覆盖实际失败策略 UI、非法值/取消/保存失败、计费确认中的两个上限、浏览器→Python→受控 HTTP 503、两次失败后停止六幕任务、超过原重试倒计时仍无泄漏、其他画册继续和刷新不恢复。31 项检查。
- `failure-streak.txt`：18 项 Python 专项测试。跨幕/逐次重试计数、成功归零、4xx/422/未知结果、关闭保护、每任务隔离、真正已开始的并发请求收尾、并发计数原子性、领取但未发出的请求停止、慢准备阶段发送前再次检查、降低配置立即生效、全局恢复/修改配置不能解除标记、显式继续保留已完成帧、重启保留、旧数据库字段迁移、严格参数校验及删除无需恢复授权。
- 迟到结果测试让请求先进入执行/发送边界、等待其他请求触发保护后再返回；不是把尚未开始的分镜假装成在途请求。未发送的尝试不会增加请求/失败计数。
- `upgrade-2.2.2.txt`：真实旧包创建和修改的原生资源/设置逐字节保留；现有画册直接进入新重命名框；旧包创建的暂存任务数据库补齐字段，没有重新请求模型，原重试参数保留。5 项通过。
