# Mio 3.1.0-dev.2 · 向导与连线画布

本轮实现架构与交互重构，不承担旧数据迁移。独立分镜、视觉预设和待命生产队列仍为主流程。

## 本轮交付

- 主侧栏改为「工作流与 API 配置」；「模板与扩展市场」成为独立全页工作区，设置中的「只留下你需要的功能」控制其可见性。市场搜索已适配全页路由。
- 「可选功能」总开关默认开启，悬浮精修助手默认开启。关闭总开关会收起子项、隐藏工作台入口并禁用子功能；不会抹去各工具的独立偏好。
- 视觉审校 API 仅在可选功能卡片开关左侧配置。移除了设置 Tab、旧摘要区域、顶部/阅读/画册菜单按钮及旧 API 设置动作。轻量面板优先显示地址、密钥、模型；测试与审校选项默认折叠。
- 新建任务支持三步向导：分镜与渠道 → 多预设 → 画册名称与待命确认。记忆上次渠道；ComfyUI 提供可搜索工作流和默认关闭的种子选项，必须存在有效种子映射才能启用。
- 支持真实节点拖动、鼠标拉线的 N:N 画布，也提供点击端口及键盘关联表。连线和节点可删除；重复边不会重复装配；未关联分镜会阻止整批提交。
- 正向、负向提示词一级并列；「应用到所有分幕」仅覆盖当前源分镜。作品简介可选且默认折叠。
- 预设不再拥有专属负向词或裸绑定 JSON 编辑区。使用普通变量，例如 `{画风负向}`、`{角色负向}`，在分镜负向提示词中显式引用；服务端不再隐式混合预设负向词。

## 明确的组合规则

每个分镜节点输出一张独立待命任务卡，并合并连接到它的所有预设：

- 分镜 A → 预设 1、2
- 分镜 B → 预设 2、3
- 结果：两张任务卡，不是四张笛卡尔积任务。

预设按画布中预设卡的添加顺序合并，同名变量后者覆盖；不同角色请使用不同变量名。每批最多 100 项，每项最多 20 份预设；队列总容量仍为 200 项。

## 数据与服务端

- 工作室偏好只写入 `ui.comfyStudio.studio`，不再同时写入 `settings.studio`；市场可见性只由 `studio.visibility.marketplace` 控制。
- ComfyUI 地址统一从 `comfyConfig` 读取，修复旧渠道解析器读取废弃镜像配置而误判空地址的问题。
- 任务冻结明确选中的已保存工作流；不会把当前全局工作流的映射偷偷混入另一个工作流。未启用种子时保留工作流原有字面值。
- `POST /api/production/assemble-batch` 先验证全部快照，再一次性发布待命索引；失败回滚，不留下可调度的半批任务。索引未引用的暂存不可变对象不会自动删除。
- 组装、切换模式、连线及确认待命均不调用模型。只有明确启动任务才执行前置变量与图像请求。

详见 [本轮验收记录](ARCHITECTURE_ACCEPTANCE.md)。当前核心回归使用 `npm run test:current`，源码包另行进行实际解压运行测试。

保留独立预设试绘、Phase 0、队列范围控制、安全重跑、阅读/分享、主题及扩展持久化。真实付费模型、用户的复杂 ComfyUI 工作流和 Windows 生命周期尚未实机验证。历史旧 UI 全链并未全部改写，旧源画册控制器也尚未全量移除；不宣称整套历史代码已经彻底重构。

只保留最新源码 ZIP 和本轮证据。Git、上传文件以及已有 `local-data/` 保留；本地运行数据不打包。官方 `data/` 随包提供并校验全部 59 个种子文件。不要用新开发版覆盖仍有未确认付费请求的旧生产目录。

在线预览使用独立的 `preview-data/` 干净演示数据；原有 `local-data/` 不改写，两者均不进入源码包。
