## 本轮确认的 8 处问题

| 优先级 | 问题与复现 | 修复 |
| --- | --- | --- |
| 高 | **画册“补齐”跳过费用确认。** 在任务可恢复时直接传 `trusted:true`；复现中确认函数调用 0 次、start 调用 1 次。 | 先刷新任务信息，再统一进入 `startProduction`；取消第一次确认不发送请求；未确认结果还有第二次额外确认。没有关联任务时引导重新装配，不回落到旧执行器。 |
| 高 | **批量补齐部分启动。** 对两本书循环发 start，第一本已运行，第二本因为队列忙而失败；先前的请求不会因此撤回。 | 删除这个非原子启动循环。该入口现在打开任务卡，明确要求逐本核对范围和费用；不再声称一键批量执行，也不以启动所有相邻任务冒充所选范围。 |
| 高 | **传输结果未知被当成普通失败。** TimeoutError、连接断开、响应截断，以及已有上游任务 ID 但结果不可读，都落入 failed，能绕过未确认结果额外同意。 | 此类 page/attempt 进入 uncertain；再次 start 必须 `confirm_uncertain:true`。明确的 ExecutionError 仍是 failed；已有结果的发布失败继续支持无付费恢复。真实本地 HTTP 测试接收 POST 后断开，确认只有一次请求，未额外同意不再发送。 |
| 高 | **仅靠 Origin/CSRF 缺少 Host 边界。** 用陌生 Host + same-origin 获取首页可读到页面能力令牌，再携令牌读取私有配置；本地复现两次都返回 200。这是 DNS rebinding 的关键服务端前提，不是实际在公网实施攻击。 | 在解析 HTTP 请求后检查 Host，陌生/重复/无效 Host 返回 MIO-HOST-001 / 403，首页、私有接口与正确令牌均不能绕过。保留回环、具体绑定地址和明确配置的可信 origin 主机。 |
| 中 | **关闭后的旧调度器仍能写数据。** close 释放 lease 后，旧对象的 pause/cancel/remove/recover-publication 仍可执行；例如删除继任调度器目录中的任务。 | 上述修改入口在持锁时检查 closed，统一返回 MIO-PROD-CLOSED / 503。worker 正在收尾时的内部结果保存不受阻止。 |
| 中 | **重复推断 key 导致 DOM 丢节点。** 多个按钮有相同 data-act 时，匹配算法会把已处理或刚插入的节点再次取走；从空容器渲染列表也会少控件。 | 仅从尚未处理的兄弟节点后缀寻找候选，不再重复消费节点。保留第一轮的活动编辑器/IME 不卸载规则。附 200 次固定种子的混合元素、文本、注释和重复 key 变换测试。 |
| 中 | **弹窗期间的队列变更可能永远不呈现。** 收到 200 时更新队列和 ETag，但因为弹窗打开不 render；关闭后持续收到 304，也就一直不 render。 | 单独保留 renderPending。允许呈现时即使本次为 304 也补一次 render，随后恢复未变化不重绘。 |
| 低 | **畸形 CSRF 请求导致断连。** `X-Mio-CSRF: é` 进入只接受 ASCII 字符串的 compare_digest，抛 TypeError，客户端得到断开的连接。 | 非 ASCII 令牌先判无效，再进行常量时间比较；稳定返回 MIO-CSRF-001 / 403，不把异常暴露为断连。 |

## 兼容行为变化

### 自定义地址

默认访问回环地址。自定义域名、反向代理或绑定 `0.0.0.0` 后用局域网 IP 访问，需配置完整可信入口，例如：

```bash
MIO_HOST=0.0.0.0 MIO_ORIGINS=http://192.168.1.10:8777 python server.py
```

这是 POSIX shell 示例；Windows 请使用对应环境变量设置方式。多个可信 origin 用逗号分隔。不要直接公开服务；Host、Origin 和 CSRF 不能替代公网认证。无浏览器来源头的合法本地 CLI 仍兼容，公共 `/api/v1` 保留 bearer 机制。

### 补齐任务

单本补齐保留缺帧范围，增加必要的费用与结果核对。旧批量补齐入口已明确降为逐本确认的安全引导；本轮没有引入未经验证的多任务原子启动协议。所选书目不会被替换成“从某任务往后全部开始”。

### 未确认结果

本轮修复针对已复现的传输歧义和已记录的上游受理标识，不宣称穷尽所有供应商异常语义。结果未确认不表示请求一定成功，也不表示供应商不会计费。需先检查上游，再决定是否明确重跑。
