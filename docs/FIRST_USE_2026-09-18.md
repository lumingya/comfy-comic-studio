# 首次上手体验修复 · 2026-09-18

## 方法与边界

从四份互相隔离的空数据目录、新浏览器会话开始，通过实际界面完成配置、写分镜、装配、确认开始、查看生成结果。不向页面注入渠道、资产或队列状态，不用生成函数 monkeypatch 来冒充服务调用。

`tests/journey_fixture_server.py` 在本机提供协议形状的 ComfyUI、NovelAI、OpenAI Images / Chat 服务。Mio 运行真实渠道适配器、队列、持久化和阅读器。测试服务只返回一张固定的微型 PNG；明确阻止非回环联网和外部 DNS，浏览器也只允许连接测试中的 Mio。没有真实账号、付费 API、真实 GPU 或画质验证。

配置、只读连接检查、获取模型、保存密钥、入队，以及取消费用确认，均没有生成端点请求。这里的请求数只是受控协议测试证据，不代表真实服务兼容性结论。

## 发现与直接修复

1. **首页没有按已有工具分流的清楚起点。** 新增三条可收起、可重新展开的渠道入口，保持原有深色视觉；明确 Mio 不提供账号、模型或额度。
2. **ComfyUI 配置页缺少直接可用的地址/检查链路。** 补充后端电脑视角的地址输入、只读检查、API 工作流导入入口与画布 JSON 提示。检查不探测 GPU、工作流或出图能力；顶栏改为“后端按需连接”，不再用旧浏览器直连状态误报“待连接”。
3. **NovelAI 权重与变量插值冲突。** 已定义变量仍替换，图像提示词中未知花括号保留；台词及其他渠道仍严格校验。官方服务无密钥时前置提示。
4. **获取到模型却可能看不到。** 获取后先展示全量返回结果，不再被默认 `gpt-image-1` 搜索词过滤。没有候选项时不打开遮挡按钮的空下拉层；404 可继续手填，错误信息指出下一步。
5. **写完分镜不知道去哪里生成。** 增加“保存并编写分镜”“去装配此分镜”；新分镜和新增分幕从空白开始，不悄悄植入演示变量。选中的渠道自动带入装配。
6. **错误通常到开始后才暴露。** 装配最终页增加幕数、空提示词、缺失变量和 NovelAI 尺寸检查；不执行脚本，不试跑模型。明确入队/生成的费用边界。
7. **改地址后还显示旧密钥已选。** 清除旧引用并提示重新绑定，密钥本身仍留在原地址作用域。不会把旧密钥自动用于新地址。
8. **换密钥后马上重试可能仍用旧配置。** 实测出现“第二次请求先于配置落盘”；现在保存/选择密钥等待渠道引用确认落盘，再允许关闭成功状态。纠正密钥不会自动重发。
9. **旧提示与实际快照行为矛盾。** 更新渠道文案、内置引导、快速开始和密钥文档。模型、地址、工作流和参数在装配时冻结；鉴权引用可以在同一渠道下纠正，不承诺所有凭证冻结。

首次使用测试默认输出到被 Git 忽略的 `docs/acceptance-first-use/`；可用 `MIO_JOURNEY_EVIDENCE` 指定证据目录。`*-wire.json` 记录方法、路径、虚构测试请求体及是否有鉴权，不记录密钥原文。测试正常结束会停止服务并删除隔离数据。

## 使用与升级

新用户：选渠道 → 配置并保存 → 新建一幕 → 去装配 → 检查后入队 → 费用确认后开始。

已有用户：先停止服务并备份整个个人数据目录，再更新代码；不要用发行默认数据覆盖个人 `data/`。更改模型或地址后重新装配，密钥失败则在同一渠道手动纠正后再次确认。结果未确认时先查上游，避免重复付费请求。
