# Mio 2.3.0 · 完整画面，明确归属

2026-09-14 · 完整源码运行包，含 59 份独立的随包内容文件；不是覆盖补丁。

## 桌面阅读不再只做等宽或限高

「留白 · 完整画面」与「无缝 · 纯图阅读」共用新的自适应阅读几何：

- 桌面足够宽时，相邻的合适竖图组成双页；横图、方图和小图独立展示。
- 一个阅读单元占据一个视口。滚动吸附与上一页/下一页按阅读单元前进，停稳后不会露出下一张图的边缘。
- 单张竖图与小图通过当前画面的柔色背景承接两侧；原图完整、不裁切、不拉伸，小图不超过原始像素尺寸。
- 阅读底部可切换「自适应 / 单页 / 连续」。手机与窄窗口仍连续阅读；无缝模板的连续模式保持纯图、零间距。
- 默认原生阅读器保留懒加载，不为翻页或开关模板抽屉重编整册。模板预览与离线 HTML 注入同一份阅读运行时和独立 CSS。
- AFTERGLOW 和其他艺术模板不改排版；无缝模板不删除源台词，也不新增配文区、页码或结尾落款。

## 提示词、变量和参考图是同一套保存输入

右上角「当前画册」明确区分草稿与具体画册版本。主设定区与分镜区使用同一个归属：

1. 在本册修改文字变量或替换参考图。
2. 等待「已保存」——自动保存即可，不需要重新应用预设或放弃整册任务。
3. 尚未发送的分镜读取这本画册最新保存的提示词、变量与参考图。单幕覆盖仍优先。

已发送请求持有独立输入证据；后续编辑不会改变其参数或已完成图片。若在准备图片期间发生保存，正式生成提交前会重新核对；未发送的旧准备被释放，重新读取新输入，不记为一次请求或失败。已确认结果与未知结果保护不变。

保存冲突、磁盘错误、无效 JSON 或缺失图片不会悄悄回退旧设定后继续声称成功。保存失败时磁盘仍是上次确认内容；正在运行的队列可能继续使用该已保存版本，请检查保存状态，必要时暂停队列。重试与重启后的未发送分镜同样从本册读取；浏览器关闭后不依赖网页刷新变量。

渠道身份和工作流归属不会因为换参考图而改变；关联渠道的模型、地址和密钥绑定继续按原有规则读取。外部 API 的较新手工提示词修订不会被一次纯变量修改倒退覆盖；参考槽位顺序发生冲突时明确阻止发送，需在分镜区确认并保存文字。

## 本册编辑与公共预设库分开

主区只编辑当前画册，标题、归属和保存状态可直接看到。原先放在底部、会暗中切换编辑对象的预设选择器已移走。

点击「预设库」进入独立对话框：

| 操作 | 影响 |
| --- | --- |
| 编辑预设草稿 | 只修改该预设的私有草稿；切换、正常保存和重载保留 |
| 更新此预设 | 只更新该公共库文件；已应用的画册不联动 |
| 应用到当前画册 | 一次确认后复制到明确显示的目标；保存后供其未发送分镜读取 |
| 另存为 | 创建新 ID，不覆盖原预设；从本册另存后主区仍属于本册 |
| 删除预设 | 一次确认；保留正在使用的独立值与参考图，不删除画册 |

同名画册与同名预设可以共存，不再依靠名称后缀判断归属。不同画册版本保存自己的设定，不把当前全局计划的最新值套给所有旧任务。现有预设文件、尚未应用的私有草稿、图片与单幕覆盖保留。

## 升级

保存并停止旧服务，将新版完整解压到新程序目录，使用原来的 `MIO_DATA_DIR` 启动。**不要把新版随包 `data/` 覆盖到原数据目录，也不要删除 `runtime/execution/jobs.sqlite3`。** 已存在的工作区不重装内置模板、不恢复已删除示例；本次阅读行为由程序运行时提供。需要新版可编辑模板文件时可手动导入随包资源，创建独立副本。

如果此前没有手动设置 `MIO_DATA_DIR`，原数据通常在 **旧程序目录的 `data/`**。直接启动新版的默认数据目录会显示新的工作区，不代表旧画册或预设丢失。请先确认路径，再清理旧程序。

Windows 命令提示符示例（在新版程序目录执行，替换实际路径）：

```bat
set "MIO_DATA_DIR=D:\旧版Mio\data"
start.bat
```

macOS / Linux 示例（在新版程序目录执行）：

```bash
MIO_DATA_DIR="/原程序路径/data" ./start.sh
```

启动后确认左下角 / 底栏显示 **2.3.0**，并核对原有画册、预设和任务仍在。不要通过删除运行数据库来让界面“变干净”。

旧任务没有记录显式变量来源时，从入队的本册作用域及各幕差异恢复；能够与原值对应的显式单幕覆盖也保留，不擅自采用后来编辑的公共计划。极早快照无法证明的“与全局完全同值的单幕覆盖”按继承处理，可在该幕重新明确设置。
