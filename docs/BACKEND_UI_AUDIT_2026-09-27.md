## 2. 已修复的问题

### 工坊、装配与字幕

| 问题 | 修复与覆盖 |
|---|---|
| 首次多个请求同时打开工坊，创建多个隐藏作品 | 将检查、创建和播种放在存储的可重入锁中；并发回归验证 6 个调用只得到一个工坊 |
| 装配后画布宽度、背景、竖排等设置丢失 | 深拷贝分镜的 Strip，同时保留作品变体快照；不复制试出图候选 |
| 空分镜、已删除的出图配置仍能装配成无效队列卡片 | 在创建画册前校验，返回明确的 400 / 404，避免留下无用作品 |
| 预设变量只替换提示词，没有替换台词 | 画册字幕与自动气泡共用变量展开规则；支持嵌套、每格覆盖和字面花括号，未知变量保留，不改写原分镜 |
| 工坊测试依赖本机全部旧数据 | 改为只复制随包清单中的演示资料到临时目录 |

涉及：`server/mio_server/workshop.py`、`album/build.py`、`pipeline/strip.py` 及对应测试。

### 出图链路与候选采用

| 问题 | 修复与覆盖 |
|---|---|
| 云端定形忽略原始提示词和预设展开结果 | 将编译并冻结的提示词交给实际云端请求，不再重新用结构化分镜覆盖 |
| 聊天出图始终优先使用内置模型，而非配置的图像模型 | 云端渲染器读取配置模型；每个付费尝试只选择一个模型 |
| 云端忽略候选数量和批量变体 | 按候选和变体生成请求，保存对应 `variant_id`、种子与候选序号；补幂等请求测试 |
| 经典队列的 `adopt_first` 未接入云端 / 混合路径 | 纯云端自动采用；混合模式等本地精修完成再采用，避免中间图误报完成 |
| 分格或变体覆盖混用了本地与云端配置时被静默忽略 | 明确拒绝不支持的混合批次，提示分批提交，不再悄悄用错模式 |
| 成品任务完成时覆盖用户后来手动采用的新图 | 仅当父候选仍是当前采用图时才替换；保护后到的手动选择 |
| NovelAI 未填写模型时默认走 4.5，却组装了 V3 参数 | 默认模型的版本判定与实际请求模型一致，发送 V4 正负提示词结构 |

涉及：`pipeline/render.py`、`render_edits.py`、`cloud.py`、`cloud_jobs.py`、`providers.py`、`llm.py`。

### 云端请求安全

- **模糊失败不隐式重发：** 任务路径禁用适配器内部重试和自动切换模型；多参考图请求只有明确的格式拒绝才允许尝试拼图降级，超时、5xx 等不确定结果直接交回任务引擎处理。
- **保留送达证据：** 不再凭错误文本里是否含“连”字判断请求没有发出。明确未发送的连接失败和已经生成、但下载失败的情况分别记录。
- **阻止跨源凭据泄漏：** 下载服务商返回的第三方 CDN 图像时，不携带 API 源的 Authorization / Cookie。
- **下载失败不重复生成：** 图片已经生成后，即使 CDN 返回 503，也不重新 POST 生成请求。

以上全部使用本地替身和模拟 HTTP 响应测试，没有读取真实密钥或调用付费服务。

### API 与配置表单

- 将工坊 `GET /workshop`、`POST /workshop/assemble` 补入 `/api/v2`，分别受 `read` / `write` 权限控制；装配本身不要求 `render`，因为不会调用模型。
- 同步 `clients/openapi-v2.json`、Python 和 AstrBot 客户端。
- 修复出图配置编辑器新增阶段多发 `order: []` 的问题：后端模型严格拒绝这个字段，原来会导致保存失败。移除多余字段及掩盖类型错误的强制断言，并增加实际保存请求的前端测试。
- 修正文档中客户端依赖、读取权限以及公开发现端点的说明；增加工坊装配示例。

前端只做接口衔接所需的最小修改，没有接管布局重做，也没有回滚其他 agent 的阅读器改动。

## 3. 教程调整

新版手册：**`http://127.0.0.1:8788/manual/`**（后端重启后生效）。

源码：

- `server/mio_server/manual/index.html`：中文手册。
- `server/mio_server/manual/en.html`：英文手册。
- `server/mio_server/manual/flow.svg`：明确标注为流程示意，而非界面截图。

调整内容：

1. **不再把旧版 3.2 手册作为新版默认教程。** 新版外观虽然复刻旧版，但端口、启动方式、数据目录和出图链路不同。
2. **手册随 server 发布。** 原方案依赖 `legacy/docs` 和旧版 vendor 脚本，而新版发布 ZIP 不包含这些目录，导致发布后教程 404。现在是独立静态页面，无外网脚本依赖。
3. **兼容当前帮助抽屉里的旧链接。** 快速开始、工作流、变量、任务、导出、备份、文件、移动访问等链接，重定向到相应的新章节；测试检查中英锚点有效。
4. **补 Vite 的 `/manual` 代理。** 开发界面也能打开后端手册。
5. **删除过时操作承诺。** 不再指导使用旧端口 / `python server.py`、不存在的离线练习按钮、一键种子修复或旧文件库入口。
6. **说明容易被误认为“按钮没用”的行为。** 导入工作流不等于切换出图配置；添加云端渠道不等于启用云端出图；修改模板不追改已装配画册；重跑已有分幕通常新增候选，需要采用才能改变阅读图。
7. **更新备份与分享边界。** 图片 ZIP 不等于 `.mio.zip` 作品包，作品包不等于完整服务备份；隐藏提示词不等于完全清理隐私；无损归档不适合直接公开分享。

旧版资料仍留在 `legacy/`，没有删除，以免影响旧版用户和其他代理。

## 4. 尚未宣称完成的范围

- 没有启动真实 ComfyUI、加载个人 LoRA 或向云端发送出图请求，因此不宣称真实模型、显存、速度和生成质量已经验收。
- 前端 150 项是 Vitest / jsdom 测试，不是全部按钮的真实浏览器 E2E。视觉和复杂交互继续由前端代理处理。
- 云端的高级负向 / 尺寸等参数仍需按渠道能力核对，不能把 ComfyUI 每格参数语义直接等同于所有云端 API；本轮没有扩张第三方适配器参数协议。
- 开箱检查中“存在工作流 / ComfyUI 在线”不等于具体 Checkpoint、节点或云端配置可用。这类前端判定需要继续优化；新版教程已经明确提示先做一幕实测。
- 旧文件库、市场、可执行变量、用户脚本和离线练习等能力不能因为恢复了外观就视为全部迁移完成。
- 本轮不会重写已有画册来追补过去丢失的设置；如需采用改过的模板或画布配置，应从分镜重新装配，保留旧作品用于对照。

## 5. 生效与协作说明

1. 等活动任务结束，再正常停止当前 Mio 后端。
2. 在项目根目录重新运行 `start.bat`；开发模式如果使用 Vite，也需在代理配置变化后重启 Vite。
3. 刷新浏览器，打开 `/manual/`，确认看到标注 **4.x / 8788 / 新版使用手册** 的页面。
4. 先用一个中性分幕、一个候选验收实际服务，再跑长任务。

**没有擅自停止或重启现有的 8788 服务，没有改写用户作品、数据库、密钥或旧资料。** 临时测试数据与临时发布 ZIP 均由测试清理。只在项目虚拟环境补装了已声明的开发依赖 Ruff。
