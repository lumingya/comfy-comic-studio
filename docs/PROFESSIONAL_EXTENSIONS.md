# 六项专业工具，按需装进作品

日常创作仍走分镜、生成、挑图、排版和导出。下面六个工具是独立扩展包：安装、审阅摘要并启用后，在具体话的「扩展」菜单选择工具；不会在主导航增加六个固定入口。

| 工具与独立包                                                                     | 怎样使用                                                       | 写入与采用行为                                                           | 业务权限            |
| -------------------------------------------------------------------------------- | -------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------- |
| [单格精修](../extensions/panel-retouch/README.md) `panel-retouch`       | 选候选，画矩形或多边形蒙版、填写外扩像素或修改指令，再明确提交 | 新图成为候选并保留原图；不替换已采用图                                   | read、render、write |
| [智能质检](../extensions/qa-review/README.md) `qa-review`               | 勾选候选后提交 VLM 评审，逐幕查看评分、问题和位置              | 固定 `auto_adopt:false`；不自动采用或淘汰，缺失评分不当满分              | read、render、write |
| [成品精修](../extensions/finalize-studio/README.md) `finalize-studio`   | 选择已采用草稿，核对现有成品阶段和参数，确认后批量执行         | 成品完成时接替仍被采用的原草稿；原图保留。期间已换图时不覆盖新的选择     | read、render、write |
| [批量变体](../extensions/variant-workshop/README.md) `variant-workshop` | 用设定集的画风和角色外观派生版本，明确生成、对比、采用与导出   | 保存派生版本不出图；生成不自动采用；采用仅作用于该分幕、该版本           | read、write、render |
| [剧本助手](../extensions/script-assistant/README.md) `script-assistant` | 生成结构化提案，按分幕、字段和逐句对白审阅，再勾选应用         | 默认不接受任何修改；锁定项不能选择，旧修订提案不能覆盖新稿               | read、render、write |
| [动态漫](../extensions/motion-studio/README.md) `motion-studio`         | 调整镜头运动与时长，保存后导出离线播放器                       | 修改默认版本的镜头设置，不生成图片、不更换采用图；语音取决于本机可用声音 | read、write         |

权限列指开放 API 的实际操作权限；面板桥入口还需要 `read`。远程安装、启停和卸载需要 `admin`。本机界面沿用本机同源保护，不要求把令牌交给面板。

## 从安装到退出

1. 在「扩展市场 / 已安装」导入对应目录或 ZIP，先审阅来源与文件摘要，再启用。ZIP 应包含包自己的清单、页面、脚本和资源，打包命令见各包 README。
2. 打开具体的一话，在「挑图 / 分镜」旁的「扩展」菜单选择工具，进入独立工具页。安装、启用和打开面板都不提交生成任务；先点击读取，再选择对象和操作。
3. 精修、成品、变体生成以及 VLM／文本模型调用都需要已配置的服务，可能消耗额度。蒙版、配置和提示词应在提交前检查；停用的本地编辑阶段不能绕道运行。
4. 使用任务 ID 或包内进度控件跟踪工作。网络超时不等于未提交；先核对已有任务，再决定是否按原幂等键重试，工具不会静默重发生成。
5. 停用会撤下入口并撤销后续面板请求，重新启用后从菜单重新打开工具。已提交的核心任务仍归队列管理；需要停止时应明确取消。卸载不删除作品中已保存的候选、评审、版本、镜头或已接受修改。

成品精修的自动接替是原有 `/finalize` 语义，面板在提交前要求确认；它与单格精修新增候选的行为不同。不要把两者的结果采用方式混用。

## 图片、导出与并发编辑

六包都只声明自己需要的正式 `panels.requests`，没有 Python 激活入口或 `ctx.internal`。沙箱保留 `sandbox="allow-scripts"` 和 `connect-src 'none'`，不能自行带令牌联网。

需要原图的面板通过 `response:"image"` 读取受验图片。宿主以 MessagePort 交付 Blob，面板在自己的隔离来源中创建临时 URL；换图、关闭或撤销会释放 URL、端口与媒体额度。下载使用 `response:"download"`，准备好文件后由宿主提供真正的下载按钮，必须再点击保存。完整限制见[图片与下载桥](EXTENSION_MEDIA_BRIDGE.md)。

变体工坊每次只把本轮新增版本追加到原生作品，服务端在锁内合并：同 ID、同内容重试不重复，内容冲突返回 409，整批不写入。它不把读取时的旧版本清单整表覆盖回去。剧本审阅和动态漫保存携带修订号；遇到冲突或不确定写入应先重新读取核对，不自动覆盖另一窗口的修改。

## 通用适配与脚本入口

| 需要做的事                   | 入口                                                                                                               | 验证边界                                                                             |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| 接入复杂 ComfyUI 工作流      | [参考适配器包](../examples/extensions/comfy-complex-adapters/README.md)、[30 分钟开发指南](COMFY_ADAPTER_GUIDE.md) | 已声明的 LoRA、多阶段采样、参考图与 history 输出形态；不等于任意节点或真实模型已验证 |
| 接入云端图像渠道             | [标准图像渠道包](../examples/extensions/standard-image-channels/README.md)                                         | 四种明确线协议、发送状态、有限轮询、同源下载与脱敏；离线模拟不是服务商认证           |
| 用 Markdown 完成生成与导出   | [通用 CLI 与 Webhook 工具](../clients/python/AUTOMATION.md)                                                        | 同一 API v2／SDK，显式采用开关、幂等续跑、Monograph HTML 与 PDF；令牌只放环境变量    |
| 增加宿主入口与只读创作上下文 | [声明式槽位契约](CREATION_EXTENSION_SLOTS.md)                                                                      | 限定槽位打开本包面板，事件只传 ID 与修订；不是任意脚本或跨扩展业务总线               |

标准渠道使用 `extra_options` 保存普通参数，凭据使用宿主已有密钥字段；生成 POST 不在适配器内重复发送。异步轮询和安全 GET 重试不等于再次提交生成。`cloud_adapter` v1 没有逐任务取消回调，不承诺远端任务取消或跨进程恢复轮询。

## 如何检查包

从仓库根目录检查一个包，例如：

```bash
python tools/check_extension_package.py examples/extensions/panel-retouch
```

六包各自 README 列出离线回归与使用限制；媒体桥、版本追加及修订冲突还有独立测试。静态 CTK 通过仅说明包结构符合静态契约，不代表代码可信、真实模型效果、所有浏览器或最终全链路验收已经完成。实际验收由[路线图](ROADMAP.md)和本轮最终报告单独记录。
