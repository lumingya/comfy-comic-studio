# 队列、分镜并发、失败处理与画册管理

## 并发是每任务的分镜数量，不是画册数量

在队列页「并发与超时」中填写并保存：

| 设置 | 范围 / 默认值 | 作用 |
| --- | --- | --- |
| 每任务并行分镜数 | 1–16，默认 1 | 每个已启用任务独享的在途请求上限 |
| 生成 / 下载等待超时 | 30–7200 秒，默认 600 秒 | 下一次请求使用该值，已发出的请求继续使用原值 |

例如一个 20 幕任务设置 **4**：先请求第 **1、2、3、4** 幕。第 3 幕先返回，就立即请求第 5 幕，即使第 1、2、4 幕还在等待；随后任何一幕结束都会释放自己的槽位。**不按四幕一批等待，不按返回顺序阻塞**。只要还有可调度的分镜，就持续补位到上限；最后不足四幕则只请求剩余内容。供应商限流、暂停、重试计时或机器资源可能使实际在途数低于上限。

### 默认顺序执行；明确操作才增加第二个池

- 任务默认按队列顺序逐个执行。可拖动未开始的待办，也可上移/下移。
- 想让另一个任务同时执行，点其 **并行启动此任务**。确认框说明新增池、总请求上限和费用风险。
- **两个任务各设 4，就可同时有 8 个请求**，不是两个任务争用四个槽位。
- 提高并发数字或批量恢复普通暂存任务，不会自动并行启动所有画册。之前已经明确启用的池保留身份。
- 最多启用 32 个任务池；这是任务池准入限制，不是共享 32 请求限制。任务结束、停止，或暂停后在途请求全部收尾时，自动释放池并让下一本继续；不再需要额外的放行按钮。
- 同一画册不能同时启用两个服务端任务；有该画册未确认结果时先核对，避免重复绘制。

设置持久保存在 SQLite，刷新和重启不丢失。每个池使用当前保存的分镜上限；降低上限不强行中断在途请求，降到新上限以下后再补位。已有保存的失败策略不被强制重置，请在队列页核对当前选项。

OpenAI/NovelAI 的超时限制网络连接/读取等待，不是整幕或整册严格总时长；生成响应与每次图片下载分别使用该值。ComfyUI 上传、提交、查询、下载共用倒计时预算，并用剩余时间限制各次请求；缓慢持续读取仍可能超过预算。同步精修和直接同步 API 不属于此队列配置。

## 失败默认不挡其他分镜，可选只暂停本任务

在队列页展开 **失败处理策略**。配置在服务端共享，但失败的作用范围是该任务，不是整个服务。

| 策略 | 行为 |
| --- | --- |
| 保留失败，继续其余分镜（关闭自动重试） | 记录失败或未知幕，释放槽位继续本任务未请求的其他幕；不把失败幕当成功，不自动重发未知幕 |
| 失败时暂停本任务 | 不再为该任务补发；已经在途的其他幕继续返回并保存，其他已启动任务仍正常执行 |
| 自动重试（新安装默认） | 所有明确 HTTP 500–599，每幕可配置额外 1–100 次，默认 5 次、间隔 15 秒；耗尽后默认继续其余分镜，也可暂停本任务 |

修改自动重试配置需确认可能额外计费。旧安装保留已保存策略，不会静默改为自动重试。2 次代表首次加最多 2 次额外尝试。重试计时按幕独立，不占请求槽，其他可调度分镜可以先执行。改回暂停/继续策略会撤销未发起的自动重试，不中断当前请求。

**所有 4xx（含 429）不自动重试。422 留下逐幕「已跳过 · 422」标记，即使暂停策略也继续后续分镜。手动继续不受累计次数限制，每次重新获得自动重试额度；已完成图片不重画。建议先在原分镜编辑器修改被拒绝内容。**

**没有明确 HTTP 状态的超时、断线、服务中断等未知结果本身永不自动重试。** 默认仍可生成同任务的其他幕；需要重发未知幕时必须人工确认。服务重启发现未结束请求时会保护性暂停调度，保留已确认索引，把中断幕标为未知，先核对再恢复。

401、参数错误、无图片等留待人工处理。外层 502 不一定是临时故障：正文明确内容拒绝、内容策略或嵌套拒绝状态时不会自动重试。不是规避审核工具，也不能保证修改后通过供应商审核。

## 乱序完成如何保留与继续

例如第 2、4 幕已完成，第 1 幕失败、第 3 幕未知：

1. 保留原任务和画册。进度显示 **2 幕已确认**，不代表前两幕完成。状态展开区分别标出每幕结果及正在请求的幕号。
2. 核对上游记录。ComfyUI 已有 prompt ID 时优先 **查询 ComfyUI 已有结果**，仅读取历史和下载，不重新提交。
3. 等本任务在途请求结束，或先立即停止；需要时调大等待超时并保存。
4. 点击 **继续未完成分镜**。对话框重新读取进度，列出真实未完成幕号（含子集任务原幕号）、已确认数量及未知费用风险。
5. 明确确认后，沿用同一任务、画册、输入版本，只恢复未完成的幕。**第 2、4 幕不会被重画**，也不会因为前面有空洞就丢失后面的成功图。
6. 未知幕可能仍在上游执行或已扣费，人工重发可能重复计费；取消确认则不发新请求。进度在确认期间改变会返回冲突，刷新后重看，不盲目执行过期确认。

画册的「补齐 / 继续」也优先复用可恢复的原任务。共享模板不改写本册分镜；关联渠道修改从下一次请求生效。尚未生成的分镜保持空白/问号，不用示范图冒充。

**保留此任务，继续其他画册**：不重发当前失败/暂留任务；无在途请求后释放它的顺序占位，让其他待办执行。**全局暂停**则停止所有池的后续补位，但当前请求继续保存。两者不同。

## 立即停止与修订提示词

- **立即停止**立即结束本地任务，使每幕的旧批次失效并关闭已建立的本地连接；所有已确认图片保留，之后的未确认返回不采纳。
- 停止一个池不停止其他池。DNS、建连或 TLS 可能在底层收尾，本地无需等它们返回。不能保证上游停止、取消收费或退款。
- 不再提供独立的任务提示词编辑弹窗。直接使用 **创作画册 → 分镜故事** 的原编辑区；上方「修改范围」选择具体画册版本。进入有未完成任务的计划时默认选中该任务；多个版本可在同一个选择器里切换。
- 该版本使用自己的分镜列表，不按已变更的共享模板位置猜测。任务结束后不会悄悄跳到更早任务。已入队任务不在这里增删、排序分镜；新结构应生成新版本。
- 修改提示词、负向词、旁白或本幕渲染字段并等待 **Python 已确认保存**。服务端每次发送前读取该画册最新保存输入，关闭网页仍生效；未保存的字不会被读到。
- 正在排队或运行的任务无需额外“应用修改”；后续请求自然读取新值。在途请求不变，完成图不重画；失败、停止或未知幕仍通过原有继续确认恢复。编辑不会自动暂停重试计时，必要时先全局暂停或暂留。
- 渠道 ID 不变，但模型、地址、参数和密钥绑定每次读取该渠道最新保存配置；工作流结构和变量绑定沿用本册版本；提示词里的变量按该版本已保存的作用域展开。ComfyUI 通过原有映射编译，不在运行中替换公共工作流。共享模板修改不影响已入队任务。
- 变量无效或图片绑定不完整时，记录输入错误，不偷偷回退到旧提示词付费生成。每次准备发送的提示词、参数、图片引用及完整输入摘要都记录在任务历史；它不是上游已接受或已扣费的证明。
- 当前脱敏原始错误可展开；完整任务详情含最近 30 条错误历史，每条历史摘要最多 16,384 字符。

## 添加、检查与删除

- **加入并执行**新建独立画册版本并进入顺序队列；全局暂停时显示“加入待办”，不会偷偷解除暂停。
- **检查当前队列 / 查找缺失分镜**只检查现有任务范围，不扫描无关画册，不创建或启动新任务。
- **删除任务及对应画册**需确认，移除同册全部关联队列记录，不删除模板、角色或设定；磁盘图片按引用和保护期另行安全回收。
- 有在途请求时先停止；未确认结果先核对或明确放弃跟踪，不能直接删除后盲目重复生成。
- 运行卡片动态高亮并列出正在请求的分镜；展开可查看各幕状态。系统减少动画时保留静态强调。进度仅统计确认图片，不虚构供应商百分比。

## 鼠标滑选与 Esc

1. 在画册集点击**批量选择与管理**。多本画册时推荐使用**紧凑网格**。
2. 按住鼠标左键，从未选画册或网格空白处拖动：**沿路径经过的画册**自动选中，不是矩形框内全部选中。
3. 从已选画册开始拖动则沿途取消选择。同一次拖动重复经过同一本不会反复翻转。
4. 靠近窗口上/下缘可自动滚动继续选择当前页已展示的画册；分页不会自动翻页。也可使用“全部选择”。
5. **Esc 清空选择并退出多选**，包括正在拖动时。正在打开的确认弹窗优先处理自身的 Esc，不越过确认流程。

普通模式的拖动仍是排序；多选模式拖动才是滑选。Ctrl/⌘ 点击和 Shift 连选仍可用。手机手指滑动保留滚动行为，通过复选框多选，不会因为浏览画册而误选。

首页提供醒目的“使用教程 · 从这里开始”，图像引擎的就近入口仍保留。

## 日志与修改历史

运行日志读取服务端 SQLite 持久事件：入队、开始请求、已确认进度、失败正文摘要、自动重试、暂停/恢复、立即停止、迟到结果丢弃、读取本次输入、并发和超时设置。刷新页面可恢复最近 200 条服务记录；连续使用最多显示 1000 条，按时间/关键词查看和复制。旧版本已经执行、却没有保存详细日志的请求不会编造补齐。当前完整错误仍在任务详情。

「服务端任务 → 查看结果 / 原始错误」显示最近 100 次实际请求输入；任务详情 API 的 `requestHistory` 提供索引、尝试号、时间、提示词、参数和摘要。外部 amend 操作仍在 `revisions` 中保留修改前后记录。原幂等键保留，已确认图片不受修订影响。

停止会尽快关闭已建立的本地 HTTP(S) 连接。DNS、建连或 TLS 协商等阶段可能仍在底层收尾；本地任务无需等待它们，返回数据不会被采用。请求批次号隔离防止旧响应污染继续后的任务。停止不能证明供应商已经停止或不计费。

## 实际请求日志

摘要区分「第几幕」「本幕第几次尝试」「自动重试次数」和「已完成数量」。准备新请求不会附带上次错误。展开可查看本次准备发送的提示词、负向词、模型、参数与图片引用；不暴露密钥或密钥绑定。准备记录不证明上游已受理或计费。任务详情保留逐幕错误和实际请求历史，移除无用的初始输入清单。

最终请求体在适配器完成参数构造后单独记录为 `requestParameters`，包括实际模型、合成提示词及 NovelAI 已确定的随机种子；不修改初始输入哈希或 ComfyUI 核对快照。图片二进制、URL、密钥字段与鉴权头不会记录；图片顺序见输入引用。尚未进入适配器发送阶段的失败只有准备输入，没有伪造的最终请求体。最终参数记录仍不证明上游受理。
