## 高频操作怎么改

画册网格从空白处拖动会框选；封面拖过 6 像素才开始排序。短按会打开画册，批量管理时则切换勾选；Esc 清除选中并退出批量管理。分镜与任务列表共享 Esc 的处理规则，并保留触控手柄。

新建生成任务时，第二步可以从眼睛图标查看预设变量，也可以查看合并后哪份预设的值生效。第三步只展开当前一幕；方向键可以沿标签移动，问题可筛选，临时补值重新核对后更新计数。概念帮助留在原入口旁，可以从浮层直达中英文离线教程。

动态壁纸默认在窗口失焦或被阅读室、画布盖住时停播。可在外观设置固定静帧，系统减少动态效果也能停播。静置时取消装饰性的循环动画，空队列改为等待事件唤醒。

## 改前、改后实测

同一台 Windows 本机的 Chrome、1440×900 视口。测试用 720p、30 fps 合成壁纸；每个状态采样约 2.2 秒。下面的 Chrome 任务时间来自 DevTools `Performance.getMetrics`，表示被测渲染进程的主线程时间，不等同整机 CPU、电量或 GPU 时间。

| 壁纸状态 | 视频帧数：改前 → 改后 | Chrome 任务时间：改前 → 改后 |
| --- | ---: | ---: |
| 画册集前景 | 68 → 66 | 448.3 → 105.9 ms |
| 打开命令面板 | 67 → 67 | 607.1 → 5.4 ms |
| 窗口真实失焦，标签页仍显示 | 66 → 0 | 484.1 → 1.5 ms |
| 阅读室遮挡 | 68 → 0 | 522.4 → 90.3 ms |
| 条漫画布遮挡 | 63 → 0 | 519.7 → 1.3 ms |

关掉阅读室或切回窗口后恢复播放。静帧与系统减少动态效果都实测为 0 帧；命令面板遮罩从 `blur(2px)` 变成无实时模糊。静置前景活跃循环从 1 降到 0；独立 CSS 对照的 9 个装饰动画也全部停下。任务引擎空载连续三次采样，每 6 秒调度查询由 29 次降到 0 次，装配队列读、写各由 1 次降到 0 次。

相同长篇合成样本各跑 3 次，表内为中位数。每次用鼠标连续滚动 18 次，分镜另外跳到第 28、45、59 幕。超过 25 ms 的帧间隔是本次卡顿信号，不能替代设备实际掉帧计数。

| 区域 | p95 帧间隔 ms | >25 ms 帧间隔占比 | >50 ms 长任务 | JS 堆 MB | Chrome 任务时间 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 50 册画册网格 | 8.3 → 4.4 | 0.4% → 0% | 0 → 0 | 16.7 → 14.4 | 374.9 → 274.9 |
| 60 幕分镜列表 | 4.4 → 8.1 | 0% → 0% | 0 → 0 | 15.3 → 21.2 | 244.7 → 211.9 |
| 120 幕条漫画布 | 8.2 → 4.4 | 0% → 0% | 0 → 0 | 17.8 → 16.0 | 51.6 → 119.7 |

画布的绘图表面从 480×24,494 降至 480×705；画布滚动会更新可见节点，脚本及主线程任务时间因此有增加，静置无须继续刷新。分镜减少了从 51 次到 1 次的各画册分话列表请求，但本次的堆占用和 p95 帧间隔没有下降。初次进入画册网格的分话列表请求从 50 次降到 0 次。以上数据不能据以承诺所有机器或自定义主题达到同样表现。

## 验收记录

- 真实 Chrome 使用鼠标按下、移动和松开验证封面、分镜和任务标题直拖；使用键盘验证分幕与浮层焦点、Esc 逐层退出、取消任务拖动、命令面板导航和画册多选。阅读分话失败只显示错误，重试后恢复画面。窄屏在 120 幕画布尾段缩放时原视野中心保持不变；45 个 LoRA 可按名称定位，390 px 窗口的单行宽度为 244 px，没有内容溢出。
- 外观用浅色、深色、注入合成壁纸三种样式，在 1440×900 和 390×844 下执行 66 项页面布局检查，并对基线与新版的 120 个视图采样前景文字与纯色底对比。对照脚本只计算有明确背景色的有效样本，不代表对任意壁纸像素和自定义主题的遍历认证。
- 本机前端 918 项、Spike 80 项、AI 辅助扩展 34 项、6 组离线扩展面板、19 个扩展与主题静态校验均通过。前端类型、格式、构建，生成客户端零差异，文档断链及干净检出中 64 个随包文件与发行包冒烟通过。
- 本机后端全量首次执行有两项临时目录 `git init` 失败，独立重跑所属模块 6 项通过。Ubuntu Python 3.11 首轮远端还复现长篇测试夹具与更新检查线程竞争；已禁用该夹具启动时的联网检查，相关 23 项通过。最终跨平台结论以当前提交的 [CI](https://github.com/lumingya/comfy-comic-studio/actions/workflows/ci.yml) 为准。
