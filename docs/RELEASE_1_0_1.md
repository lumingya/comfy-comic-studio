# Mio 1.0.1 — 流程修复与升级说明

2026-09-12 · 本地维护构建，不代表上游官方发布。基于 GitHub `lumingya/comfy-comic-studio` 的 `0b63298`。

## 下载包与启动

这是完整源码运行包，不是补丁。前端仍使用独立 `styles.css` 和 `js/*.js`，本地 vendor 已包含，不需 Node.js、npm 或联网安装运行依赖。

需要 **Python 3.10 或以上**：

- Windows：解压后双击 `start.bat`，或在项目目录运行 `python server.py`。
- macOS / Linux：在项目目录运行 `sh start.sh`，或 `python3 server.py`。
- 浏览器打开终端打印的地址，默认 `http://127.0.0.1:8777`。端口以启动日志为准；可以设置 `MIO_PORT`。
- 不要双击 `index.html` 代替启动服务。生成、保存与删除需要本地服务。

本包**不含 Windows exe**；未在 Linux 上冒充构建或验收 Windows 可执行文件。

## 保留 data/ 的升级步骤

1. 关闭旧版网页和 Mio 服务。若仍有上游请求，关服务也不能保证取消请求或计费。
2. 备份旧项目的完整 `data/`；旧版另有 `images/`、六个旧式 JSON 或 `comfy_comic_data.json` 时也一起备份。
3. 将本包解压到**新目录**，把备份的 `data/` 完整复制到新目录。不覆盖、不清空、不只挑选几份 JSON；旧版 `images/` 等也按原位置复制。
4. 使用新目录中的 `start.bat` / `start.sh` 启动，强制刷新浏览器。核对画册、渠道、原图和保存状态，再继续工作。
5. 保留旧目录作为备份，但不要同时运行两份服务或在两个目录交替编辑同一份工程。

新包不附带 `data/`，因此解压本包不会用测试数据覆盖你的画册。首次运行会沿用项目原有的新用户示例与配置流程。

**务必保留 `data/execution/jobs.sqlite3`。** 里面既有幂等请求记录，也有删除标记。删除它、只还原旧 JSON 或降级后继续使用旧数据库，均不在本版防重复／防复活保证范围内。若需要回退，关闭服务并恢复升级前的完整备份，而不是混合新旧数据。

## 本次实际改动

### 删除不再是任务恢复流程

- 删除画册及全部关联队列记录只确认一次；生成中直接显示“停止并删除”。失败、超时、已停止、结果不明均不阻塞删除。
- 没有“放弃跟踪”二次确认，不需先去供应商核对。
- 服务端按画册 ID 查找所有关联任务，不依赖浏览器是否已保存 `serverId`，批量操作在同一 SQLite 事务中提交。
- 删除使所有旧请求批次失效，并尽力关闭本地连接。迟到响应、普通轮询、旧页面完整配置回写、刷新及服务重启均不能重建同 ID 的画册或重新提交它。
- 删除不调用生成接口，也不等于取消上游请求或退款。诊断记录保留，但不会作为待处理任务再次出现。
- 若删除事务已提交、后续 JSON 文件整理失败，仍明确返回已删除；以后读取和保存均按持久删除标记过滤，不谎报成部分删除失败。
- 图片文件仍按已有素材清理策略回收，不立刻不可恢复地擦除原图。

### 状态、队列与恢复

- `allowedActions` 由服务端状态规则生成，恢复投影与前端按钮使用同一契约；恢复前仍检查最新进度与确认版本。
- 仅保留真正涉及新请求的计费风险确认。移除前端放弃跟踪和手动放行流程；旧 `abandon` API 仅为兼容保留，不作为删除条件，也不能授权未知结果重发。
- 保留既有独立分镜池、默认 FIFO、明确手动并行、5xx 自动重试、4xx 不自动重试、422 跳过、手动恢复刷新自动额度、保留完成图和未知结果不盲目重发规则。
- 保留按稳定渠道 ID 读取最新保存配置、在途输入不变、原分镜编辑器的本册作用域以及多标签页配置版本冲突保护。
- 演示／真实生成按任务快照分流，不随当前渠道切换而把真实任务送进浏览器演示生成器。
- 服务端生成单调递增配置版本，避免客户端时钟不变时旧页面覆盖新配置。
- 保存冲突和保存失败改用中文，仍保留未保存的本页修改，不假装已经生效。

### 阅读、导出和日志

- 保留整册阅读、单一导航、移动端单幕、导出样张三张限制、缺页占位与模板脚本授权。
- 大画册自定义模板载入及完整原图导出新增取消入口；重试导出无需手动解锁。关闭阅读器、删除当前画册会取消其本地准备工作。
- 自定义阅读显示副本最长边 1440px；导出独立读取原图，不用显示缩略图冒充全分辨率。
- 本地服务断连时队列直接显示提示；恢复连接只读取状态，不触发重复提交。
- 日志新增收到响应阶段；失败事件带本次已确定模型；读取输入、确定参数、收到响应、保存图片分开表达。
- 新日志不抢历史滚动位置；同次尝试从输入更新到最终参数时不收起详情。保留已有脱敏与复制诊断能力。

## 验收说明

验收使用 Linux、Python、Playwright Chromium 和受控本地 HTTP 上游，不使用真实付费渠道。最终逐项执行记录见包内 `docs/acceptance/`（原始命令输出、关键页面截图）。

重点不仅检查函数存在，还执行了：

- 原版真实复现：请求开始 → 本地停止 → 删除返回 Conflict（HTTP 409 来源）。
- 配置渠道 → 创建与编辑 → 入队 → 422 跳过、503 重试 → 在原编辑器修改本册 → 手动继续 → 刷新读取原册 → 导出 → 下载文件通过 `file://` 重新打开与图片解码 → 删除。
- 运行中一次停止删除、停止后未知结果删除、混合批量删除、重复点击、旧标签页回写与轮询同步、硬重启不复活。
- 批量事务故障回滚、迟到结果隔离、未保存任务映射的同册任务清理、删除不授权其他未知请求重发。
- 慢原图导出取消、取消后再次导出；实际下载图片以 **2048 × 3072** 解码，保留原分辨率。
- 整册载入取消、24 幕自定义模板无重叠翻页、结尾位置、移动单幕、模板媒体和脚本、字幕布局、真实 Fullscreen API 的进入和退出。
- 独立滑动并发池、保存后新模型／地址作用于未发送请求、已发送请求输入不变、离开网页后仍读取已保存分镜。
- 桌面和 390px 移动视口的明暗主题截图及横向溢出检查；日志滚动和展开状态回归。

## 已知限制与未验证项

- **未连接真实 ComfyUI、NovelAI、OpenAI 或第三方付费供应商**。适配器与规则有受控回归，不等于供应商在线兼容或扣费行为验证。
- 没有 Windows/macOS 实机、手机真机、Safari/WebKit、Firefox 的本轮验收；Windows `cmd.exe` 执行测试会明确跳过。移动端结果是 Chromium 视口模拟。
- 没有用户所述“未交付工作目录”和旧发行包，只能核对本轮 GitHub 基线与改动；未声称已经比较那份未提供的包。
- 大画册不是无限容量：自定义整册预览图像累计预算 **64 MiB**，默认单图阅读更节省资源；单次离线 HTML 原图累计内联预算 **128 MiB**，超过时明确失败，不降低分辨率。尚未实现流式 ZIP 导出或多 GB 大册压力验收。
- HTML 最终组装、图片解码和系统文件写入存在短暂不可即时中断阶段；取消会在安全检查点生效，尚未下载的文件不会发出，已交给系统的保存不能保证撤销。
- 图片磁盘文件可能在停止竞态中成为未引用素材，按现有保护期清理；不会重新进入被删除画册。
- 程序可以关闭本地连接，但不能证明供应商已停止、未收费或已退款。

## 开发与复验

运行环境不需要 npm。只有开发验收需要：

```sh
npm ci
npx playwright install --with-deps chromium
npm test
npm run package
```

`npm run package` 生成干净的完整源码 ZIP 与 SHA-256 清单，不打包 `data/`、历史数据备份、浏览器缓存、虚拟环境、node_modules 或 Git 凭据。
