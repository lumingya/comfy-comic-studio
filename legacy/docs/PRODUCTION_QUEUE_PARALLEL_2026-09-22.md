# 装配队列：并行运行、逐本控制与批量操作（2026-09-22）

[教程中心](README.md) · [生成任务](guide/FOUNDATION.md) · [版本说明](RELEASE_CURRENT.md)

本次把「装配与队列」从**单批次串行**改为**多本画册并行、每本独立控制**，同时整理任务卡与右键菜单。旧任务记录与控制文件自动迁移，不需要手工处理。

## 行为变化

| 之前 | 现在 |
| --- | --- |
| 同一时间只运行一本画册；其他任务卡被「另一本正在运行」锁住 | 每本画册独立运行，点几本就跑几本；互不等待、互不锁定 |
| 「从此处顺次生成」把之后的任务冻结成一个批次 | 顶部「按顺序开始生成」把待命任务排进**顺次队列**，一本接一本；顺次队列与手动开始的画册并行 |
| 全局「暂停 / 恢复当前批次」 | 任务卡上的**暂停 / 继续生成**只作用于这一本；顶部「全局暂停」「继续生成」作用于全部 |
| 并发固定为 1 幕 | 顶部「默认并发」+ 任务卡 / 新建向导里的**分幕并发**（留空跟随全局，1–128），运行中可调，对下一幕生效 |
| 队列顺序不可调 | 拖动任务卡排序（服务端保存），右键菜单可上移 / 下移 / 移到最前 / 最后；顺次队列跟随可见顺序 |
| 逐张移除已完成记录 | 顶部「清空已完成」一键移除，画册与图片保留 |
| 无法复制任务 | 「克隆」复制分镜、预设与参数为新的待命任务卡，排在原任务之后 |
| 只能逐张操作 | 桌面多选（Ctrl / ⌘、Shift、框选）+ 右键批量开始 / 顺次 / 暂停 / 继续 / 停止 / 克隆 / 移除，Delete 移除所选 |

### 被移除的入口

`只看未确认结果`、`导出核对清单`、`从此处顺次生成`、`重算前置并继续`、`诊断详情` 五个按钮从任务卡与顶部栏移除；`恢复当前批次` 改为「继续生成」，与任务卡一致。「诊断详情」在任务出现错误或未确认结果时仍会出现在右键菜单中；「重算前置」的场景由「克隆」覆盖（克隆出的任务会重新执行前置准备）。分镜工坊与预设工坊的导出按钮统一为「导出」。

### 未改变的保障

- 装配只是待命，不调用模型；任何开始都需要明确确认，云端渠道保留费用提示，未确认结果重跑需要单独确认。
- 暂停只停止**后续**分幕，已发出的请求照常返回，不重复计费；停止不会撤回提供商已收到的请求。
- 重启后运行中的任务标记为「中断待核对」，顺次队列中安全排队的任务保留但保持暂停，不会自动恢复。
- 凭据错误（401 / 403）或连续 3 幕失败会停止这一本，并清空顺次队列，避免用同一套坏配置继续付费；其他手动开始的画册不受影响。
- 系统上限只剩两条技术护栏：单本分幕并发最多 128，队列记录最多 1000 条。负载完全由你决定。

## 后端接口（`/api/production/`）

| 路由 | 参数 | 说明 |
| --- | --- | --- |
| `assemble` / `assemble-batch` | 新增可选 `concurrency` | 任务自己的分幕并发，`null` 跟随全局 |
| `start` | `id`、可选 `indices`、`concurrency` | 立即运行这一本（与其他运行中的画册并行） |
| `start-many` | `ids` | 同时开始多本 |
| `start-sequence` | 可选 `ids`（省略 = 全部待命任务） | 加入顺次队列 |
| `pause` / `resume` / `cancel` | 可选 `id` 或 `ids`（省略 = 全局） | 暂停 / 继续 / 停止；对排队中的任务 `cancel` 即移出队列 |
| `remove` | `id` 或 `ids` | 移除记录（运行或排队中的会被跳过） |
| `clone` | `id`、可选 `title` | 克隆为新任务 |
| `reorder` | `order`（完整 id 列表） | 保存新顺序 |
| `clear-finished` | — | 移除全部已完成记录，返回 `removed` 数量 |
| `concurrency` | `value`、可选 `id`（省略 = 全局默认） | 设置分幕并发；`id` 配合 `value: null` 表示跟随全局 |

`GET tasks` 的返回新增：`active`（运行中的任务 id 列表）、`lane`（顺次队列）、`concurrency` / `maxConcurrency`；每个任务新增 `running`、`queued`、`queuePosition`、`paused`、`concurrency`、`effectiveConcurrency`。旧字段 `batch` 仍保留为 `active + lane` 的别名，`paused` 表示顺次队列是否被全局暂停。

## 实现要点

- `backend/production/queue.py`：每个明确开始的任务拥有自己的运行线程，任务内按并发上限派发分幕；顺次队列由独立调度循环一次放行一本。所有分幕写入同一个任务记录仍然串行化，画册发布通过发布锁串行，避免同一本画册的修订冲突。
- `backend/production/store.py`：任务摘要进入内存缓存，队列轮询不再逐个读盘。
- `js/assembly-workshop.js`：任务卡按 `running / queued / paused` 三态渲染；`desktop-selection.js` 新增任务卡多选作用域；拖动排序采用与画册书架相同的指针手势（8 px 激活），不与框选、按钮点击冲突。
- 顺便修复：装配向导第二步的预设复选框在点击后显示为未勾选（浏览器在取消默认行为后回滚勾选状态）。
