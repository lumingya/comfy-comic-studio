# 成品档精修管线

独立可选的「成品精修」剧集面板。对用户明确选中的已采用草稿运行现有成品阶段；不在基础界面新增专业工具入口。

## 安装与使用

1. 把本目录打成 ZIP，在 Mio 的「扩展市场」导入并审阅摘要后启用。
2. 在已有采用图的一话，从「挑图 / 分镜」旁的「扩展」菜单打开「成品精修」，点击「读取已采用草稿与配置」。安装、启用和打开面板均不提交任务。
3. 逐格勾选或「全选已采用草稿」。列表只包括 `status=adopted, stage=draft`，普通候选和已有成品不会混入。
4. 选择具有有效 `final` 阶段的已绑定出图配置，核对各阶段工作流、顺序、输入衔接和普通参数。阶段在「高级出图方案」编辑，本面板不修改全局配置。
5. 确认采用行为后点击「提交所选画面的成品精修」。进度显示每格任务，完成后在下方逐格查看原图与成品。

成品管线使用现有 `/episodes/{episode_id}/finalize`。放大、脸部或细节重绘的效果取决于所选配置的工作流和阶段，面板本身不预设模型或第三方节点。

**采用行为需要确认**：如果原草稿在任务完成时仍被采用，新成品会接替它；原图作为候选保留。如果创作者期间改选了别的图，迟到的成品不会覆盖新的选择。结果保留 `parent_take_id`、成品阶段和任务来源，可随时对比。

## 进度、失败与恢复

每格依次运行配置中的有效阶段；任务面板按格显示完成数与状态。默认每 5 秒读取一次，单次会话最多自动读取 100 次；可取消勾选或手动刷新。重新打开面板后，点击读取，再从近期成品任务中继续查看；也可直接粘贴任务 ID。

失败、超时和停止都不自动重跑上游；成功部分保留。相同选择和配置的重复点击使用同一幂等键，需要再次运行时先点击「开始新的成品请求」。网络超时应先检查近期任务是否已创建。提交前会重新读取采用状态，避免把界面里的过期选择当成当前草稿。

停用立即撤销菜单入口和后续桥请求；已经提交的任务可能继续执行，请在停用前明确停止。停用、卸载均不删除作品、草稿或成品。本包没有私有持久化状态。

## 契约与离线验证

纯声明 `panels.requests` 包，无 Python 入口、宿主内部接口或直接联网。JSON 请求由宿主校验实际接口类型与 `read` / `render` 权限；图片使用受控媒体桥并在换图时释放句柄。协议见[媒体桥说明](../../../docs/EXTENSION_MEDIA_BRIDGE.md)。

```bash
python tools/check_extension_package.py examples/extensions/finalize-studio
node examples/extensions/finalize-studio/logic.test.cjs
node examples/extensions/finalize-studio/bridge.test.cjs
python -m unittest discover -s server/tests -t server -p test_professional_retouch.py -q
```

隔离测试覆盖安装/启用/停用/卸载、权限、仅提交明确选择、多阶段冻结、进度、原图保留与成品回流。离线测试使用模拟 ComfyUI，不调用付费服务，也不据此宣称某个真实放大或细化工作流已经过效果评审。
